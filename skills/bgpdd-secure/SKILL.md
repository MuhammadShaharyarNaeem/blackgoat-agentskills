# End-to-End Multi-Agent PDD: Security Lane (bgPDD-Secure)

This Standard Operating Procedure (SOP) answers one question with gated evidence: **does the application resist the attacks in its threat surface, as far as an agent can safely and non-destructively test?** It converts `security-and-hardening`'s Coverage & Provability table plus the web and API OWASP Top 10 into an attack matrix scoped to the target, has Cipher (and Quinn, for browser-rendered surfaces) execute it as safe read-only probes against the running application, and passes the results through the same mechanical gates the other lanes use.

**When to use**: an application already exists — built by this squad or not — and you want a scoped, evidenced audit of its security surface: before shipping, after a boundary change, or on a recurring cadence. **When NOT to use**: building or changing behavior (→ `/bgpdd-plan` or `/bgpdd-lite`), a specific defect already isolated (→ `/bgpdd-bugfix`), functional regression rather than security (→ `/bgpdd-verify`), or an epic already inside `/bgpdd-shipping` Stage 2, which runs its own Cipher audit against that build.

Invoke with `/bgpdd-secure {target}`.

**Scope boundary, v1 — audit and safe read-only probes only.** No destructive payloads, no data exfiltration, no denial-of-service, no persistence of any kind. Staging or local environments only — **never production**. A finding that would require active exploitation to confirm (e.g. actually completing a privilege-escalation write, actually exfiltrating a record) is reported at the tier it actually reached — `partial` or `BLOCKED` — never escalated to `provable`/`PASS` by assumption (`{PLUGIN_ROOT}/agent-squad/base-persona.md` § Evidence Integrity: an unnamed proxy is a fabrication in effect). **Deliberate divergence from `security-and-hardening`'s Ask-First tier (convention #8):** that contract lets a human approve crossing an Ask-First boundary (new auth flow, elevated permissions); this lane never crosses one even with approval — v1 has no approval path for active exploitation, only for scope inclusion (Phase 0).

## 1. Global System Constraints

> ### MANDATORY FIRST READ — the Orchestrator Contract
>
> **Before Phase 1, you MUST read `{PLUGIN_ROOT}/agent-squad/orchestrator-contract.md` in full.** Do not improvise those rules from memory. If the file does not resolve, STOP and report the broken path.
>
> Then read `{PLUGIN_ROOT}/agent-squad/pipeline-skeleton.md` — the shared pipeline skeleton (path resolution, error recovery, upgraded chain of thought, game tape). Refinements below override the skeleton only where labelled (convention #8).

The sections below carry ONLY this pipeline's refinements on top of that contract.

- **Strict Delegation — this pipeline's agents**: **Cipher** (Phase 2, primary), **Ward** for data-handling rows only (Phase 2 step 4, and only when the matrix carries such a row), **Quinn** for browser-rendered probes only (Phase 2, e.g. an XSS payload's actual rendering, a cookie-flag check on a login flow), and optionally **Scout** for bounded environment/surface research (Phase 1). You MUST NOT roleplay any of these agents' work yourself.
  - **EXCEPTION — Phases 0–1 are interactive** (Orchestrator + user, main session), per the Orchestrator Contract §1 interactive-steps rule — authorization, scope, and matrix confirmation are turn-by-turn decisions a delegated agent cannot pause for.
- **Security-only, pipeline-wide: no builder in this lane, and a `FAIL`/Critical finding is an output.** No agent here modifies product source code — Cipher's persona already forbids remediation (`{PLUGIN_ROOT}/../agents/cipher.md` § Interaction Style: he reports, the Orchestrator routes), and Quinn's probes here write no product code either (§ this lane's Phase 2 divergence, below). Mirroring `bgpdd-verify`'s own labelled divergence from build's rejection loop: a confirmed vulnerability is a **finding**, never a fix task — there is no builder to loop to, and a lane that patches what it measures grades its own work.
- **Bidirectional contract with `/bgpdd-bugfix`.** Confirmed product defects **route out** to a fresh `/bgpdd-bugfix` session, one per finding (Phase 4 step 2) — contract, not offer, exactly as `bgpdd-verify` §1 states it for functional defects.
- **Cipher never authors what he is graded against** — the same invariant `bgpdd-verify` §1 binds Quinn to. Corollaries:
  1. **The attack matrix** is the Orchestrator's artifact (Phase 1), authored interactively with the user. Cipher, Ward and Quinn receive a resolved read-only path and never edit it.
  2. **The environment preamble** (start commands, base URLs, non-production attestation, forbidden hosts, and the scope exclusions the Phase 3 gate asserts) is authored by the Orchestrator with the user, before execution (Phase 1).
  3. **The Phase 3 gate flags** are *emitted* from that preamble, never invented at the gate.
  4. **A matrix defect at Phase 3** re-opens Phase 1 with the user rather than routing to Cipher, and consumes none of his rounds.
- **Tier-2 workspace**: `.docs/{project-name}/` per `base-persona.md`'s standard model. When `.docs/summary/{target}/overview.md` exists from a prior `/bgpdd-discovery` run on this same slug, reuse its cross-API surface map to seed Phase 1's `Surface` column instead of re-deriving it — optional here (unlike `bgpdd-verify`, this lane has no entry-ticket dependency on discovery, since it audits an application boundary rather than a documented feature).
- **Run log** (Contract §4's obligation; CLI contract in `{PLUGIN_ROOT}/pipeline-tools/SKILL.md`). Per delegation return — each Scout (Phase 1), Cipher (Phase 2), Ward (Phase 2, when delegated), Quinn (Phase 2, when used), and every Phase 3 delta-only follow-up round: `python {PLUGIN_ROOT}/pipeline-tools/scripts/record_run.py --log .docs/{project-name}/implementation/run-log.jsonl --pipeline bgpdd-secure --phase "<phase>" --event delegation --agent <name> --model <tier> --unit "<the run title>" …` (`--model` mandatory; `--rounds` on a re-delegation; a token measurement is equally mandatory — `--tokens-in`/`--tokens-out`, `--from-json`, or `--tokens-unavailable "<reason>"`; `--status` from the handoff). Into Phase 4's game tape: `python {PLUGIN_ROOT}/pipeline-tools/scripts/summarize_run.py --run-log .docs/{project-name}/implementation/run-log.jsonl --ledger .docs/{project-name}/implementation/gates.jsonl --unit "<the run title>" --markdown`.
- **Content contracts, refining the skeleton's Upgraded Chain of Thought**: `attack-matrix.md` passes `--lint-only` (Phase 1); the security report and any probe results have a parseable line for every gated row.
- **File Artifacts**: standard GitHub markdown, saved under `.docs/{project-name}/`.

## 2. Global Error Recovery

**Refinement of Orchestrator Contract §2 (skeleton owns the rest):** the 2-round bound applies to `attack-matrix.md` (lint failures) and Cipher's/Ward's/Quinn's reports and captures (a non-conforming report, a missing evidence citation). **A gated row that fails because a real vulnerability was confirmed is outside the bound entirely** — it is a finding, not a defect in the run (§1).

## 3. Detailed Pipeline Phases

### Phase 0: Fit Check, Hydration & Authorization Gate (Orchestrator)
- **Delegated Agent**: None — interactive, main session (Orchestrator Contract §1's interactive-steps rule; convention #6 — this step is never delegated).
- **Workflow**:
  1. **Entry ticket**: confirm the target application exists and can be started or is already reachable. This lane has no Tier-1 discovery prerequisite (§1) — an app never run through `/bgpdd-discovery` is still in scope.
  2. **Authorization gate (mandatory, irreversible/outward-facing — Orchestrator Contract §1's Phase Transitions rule and interactive-steps rule both bind here, cited together).** Before any probe is planned, obtain from the user, in the transcript, all of:
     - Confirmation that the target is theirs to test, or that they hold explicit authorization to test it.
     - Confirmation the target environment is **non-production** (staging or local) — name the base URL(s) and have the user confirm each one.
     - The **scope exclusions**: hosts, routes, accounts, or categories the user wants withheld from probing.
     Record all three verbatim in the environment preamble (Phase 1 step 3). No probe is planned or executed against an unconfirmed target — this is a hard HALT, not a warning.
  3. **Route out what this lane is not for** (see "When NOT to use" above). If the user's real goal is a known defect or a feature build, re-route rather than absorbing scope.
  4. Confirm with the user: the Tier-2 work slug `{project-name}` (default `{target}-secure`), and the **priority floor** for the Phase 3 gate (Critical, or Critical+Important). **Slug-collision guard (mechanical)**: if `.docs/{project-name}/requirements.md` or `implementation/plan.md` exists, HALT — pick a different slug, mirroring `bgpdd-verify` Phase 0 step 3.
  5. **Re-audit shortcut**: if `.docs/{project-name}/attack-matrix.md` exists from a prior confirmed run and the user wants a re-run, skip Phase 1 for Phase 2 after re-confirming the authorization gate (step 2 is never skipped, even on a re-run — non-production status and scope can drift between runs). Before Phase 2 runs, copy the current `security-report.md` to `.docs/{project-name}/implementation/evidence/security/prior-security-report.md` — Cipher's contract only appends a fresh `## Security Audit:` section per round and never edits an earlier one (`agents/cipher.md` § 4), so the live file alone cannot tell a fixed finding from a standing one. After Phase 2, run `python {PLUGIN_ROOT}/pipeline-tools/scripts/diff_findings.py .docs/{project-name}/implementation/evidence/security/prior-security-report.md .docs/{project-name}/implementation/security-report.md --fail-on-new`, and treat a NEW finding as a Phase 3 report-gate failure — and, when `.docs/{project-name}/implementation/privacy-report.md` exists from that prior run, copy and diff it the same way (Ward appends per round exactly as Cipher does, so the same blindness applies) — a mechanical tightening of THIS step's own re-confirmation clause (convention #8): re-confirming authorization was never a promise that Cipher's fresh findings had themselves been checked against the prior round's.

### Phase 1: Attack Matrix Derivation (Orchestrator + user, main session)
- **Delegated Agent**: None for authoring; optionally **Scout** (`{PLUGIN_ROOT}/../agents/scout.md`) for bounded surface/environment research, writing only to `.docs/{project-name}/research/`.
- **Format authority**: this file owns the attack matrix's grammar — no other skill's matrix format applies here (deliberate: `planning-and-task-breakdown`'s acceptance-matrix grammar is for `GO → DO → ASSERT` functional steps, not attack rows). Columns, one row per category:

  `Category | Surface | Tier | Preconditions | Planned evidence | Verdict`

  - **Category**: a row from `security-and-hardening`'s *Coverage & Provability* table, plus any OWASP API Top 10 category (`{PLUGIN_ROOT}/security-and-hardening/references/security-deep-dive.md` § OWASP API Security Top 10) that applies when the target exposes an HTTP API surface. For an API category absent from *Coverage & Provability*, reuse the tier of the web category it most resembles and name the precedent in the Verdict cell (e.g. BOLA/BFLA reuse Broken Access Control's `partial`; Improper Inventory Management reuses Logging & Monitoring Failures' `not agent-testable`) — do not invent a new tier taxonomy. **Data-handling Category vocabulary (fixed — this file owns it, as it owns the rest of the grammar).** `check_attack_matrix.py` accepts free text in `Category`, so this lane fixes exactly six tokens as the data-handling class, spelled verbatim: `PII exposure`, `Consent`, `Retention`, `Deletion propagation`, `Third-party data flow`, `Compliance evidence` (the sections of `{PLUGIN_ROOT}/security-and-hardening/references/data-privacy-checklist.md`, plus the compliance row). A row carrying one of the six routes to Ward at Phase 2 step 4; every other Category is Cipher's. The spelling is the trigger — a paraphrase routes nowhere, which is why this list is fixed rather than descriptive.
  - **Surface**: the concrete route, page, or endpoint group the category applies to for this target.
  - **Tier**: exactly one of `provable` / `partial` / `not agent-testable`, taken from *Coverage & Provability* (or reused per the rule above).
  - **Preconditions**: what the row needs before Cipher/Quinn can execute it — e.g. two accounts at different privilege levels/tenants for any Broken Access Control, BOLA, or BFLA row (`{PLUGIN_ROOT}/security-and-hardening/SKILL.md` § Security Review Checklist → Authorization: "IDOR checks proven with two accounts... a code read alone is BLOCKED, not PASS"). A precondition the user cannot supply (no second test account, no staging replica) makes the row `BLOCKED` before it is run, not silently dropped.
  - **Planned evidence**: the artifact type expected to close the row — a capture under `evidence/security/`, a runtime probe under `evidence/runtime/` (browser-rendered rows only), or a source-read citation for a `not agent-testable` row that is closing as `BLOCKED` by design.
  - **Verdict**: left blank at authoring time; filled in Phase 4 from the gated results.

  **Workflow**:
  1. Draft `.docs/{project-name}/attack-matrix.md` WITH the user: enumerate the target's surfaces (routes/pages/API groups), then cross them against `security-and-hardening`'s *OWASP Prevention Areas*, its *Coverage & Provability* table, and — where an HTTP API surface exists — the API Top 10 (§ above). Not every category applies to every surface; omit a category-surface pair that plainly does not apply and say why inline, rather than padding the matrix.
  2. **The Three-Tier Boundary System bounds Cipher's and Quinn's own conduct while probing** (`{PLUGIN_ROOT}/security-and-hardening/SKILL.md` § The Three-Tier Boundary System) — cite it in the brief rather than restating it: a probe that would itself violate an *Always Do* or *Never Do* line (e.g. weakening a header to test around it) is out of scope for v1, full stop.
  3. **Environment preamble (required)**, inline in the matrix, mirroring `bgpdd-verify`'s inline form (deliberate, same divergence, convention #8): the application start command(s), each service's non-production base URL, the forbidden-host patterns, the scope exclusions from Phase 0 step 2, and the test identities/accounts needed for two-account rows.
  4. **Lint gate (mechanical)**: `python {PLUGIN_ROOT}/pipeline-tools/scripts/check_attack_matrix.py --lint-only --matrix .docs/{project-name}/attack-matrix.md --ledger .docs/{project-name}/implementation/gates.jsonl` — exit 0 required before Phase 2. This script enforces the column grammar above (every row has all six fields, `Tier` is one of the three named values, a `not agent-testable` row cites no `Planned evidence` beyond the closing citation, every Broken-Access-Control-family row declares its two-account precondition) and the presence of the environment preamble's authorization/scope-exclusion block. On exit 1/2, fix the named rows and re-run (2-round bound, then halt and surface).
  5. The user confirms the matrix before you proceed.

### Phase 2: Execution (Cipher; Ward for data-handling rows; Quinn for browser-side probes)
- **Delegated Agent**: **Cipher** (`{PLUGIN_ROOT}/../agents/cipher.md`), one delegation, launched in the background; **Ward** (`{PLUGIN_ROOT}/../agents/ward.md`), a separate delegation alongside Cipher, only for rows carrying a data-handling Category (Phase 1); **Quinn** (`{PLUGIN_ROOT}/../agents/quinn.md`), a separate delegation, only for rows whose `Planned evidence` requires a browser-rendered probe.
- **Workflow**:
  1. Brief Cipher with: the attack matrix path (read-only); the target repo root; a **run title** (`{project-name}` slug) for his `## Security Audit: <scope> — <date>` section header; the resolved paths of `base-persona.md`, `security-and-hardening/SKILL.md`, `security-checklist.md`, and `runtime-evidence/SKILL.md`; and the Orchestrator Contract §2 rules verbatim. The data-handling rows and `data-privacy-checklist.md` are Ward's (step 4) — do not brief them to Cipher as well, or two reports claim the same rows.
  2. Cipher executes his own standing contract unchanged: every check runs as a self-gating `run_quiet.py --capture` under `.docs/{project-name}/implementation/evidence/security/`, one check line per row per `{PLUGIN_ROOT}/pipeline-tools/SKILL.md` § `check_agent_report.py`'s grammar (not restated here), findings in the squad's severity taxonomy, into `.docs/{project-name}/implementation/security-report.md` (`{PLUGIN_ROOT}/../agents/cipher.md` § 4 — his report path and check-line rules are the authority; this brief adds only the matrix as his row source).
  3. For a row whose evidence needs a rendered page (an XSS payload's actual DOM output, a session cookie's flags observed in a real browser), delegate that row to **Quinn** instead: she captures it as a Tier-3 runtime probe per `{PLUGIN_ROOT}/runtime-evidence/SKILL.md` (§ The Runtime Probe, § The Capture Artifact) under `.docs/{project-name}/implementation/evidence/runtime/`, citing it with the `**Runtime evidence:**` grammar that skill owns (§ Citation) inside Cipher's `security-report.md` under the same run title — she does not open her own report for this lane. **Deliberate divergence from `bgpdd-verify`'s Quinn (convention #8): her probes here are diagnostic captures only, never permanent Playwright specs** — this lane audits a point-in-time posture rather than building a repeatable regression suite, so there is no product-repo write, no spec authorship, and (consequently) no Phase 4 commit step for her output.
  4. **Ward** (`{PLUGIN_ROOT}/../agents/ward.md`), launched alongside Cipher, takes every matrix row whose `Category` is one of Phase 1's fixed six data-handling tokens. **If no row carries one, Ward is not delegated at all** — deliberately tighter than step 1's unconditional Cipher delegation (convention #8): spawning an agent with no rows to execute buys an empty report. Brief him with the same shape step 1 gives Cipher — the attack matrix path (read-only), the target repo root, the same **run title** — plus the resolved paths of `base-persona.md`, `{PLUGIN_ROOT}/privacy-engineering-patterns/SKILL.md`, `{PLUGIN_ROOT}/compliance-evidence-patterns/SKILL.md`, `{PLUGIN_ROOT}/security-and-hardening/references/data-privacy-checklist.md`, and `{PLUGIN_ROOT}/runtime-evidence/SKILL.md`. He writes `.docs/{project-name}/implementation/privacy-report.md`, section header `## Privacy & Compliance Audit: <scope> — <date>`, one check line per row in the **identical** grammar Cipher's report uses (step 2's authority, not restated here) so Phase 3's report gate is re-pointed rather than changed, and reports `<artifact>`.
  5. Instruct all delegated agents explicitly that this run is **audit-only** (§1's scope boundary): a confirmed vulnerability is a finding with its evidence and exact reproduction — no agent here exploits further, exfiltrates data, attempts persistence, or fixes product code, Ward included. A row whose precondition is absent, or whose category is `not agent-testable`, is `BLOCKED` — never `PASS`, never omitted (`base-persona.md` § Evidence Integrity). If the application will not start, every dependent row is `BLOCKED` naming what was missing.
  6. Read each handoff. **Validate before acting on it** (Contract §1's rule): save each to a file and run `python {PLUGIN_ROOT}/pipeline-tools/scripts/check_handoff.py --handoff <that file> --persona cipher --repo . --since <the sha HEAD held when you launched him> --ledger .docs/{project-name}/implementation/gates.jsonl` (and the same for Ward's, `--persona ward`, and Quinn's, `--persona quinn`, when each ran). Exit 1 = a delta-only follow-up under §2's bound, not a Phase 3 gate run.

### Phase 3: Mechanical Gates (Orchestrator)
- **Delegated Agent**: None — the Orchestrator runs every gate directly, under the Orchestrator Contract §1 interpreter rule.
- **Workflow**:
  1. **Attack-matrix gate (results)**: `python {PLUGIN_ROOT}/pipeline-tools/scripts/check_attack_matrix.py --matrix .docs/{project-name}/attack-matrix.md --report .docs/{project-name}/implementation/security-report.md --repo <target repo root> --require-priority <the Phase 0 floor> --ledger .docs/{project-name}/implementation/gates.jsonl` — checks every matrix row has a corresponding check line, that no `not agent-testable` row was closed as `PASS`, and that every two-account precondition row cites two distinct identities. Do not restate its internals beyond what this bullet already names.
  2. **Report gate**: `python {PLUGIN_ROOT}/pipeline-tools/scripts/check_agent_report.py --report .docs/{project-name}/implementation/security-report.md --milestone "<run title>" --repo <target repo root> --ledger .docs/{project-name}/implementation/gates.jsonl` — the check-line/capture/verdict-arithmetic authority is `{PLUGIN_ROOT}/pipeline-tools/SKILL.md` § `check_agent_report.py`; not restated here.
  3. **Privacy report gate (only when Ward was delegated — Phase 2 step 4)**: `python {PLUGIN_ROOT}/pipeline-tools/scripts/check_agent_report.py --report .docs/{project-name}/implementation/privacy-report.md --milestone "<run title>" --repo <target repo root> --ledger .docs/{project-name}/implementation/gates.jsonl` — same flags, same authority as step 2; Ward's check-line grammar is identical by design (Phase 2 step 4), so this is step 2 re-pointed, not a second contract. Ward not delegated = no rows for it to gate, so it does not run.
  4. **Runtime-evidence gate (when Quinn ran any row)**: `python {PLUGIN_ROOT}/pipeline-tools/scripts/check_runtime_evidence.py --report .docs/{project-name}/implementation/security-report.md --milestone "<run title>" --repo <target repo root> --ledger .docs/{project-name}/implementation/gates.jsonl` plus the `--surface`/`--forbid-host` flags drawn from Phase 1's environment preamble by hand (this lane has no `--emit-gate-args` producer — its preamble is prose, not the acceptance matrix's fixed-key grammar — so paste the preamble's base URLs and forbidden-host list directly; never loosen or invent one). Freshness runs against Cipher's/Quinn's captures.
  5. **Route by failure class**, mirroring `bgpdd-verify` Phase 3 step 3 (deliberate reuse, not restatement — the shapes are identical, only the agent and artifact names differ):
     - **Report/capture defects** (a missing check line, a non-conforming or stale capture): a delta-only follow-up to whichever of Cipher, Ward or Quinn owns that report, quoting the named problem — 2-round bound (§2), then halt and surface.
     - **Matrix defects** (a row missing a required field, an uncited precondition): re-open Phase 1 with the user, re-lint, then re-run all three gates. Consumes no execution round.
     - **Gate-invocation defects** (a bad `--require-priority` token): your own usage error — fix and re-run. Consumes no round.
     - **Confirmed vulnerabilities** (a gated row whose evidence reproduces a real weakness): do **NOT** loop. Carry to Phase 4 as findings (§1).
     - **Authorization/environment blocks** (the target cannot be confirmed non-production, cannot start, or the transport is unavailable): HALT and surface — never substitute an in-process or source-read-only reading for a `provable`/`partial` row (`runtime-evidence`'s Tier Ladder), and never re-probe a target whose non-production status is now in doubt.

### Phase 4: Verdict, Findings Routing & Game Tape (Orchestrator)
- **Delegated Agent**: None. No delegation, no halt.
- **Workflow**:
  1. **Relay the verdict** to the user: per-row Verdict filled into the matrix — `PASS` / `FAIL` (a confirmed finding) / `BLOCKED`. **A `not agent-testable` row always closes `BLOCKED`, never `PASS`** — absence of a finding there is absence of a test, not a clean bill of health (`{PLUGIN_ROOT}/security-and-hardening/SKILL.md` § Coverage & Provability). A `partial` row's verdict names what was, and was not, covered.
  2. **Route findings** (§1's bidirectional contract): for each confirmed vulnerability, give the user the failing row, Cipher's (or Ward's, or Quinn's) reproduction, its severity, and the evidence path, and route it to a fresh `/bgpdd-bugfix` session — one per finding. Ward's findings take this same route with no exception of their own: a confirmed retention or deletion-propagation defect is a product defect, and the only thing that differs is which report the reproduction is quoted from. A standing Critical finding is surfaced first and loudest (`cipher.md`'s Zero Tolerance on Critical), regardless of how the other rows closed.
  3. **Game tape**: append a `## bgpdd-secure — [date]` section to `.docs/{project-name}/implementation/game-tape.md` (create if absent) — at most 10 bullets: scope and exclusions confirmed at the authorization gate, gate results as verbatim command + captured output tail, findings raised, `BLOCKED` rows and why, retry rounds and why.
  4. **State persistence** via `update_state.py` — never hand-edit JSON:
     ```bash
     python {PLUGIN_ROOT}/pipeline-tools/scripts/update_state.py \
       --state .docs/{project-name}/orchestrator-state.json \
       --init --project-name "{project-name}" \
       --set-pipeline bgpdd-secure \
       --set-feature {target} \
       --set-artifact attack_matrix=.docs/{project-name}/attack-matrix.md \
       --set-artifact requirements=null \
       --set-artifact design=null \
       --set-artifact plan=null
     ```
     Append `--add-blocker` entries for authorization/environment blocks and `BLOCKED` rows (not for confirmed-vulnerability findings — those are output, routed in step 2). A blocker write carries `--ledger .docs/{project-name}/implementation/gates.jsonl`.
  5. **No commit step in this lane.** Unlike `bgpdd-verify` Phase 4 step 4b, none of Cipher, Ward or Quinn produces a permanent product-repo artifact here (§ Phase 2 step 3's divergence) — the only durable outputs are the matrix, the security report, Ward's privacy report, and the evidence captures, all under `.docs/{project-name}/`, so no hand commit is needed.
  6. **Re-entry: this state file is terminal by design**, mirroring `bgpdd-verify` Phase 4 step 5. A later `/bgpdd-plan` or `/bgpdd-lite` run must never `--init` over this file. The way back in is the Phase 0 re-audit shortcut; the way out for a confirmed finding is a fresh `/bgpdd-bugfix` per finding (step 2).
