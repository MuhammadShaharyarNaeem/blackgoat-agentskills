# review_package.py — reference

Depth for the `review_package.py` section of `../SKILL.md`: the observed failure it converts, the rendering rules, the sidecar's meaning, and the self-test inventory.

## The observed failure

`bgpdd-build` Phase 3 step 4 instructs a **fresh** Luna to re-review "the remediation diff itself" and record a new verdict. That instruction had no referent. The reviewer received a `<changed_files>` path list and read the amended working tree, which shows those files as they are **now** — not what the remediation changed. Three consequences, all silent:

1. **A fix is indistinguishable from the status quo.** A reviewer reading `OrderService.cs` cannot tell which lines the builder just wrote from the lines that were there before her first review.
2. **A deletion is invisible.** Nothing in a path list or a file read carries "this function is gone" — the strongest class of remediation regression is the one the reviewer structurally cannot see.
3. **The verdict floats.** "Approve on the CURRENT diff" is checkable only if the current diff is a thing with a hash. Without one, carrying a pre-fix verdict forward is undetectable after the fact.

Per `CLAUDE.md` convention #9, the fix is not a firmer sentence in step 4. It is an artifact that has to be generated and named: the Orchestrator runs this script **before** delegating, and passes the resulting path in the brief. The reviewer reads a file; the file's hash is in a sidecar; the two together make "she reviewed this diff" a checkable claim.

## Rendering rules

- **Range** — `base..head` in the two-dot sense (`git log`/`git diff` with an explicit range). Both refs are resolved to commit shas up front via `rev-parse --verify <ref>^{commit}`; an unresolvable ref is exit 2, never a silently empty package.
- **`--head WORKTREE`** — the sentinel that makes this tool usable where it is actually needed. In `bgpdd-build`, a milestone's changes stay **uncommitted** until the Phase 5 commit gate, so `base..HEAD` there renders an empty package for work that plainly exists. `WORKTREE` (case-insensitive) runs `git diff <base>` with no range — base against the working tree — while `## Commits` still spans `base..HEAD` and is legitimately empty mid-milestone. The typical build invocation is therefore `--base HEAD --head WORKTREE`: the last commit is the previous milestone's, so the package is exactly the current milestone's uncommitted work. The sidecar records `head: "WORKTREE"` rather than a sha, because there is no commit to name.
- **`--changed-files`** — passed to git as a pathspec after `--`, restricting `## Stat` and `## Diff` (never `## Commits`: the commit list is the range's, and hiding commits would misrepresent what produced the diff). The header's `Scope:` line records the filter so a reader knows the package is partial.
- **The fence** — `## Diff` is fenced with a backtick run **one longer than the longest backtick run inside the diff**, minimum three. These packages routinely contain diffs *of markdown*; a fixed three-backtick fence gets closed by the content and the rest of the diff escapes the code block, which is exactly the corruption that would make the artifact worse than no artifact.
- **Binary files** — no `--binary` flag, so git emits its own `Binary files a/… and b/… differ` notice. Git output is decoded with `errors="replace"` throughout: a rendering tool must not die on the content it exists to render.
- **Encoding** — the package and sidecar are written UTF-8; git output is decoded `utf-8-sig`-tolerantly; stdout JSON is ASCII-escaped for cp1252 console safety, mirroring `record_run.py`.

## Excludes

- **Observed gap.** Nothing in the original renderer distinguished "reviewable diff" from "diff" — a lockfile bump or a regenerated designer file landed in `## Diff` exactly like a hand-written change, and a reviewer either read through it (wasted attention) or skimmed past it (the actual review became implicit, undocumented triage).
- **`DEFAULT_EXCLUDES`** is a flat, fixed list of `**/`-prefixed git pathspec glob patterns — lockfiles (`**/package-lock.json`, `**/yarn.lock`, `**/pnpm-lock.yaml`, `**/Cargo.lock`, `**/poetry.lock`, `**/Pipfile.lock`, `**/composer.lock`, `**/Gemfile.lock`, `**/packages.lock.json`), minified/compiled/generated output (`**/*.min.js`, `**/*.min.css`, `**/*.map`, `**/*.snap`, `**/*.g.cs`, `**/*.Designer.cs`, `**/*.generated.*`, `**/*.pb.go`, `**/*.pyc`), and vendored/build trees (`**/node_modules/**`, `**/vendor/**`, `**/dist/**`, `**/build/**`, `**/bin/**`, `**/obj/**`, `**/__pycache__/**`). Deliberately short and allow-nothing-surprising — it is not a taxonomy of "generated code", it is a list of concrete files a human should not be asked to read line-by-line.
- **`--exclude <pattern>`** (repeatable) adds a pattern; **`--no-default-excludes`** drops the built-in list. Effective excludes = defaults (unless disabled) + `--exclude` patterns. A user's own `--exclude` pattern is used **exactly as given** — it follows plain git glob rules, not a `DEFAULT_EXCLUDES`-flavored rule, so a caller who wants a nested match writes their own `**/` (`--exclude "**/*.log"`), the same way `DEFAULT_EXCLUDES` does internally.
- **The pathspec magic** is `:(exclude,glob)<pattern>` — verified empirically against `git` 2.55 in a throwaway repo (`git help pathspec` ships no man page on this platform): the magic words are order-insensitive (`:(glob,exclude)` behaves identically), an exclude-only pathspec (no positive pathspec at all) matches "everything except the excluded", and combining it with a positive `--changed-files` pathspec subtracts the exclusion from that set. Appended **after** any `--changed-files` paths in the `## Stat`/`## Diff` pathspec (or alone, still after `--`, when there are none). `## Commits` never takes a pathspec at all, so it is structurally unaffected.
- **The `**/` rule — reaching any depth.** Git's glob pathspec magic is `fnmatch` with `FNM_PATHNAME`: a bare `*` does not cross a `/`, and a literal filename with no wildcard matches only that exact path — `*.min.js` alone would exclude `app.min.js` at the repo root but not `src/app.min.js`, and `package-lock.json` alone would exclude only the root lockfile, missing `frontend/package-lock.json` in a monorepo. Every `DEFAULT_EXCLUDES` entry is therefore written `**/`-prefixed (`**/package-lock.json`, `**/*.min.js`, `**/node_modules/**`), which matches the pattern at **any** depth including the root — verified empirically (a throwaway repo with both a root and a `frontend/` lockfile: `**/package-lock.json` excludes both; `src/app.py` is untouched). A `--exclude` pattern is not auto-prefixed on the caller's behalf: it is used exactly as typed, so a pattern meant to reach nested paths needs its own `**/`.
- **Visibility, not silence.** Before filtering, `review_package.py` runs `git diff --name-only <range> -- <changed-files>` once unfiltered and once with the exclude magics; the set difference is `excluded_files`. The header always carries `- Excluded from diff (N): \`a\`, \`b\`` or `- Excluded from diff: none` — never omitted — and both the stdout JSON and the sidecar carry `excluded_files` and `exclude_patterns`. This is what lets Luna write a `### Files reviewed` line for a file whose hunks she never saw: `not reviewed: excluded from package`, instead of silently having nothing to say about it.
- **All-excluded is still exit 2, with a different message.** When every changed path in scope was excluded (the filtered diff is empty but the unfiltered one was not), the error names the cause explicitly — "every changed path was excluded by pattern; pass `--no-default-excludes` or narrow `--exclude`" — distinct from the plain empty-range message, because the fix is different (loosen the excludes, not fix `--base`).

## The size ceiling

- **What it converts.** `code-review-and-quality/SKILL.md` § `Escalate When` has always said, in prose, that a change too large to review properly should be split. Nothing enforced it — the Orchestrator (or a builder under deadline pressure) could hand Luna an arbitrarily large diff and there was no mechanical moment where "this is too big" became a decision instead of a feeling. `--max-diff-lines` is that moment, per `CLAUDE.md` convention #9.
- **What is counted**: `diff_lines`, the number of lines in the **filtered** `## Diff` text (excludes already applied) that start with `+` or `-` but not `+++`/`---` — added and removed lines, not context lines, not the file-header pair every hunk carries. Counting after excludes means a huge lockfile diff cannot trip the ceiling on its own; counting is deliberately a plain line count, not a token estimate or a weighted complexity score — the reference this converts talks about reviewability, and lines-changed is the crudest proxy that is still legible to the person deciding whether to waive it.
- **The waiver is hand-typed, on purpose** — `read_size_waiver`, `SIZE_WAIVER_HEADING_RE`, `WAIVER_PLACEHOLDER_RE`, `ANY_HEADING_RE` and `strip_fenced_blocks` are duplicated verbatim from `check_commit_gate.py` (family convention: stdlib-only, one file each, no shared module), so a `## Size waiver` section is read and validated identically in both gates: present, outside a fenced block, and not one of the placeholder shapes (`TODO`, `<...>`, a wrapped `<...>` span, etc.). The decision to exceed the bound is the user's; no script can verify a judgement call, only that one was actually recorded. This is the same labeled exception (convention #8) `check_commit_gate.py --waiver` already makes, not a new rule.
- **Failure modes**: `--max-diff-lines < 1` is exit 2 (a bound of 0 can never be satisfied); `--waiver` without `--max-diff-lines` is exit 2 (there is nothing to waive); over the ceiling with no `--waiver` is exit 2 naming both routes out (split the milestone via `/bgpdd-plan`, or write the `## Size waiver` section); over the ceiling with a `--waiver` file that has no `## Size waiver` heading, or one whose body is empty or a placeholder, is exit 2 with the specific cause.
- **A satisfied waiver still writes the package** (exit 0), with `- Size waiver: <path> (N lines over --max-diff-lines M)` in the header and `size_waiver: {path, present, section_found, body_nonempty, satisfied}` in the JSON and the sidecar — the exact shape `check_commit_gate.py` already gives its own `--max-changed-files` waiver, so a downstream reader parses both the same way.
- **Still not a judgement.** The ceiling is a structural refusal (exit 2: the package cannot be generated), never an exit 1 — this script does not gain an opinion about whether a large diff is *good*, only a mechanical bound on how large one may be before that question needs a human's written answer.

## An empty diff is exit 2

An empty package is not a cheap package — it is a review of nothing that looks exactly like a review of something. The cycle this tool serves always has a diff by construction (a remediation that changed nothing is itself the finding), so an empty range means the `--base` is wrong. Failing loudly at generation time is strictly cheaper than a reviewer approving an empty file. This is a deliberate divergence (convention #8) from `run_quiet.py`, which happily captures an empty stdout: there, emptiness is a legitimate observation; here it is a broken input.

## The sidecar

`<out>.meta.json` mirrors `run_quiet.py`'s shape — `argv`, `cwd`, `started`, `finished`, `exit_code`, `capture_sha256`, `tool`, `schema` — so a downstream reader already knows how to read it.

- `capture_sha256` is computed over the **finished package file's bytes**, so any later edit of the package invalidates it, including a plausible one.
- `argv` is the exact `git diff` argv that produced the load-bearing `## Diff` section — the same field name and role `run_quiet.py` gives its child command.
- `git_argv` additionally records all three commands (`log`, `diff --stat`, `diff`) as argv lists, so the whole package is reproducible rather than just its diff. This is the one field beyond the mirrored shape.
- `base` / `head` carry the resolved shas, not the refs as typed — `HEAD~1` means nothing a week later.

The sidecar is provenance, not a gate: nothing currently re-hashes it. Its value is that a review verdict can cite a package hash, and a mismatch is then detectable.

## Scope limits

- **It renders; it does not judge.** There is no exit 1. Whether the diff is good is Luna's job — including the size ceiling: exceeding `--max-diff-lines` is a structural refusal to generate the package (exit 2), not a verdict on the change.
- **No merge-base handling.** `--base` is whatever revision the caller names; if a three-dot merge-base range is wanted, resolve it with `git merge-base` and pass the sha.
- **No renames-follow, no `--find-copies`.** Git's defaults apply.
- **No token estimate.** The size ceiling counts diff lines, deliberately not tokens or a weighted complexity score — see § The size ceiling.
- **The ledger line is best-effort**, per the shared gate-ledger contract in `../SKILL.md`, even though this script is a renderer rather than a gate. It carries `--ledger`/`--milestone` so the lane-parity sweep (agent-audit Metric 20) sees a scripted step, and so a package generation is attributable next to the gates that follow it.

## Self-test inventory

`python scripts/review_package.py --self-test` runs **34** cases in a disposable `git init` repo.

The original **19**: all three sections plus the header render; the sidecar sha matches the written package; an edit to the package invalidates that sha; the sidecar records the exact git argv (including `-U<context>` and all three commands); an empty range is exit 2 with nothing written; a binary file in the diff is handled rather than crashed on; `--changed-files` restricts the diff and is recorded in the header; a filter matching nothing is exit 2; an unresolvable `--base` is exit 2; a non-git directory is exit 2; missing `--base` and missing `--out` are each exit 2; `--context` visibly changes hunk size; a diff of markdown gets a longer fence; the ledger records one line on both the PASS and the ERROR path; UTF-8 content round-trips; a deletion is visible in the package (the case the tree read cannot show); `--head WORKTREE` renders uncommitted changes and records `head: "WORKTREE"`; `WORKTREE` on a clean tree is still exit 2; and an unwritable `--out` is exit 2.

**Excludes (7)**: a lockfile in the diff is excluded by default and named in both the header's `Excluded from diff` line and the sidecar, with its hunk absent from `## Diff`; `--no-default-excludes` brings it back; `--exclude "*.md"` removes a (root-level) markdown file, since a user pattern is used as typed rather than auto-`**/`-prefixed; a diff where every changed path was excluded is exit 2 with the distinct all-excluded message; excludes never filter `## Commits` (a lockfile-only commit still appears in the commit log even though its diff is fully excluded); `--changed-files` naming only an excluded file is exit 2 with the same all-excluded message; a **nested** lockfile (`frontend/package-lock.json`) is excluded by default same as a root one, proving `DEFAULT_EXCLUDES`'s `**/` prefix reaches any depth.

**The size ceiling (8)**: under the ceiling passes and reports `diff_lines`; over the ceiling with no `--waiver` is exit 2 with nothing written; over the ceiling with a waiver whose `## Size waiver` body is a placeholder is exit 2; over the ceiling with a real waiver body passes and renders the `- Size waiver:` header line; `--waiver` without `--max-diff-lines` is exit 2; `--max-diff-lines 0` is exit 2; the line count ignores a file's own `+++`/`---` header lines; the line count is taken **after** excludes, so a huge excluded lockfile diff does not trip the ceiling.
