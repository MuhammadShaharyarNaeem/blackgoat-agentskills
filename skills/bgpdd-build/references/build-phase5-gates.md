# bgpdd-build — Phase 5 Sub-Contract: The Epic Gate Ladder

**This file is a SUB-CONTRACT, not rationale.** `bgpdd-build/SKILL.md` Phase 5 carries a stub that names this ladder's HALTs, gate script names and exit routes; the executable detail lives here and is binding. Read it in full before executing Phase 5. Where it and the spine appear to conflict, the spine wins — but nothing here is optional.

The ladder runs **before** the Dep delegation (spine step 3) except for the ship-decision shape gate, which runs after Dep returns. Steps keep their spine numbering.

## § Steps 1, 2 and 2.5 — the pre-Dep ladder

  1. **Completion Gate**: Before invoking Dep, verify that ALL milestones in `implementation/plan.md` are marked complete (`[x]`). If any milestone heading lacks `[x]`, loop back to Phase 1 for the next pending milestone.
  2. **Build Coverage Gate**:
     a. `python {PLUGIN_ROOT}/pipeline-tools/scripts/check_coverage.py --requirements .docs/{project-name}/requirements.md --test-report .docs/{project-name}/implementation/test-report.md --ledger .docs/{project-name}/implementation/gates.jsonl` (full CLI contract: `{PLUGIN_ROOT}/pipeline-tools/SKILL.md`).
     b. Exit 0 = every Must-Have `FR`/`NFR` has a passing test — report any `warnings` and `uncovered_should` entries as non-blocking notes, then proceed. Exit 1 = the `uncovered` array lists the Must-Have gaps. Exit 2 = an artifact defect, not a tool defect.
     c. On exit 1 or 2, DO NOT proceed — loop back to Phase 2 (Testing) with the exact `uncovered` IDs and `warnings` (or the `error` message) so Quinn closes the gap. (This closes the traceability chain: Rex's `FR`/`NFR` → Alex's task → Quinn's test.) After the fix, re-run step (a) to verify.
  2.5. **Acceptance Suite Gate (mechanical)** — the feature-scoped walkthrough, and the last gate before Dep. It is the only gate that proves the wall stands rather than the individual bricks (why: `build-rationale.md` § Why the acceptance suite is a separate gate).
     a. Delegate to **Quinn** (a follow-up to the same spawned Quinn if she is still resumable, else fresh): execute the matrix at `artifacts.acceptance_matrix` (or `.docs/{project-name}/acceptance-matrix.md` when that field is absent — see the Hydration Phase polymorphism in §1) end to end and record per-step results to `.docs/{project-name}/implementation/acceptance-results.md`. **Quote the exact result-line grammar into her brief** — `` `- <ScenarioId>.<StepNumber>: <PASS|FAIL|BLOCKED|NOT RUN> — <detail>` `` (manual steps cite their evidence path inline in the detail) — and name `{PLUGIN_ROOT}/pipeline-tools/SKILL.md` as the file that owns the full contract. **Do NOT let Quinn invent the format she is graded on** — the same principle as the `RUNTIME PROBE:` routing rule (Phase 2 step 1b). Brief her that `manual` steps are legitimate but pass **only** with a capture cited under `evidence/runtime/` — unevidenced, a manual step reads as NOT RUN and blocks. Inject the resolved path of `{PLUGIN_ROOT}/runtime-evidence/SKILL.md`.
     b. Run the gate against the resolved matrix path from step a:
        `python {PLUGIN_ROOT}/pipeline-tools/scripts/check_acceptance_suite.py --matrix <resolved acceptance-matrix path> --results .docs/{project-name}/implementation/acceptance-results.md --repo . --ledger .docs/{project-name}/implementation/gates.jsonl [--require-priority P0,P1]`
        **No `--changed-files` here (convention #8, refining `pipeline-tools`' freshness rule rather than contradicting it):** the results file is produced by the Quinn delegation immediately before this gate, so freshness holds by construction; `bgpdd-shipping`'s later re-execution is the one call site where staleness is possible, and that is where the flag is passed.
        Exit 0 = every gated scenario ran, every step is green, every manual step is evidenced, and no `[inverse of N]` dangles — proceed to Dep. Exit 1 = **BLOCK**: the JSON names the missing/failing/unevidenced steps; route the failures back through Phase 1–3 for the affected milestone, then re-run. Exit 2 = the matrix or results file is structurally non-conforming — an artifact defect: halt and surface it to the user, then route back to Alex (matrix) or Quinn (results). Full CLI contract: `{PLUGIN_ROOT}/pipeline-tools/SKILL.md`.
     c. **Resolve before checking absence.** If `artifacts.acceptance_matrix` is JSON `null`, this is a lite-originated epic with legitimately no matrix — say so explicitly to the user now and record the skip in Phase 6's game tape; do not check for the file at all. If the key is absent (an older state file), fall back to checking whether `.docs/{project-name}/acceptance-matrix.md` exists. **If a matrix was expected (the field was non-null or absent) and the resolved file does not exist**, that absence is a planning defect — **HALT** and route back through Alex. Do NOT let Quinn author the matrix she is about to be graded on, and do NOT skip the gate: a feature with no declared walkthrough is a feature nobody agreed on the meaning of "works" for.

## § Step 6 — ship-decision shape gate (after Dep returns)

  6. **Ship-decision shape gate (mechanical)**: after Dep returns, verify the artifact he just wrote is one the shipping pipeline can actually gate on:
     `python {PLUGIN_ROOT}/pipeline-tools/scripts/check_ship_decision.py --report .docs/{project-name}/implementation/ship-decision.md --ledger .docs/{project-name}/implementation/gates.jsonl`
     Deliberately **without** `--require-go`: a prep `NO-GO` is a legitimate, useful result here, and this gate checks the decision's *shape* (one unambiguous verdict, a Rollback heading, a checklist section), not its content. Exit 0 = well-formed — proceed. Exit 1/2 = the artifact is malformed: route back to Dep as a follow-up to produce a conforming decision (bounded by the Orchestrator Contract §2 2-round rule).
