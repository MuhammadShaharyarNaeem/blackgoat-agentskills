# Changelog

All notable changes to the `blackgoat-agentskills` plugin are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [SemVer](https://semver.org/).

## [Unreleased]

### Added
- **Nova (UI Builder)** (`agents/nova.md`): the Builder role split by domain. Mason is now backend-only (`[API]` milestones); Nova owns `[UI]` milestones, with `ui-design-patterns` plus the new component-mechanics craft floor wired in as Always dependencies and a rendered self-verification duty — screenshot evidence saved to `.docs/{project}/implementation/evidence/`, or an explicit `NOT RENDERED` note when rendering is impossible, never a visual claim made from a source read alone. Motivation: mixed-domain milestones were overloading a single builder (one Vue UI milestone measured ~51K chars of wake-up payload) and shipping UI that was weak on basic mechanics — whitespace, table pagination, text boxes, autocompletes.
- **`[API]` domain tag + milestone domain homogeneity** (`planning-and-task-breakdown`): every task now carries exactly one domain tag (`[UI]`/`[API]`; `[SEC]`/`[EXT]`/`[BLOCKED]` remain overlays, not domains), every milestone is domain-homogeneous, and a vertical slice now spans a *pair* of adjacent milestones — its `[API]` milestone immediately followed by its `[UI]` milestone, seamed by `Boundary contracts:` provides/consumes — a deliberate refinement of Step 3's Slice Vertically rule. `bgpdd-build` routes each milestone to the matching builder; a mixed-domain milestone is now a planning defect that halts the build for re-planning rather than something a builder muddles through.
- **`component-mechanics.md`** (`ui-design-patterns/references/`): the mechanical craft floor for tables/pagination, forms, autocomplete keyboard behavior, spacing on computed values, buttons, and feedback states — a checkable-items reference backing Nova's build-time baseline, Quinn's `[UI]` test assertions, and Luna's design-critique axis, rather than leaving those mechanics to be re-derived from taste each time.
- **`check_commit_gate.py`** (`pipeline-tools`): makes the `bgpdd-build` milestone commit gate machine-run instead of prose-run — reads the latest review's Verdict token, checks the review postdates the diff, checks the `blockers` ledger is empty, and performs the commit itself on a pass, so a skipped gate is loud (no commit happens) rather than silent. Ships with `--require-rendered-evidence` for `[UI]` milestones (the review must cite an existing evidence file — mechanizes `ui-design-patterns`' "source can fail a check but never pass one" rule, after an observed ERP run where design critiques approved rendered properties from source reads alone) and `--verify-tree` (git porcelain status checked against the declared `<changed_files>` plus `.docs/`; undeclared edits fail the gate). Motivated by an observed run that committed three consecutive milestones over standing Request Changes verdicts.
- **`next_milestone.py`** (`pipeline-tools`): mechanical next-pending-milestone derivation from `plan.md` — title, domain, full task block for the delegation brief, remaining-milestone counts, and a stale-cursor verdict. Defines the completion convention as `[x]` appended to the `## Milestone` heading line, replacing the previous mandate to re-read the full plan on every milestone (~290K chars, roughly 73k tokens, on a real plan) with roughly 2K of JSON.
- **`run_quiet.py`** (`pipeline-tools`): a build/test runner that writes the full log to disk and prints only errors with surrounding context lines, a tail, and the log path — so agents lose the noise but never lose a diagnostic. Paired with a new Build & Test Log Discipline rule in `dotnet-backend-patterns`, including no-Python flag fallbacks (`-clp:ErrorsOnly;Summary`, `--logger "console;verbosity=quiet"`).
- **`update_state.py`** (`pipeline-tools`): the sanctioned atomic read-modify-write path for `orchestrator-state.json`. Blocker removal requires `--evidence` and appends to a `blockers-resolved.log` — the append-only ledger doctrine made mechanical instead of relying on an agent to remember it.
- **Continuation vs fresh delegation** (`orchestrator-contract` §1): within one milestone, builder/tester fix rounds now continue the *same* spawned agent via delta-only follow-up messages rather than re-briefing from scratch, with mechanical triggers for when a fresh spawn is required instead (circuit-breaker trip, the 3-follow-up cap, or the runtime lacking follow-up capability). Reviewers are exempt and always spawn fresh — independence has to live in the verifier. Runtime-neutral: on runtimes without follow-up messaging, the rule falls back to fresh re-delegation carrying the prior handoff forward.
- **Three-tier persona injection** (`orchestrator-contract` §1): prefer a runtime-native agent type (no re-injection needed) → fall back to persona-file path injection → fall back to verbatim inline only as a last resort. From-memory persona recitals remain forbidden at every tier. Deliberately relaxes the former always-verbatim rule, which cost ~6–8K chars on every single delegation regardless of whether the runtime already knew the persona.
- **Convention #9** (repo `CLAUDE.md`): a prose rule that gets violated in practice converts to a mechanical gate rather than being re-worded or bolded harder — stated as a standing convention so future audit surgery has a default move instead of reinventing one each time.
- **Metric 18 — Convergent Redundancy (Distillation)** in `agent-audit`: flags clusters of rules/lines that encode one underlying principle as distillation candidates (merge prose upward into a principle + corollaries, push enforcement into a mechanism, move rationale to `references/`). Shipped alongside a distillation pass over the four heaviest contracts (`blackgoat-research`, `planning-and-task-breakdown`, `orchestrator-contract`, `agent-audit` itself — heuristics now carry a "Metric families" preamble) and a new **`--design` mode `supersession-annotation` lint** in `pipeline-tools` that machine-checks every Divergence & Supersession Register row against its in-place requirements.md annotation (scope limit: divergences never filed as register rows remain Phase 2.5's job).
- **AI-tells catalog** (`ui-design-patterns/references/ai-tells.md`): the long tail behind the generic-default check, adapted from the "AI Tells" section of [leonxlnx/taste-skill](https://github.com/leonxlnx/taste-skill) (MIT) — fabricated content/data (placeholder-canon names, fake-perfect numbers, generic avatars), decorative metadata, fake product previews, marketing-copy tells, separator/dash rationing, and list-decoration tells. Wired at three points: the **Generic-default check** points to it for content-heavy surfaces, a new Verification Checklist row gates demo/seed/empty-state data on the fabricated-content group, and Luna's craft-floor list in `references/design-critique.md` checks it during design critique. Two adaptations were required and are load-bearing: every group is **scoped by surface mode** (the source self-declares dashboards and multi-step product UI out of scope, so applying a landing-page tell to an Operate surface is its own error — a status dot on a server-health row is information, not a tell), and the source's absolute zero-em-dash ban is relaxed to a **rationing rule** (refused in short strings — headlines, pills, labels; natural frequency in body prose), labelled inline as a deliberate divergence from the source since it is a stylistic position rather than a craft floor. Deliberately NOT adopted from that repo: its 87 KB monolithic main skill (flat, no `references/` split), its mandated React/Next/Tailwind/Motion/shadcn stack (stack rules belong to the framework playbooks, and the squad's frontend playbook is Vue 3), its three-dial system and design-system map (duplicates the committed-direction contract), its Section 0 brief-inference stage including "ask one question" (subagents cannot pause for the user; brief inference is Rex's honing and Aria's direction commit), and its other 11 skills.
- **Design DB tool** (`ui-design-patterns/tools/design-db/`): the CSV design database + stdlib-only BM25 search from [nextlevelbuilder/ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) (MIT), vendored as a queryable tool with NO skill/trigger surface of its own. Consumed at exactly one pipeline point: `bgpdd-plan` Phase 2 step 3b injects the search-script path into Aria's brief for `[UI]` work, and `ui-design-patterns`' new **Candidate sourcing** rule has her query it for 2–3 candidate styles/palettes/font pairings before committing the visual direction — with the explicit precedence that the house contract wins over any database recommendation, and a no-Python fallback (commit from the brief and house rules alone). Deliberately NOT adopted: the upstream skill's self-activating description (trigger collision with the pipelines), its doctrine (recommends looks the house contract refuses by default), its design-system generator, and any new UI agent — direction stays Aria's, execution Mason's, critique Luna's.
- **Phase 2.5 — Adversarial Design Gate** (`bgpdd-plan`): a new Orchestrator-run phase between design and planning, with no delegated agent. The Orchestrator runs the `doubt-driven-development` cycle **per-section** on Aria's `detailed-design.md` (the design exceeds DDD's one-read unit), always extracting every money-moving sequence, every state machine, and every read-then-decide gate. Each DOUBT prompt carries a fixed 6-item attack list verbatim: crash windows (process dies after step N, for every N, each naming a recovery mechanism), reversals, races (every read-then-decide gate names its serialization mechanism and a two-concurrent-requests test), trust-boundary amounts, state-machine self-consistency, and config knobs. Findings land in `.docs/{project-name}/design/design-review.md`, go back to Aria as **ONE** revision round (deliberately tighter than DDD's 3-cycle bound, and labelled as such per convention #8), and the returned fixes are verified individually **plus** a regression re-read of every clause a fix touched — a fix round produces a new artifact, not a patch. Unresolved Blockers escalate to the user at the Iteration Checkpoint. Direct response to the v6/v7 money defects that crossed design → plan with 100% fidelity and zero detection. Plan-only by design: design documents exist only in this pipeline, so its absence from sibling pipelines is not a symmetry defect.
- **Three more `pipeline-tools` lints, with tests and fixtures**, landing alongside the `supersession-annotation` design-mode lint noted above — all four are new since v1.2.0, which shipped none of them. Plan mode: **`literal-count`** flags a transcribed artifact-inventory count in a task block (a number followed by an inventory noun — `error codes`, `routes`, `endpoints`, `components`, `screens`), machine-enforcing the pre-existing *count definitions, not mentions* doctrine; **`consumes-provides`** parses each task's `**Boundary contracts:**` field against a deliberately forgiving `provides:`/`consumes:` grammar and fails when an identifier is provided by a later task or by no task at all; **`path-hygiene`** flags path-shaped strings pointing outside the plan's own repository (Windows absolute, UNC, `file:///`, and any `../` repo-escaping segment). Shipped with ~390 lines of new tests and six fixture corpora, each exiting 1 on exactly one check.
- **Metrics 16 and 17 in `agent-audit`**, taking the coverage table from 15 rows to 18. **16 — Defect-Class Enforcement**: a hand-kept inventory verifying that rules installed in response to real escapes are still on disk, because their removal during an unrelated refactor is completely silent — no run ever reports that last month's gate is gone. It instructs the auditor to grep the live files rather than trust the inventory, since distillation passes relocate rules without deleting them, and it explicitly refuses to over-credit `supersession-annotation` (unfiled divergences remain Phase 2.5's job). **17 — Output-Rubric Gate Coverage**: each of 8 output-quality dimensions must map to at least one enforcing mechanism; an uncovered dimension is a Warning, not a Blocker, because not every dimension deserves a hard gate. Alongside these, three existing metrics were widened: **1** gains **writer ownership** (exactly one declared writer per artifact, with phase-order counting as much as writer count), **13** gains a mandatory first check that every `bgpdd-*` pipeline actually loads `orchestrator-contract.md` (the consolidation traded a visible duplication defect for an invisible omission one — a pipeline that silently drops the reference loses those rules with no symptom at all), and **15** expands to four checks including **existence before agreement**: a machine-enforced grammar documented only on the validator's side is unreachable, so the check never fires, and a check that never fires is indistinguishable from one that passes — hence Blocker, not Warning. The Verify section also gains a **stale-reference sweep** after any rename, reorder, terminology change, or **policy flip** — the last being the harder case precisely because nothing textual changed, so a skill can forbid a practice in its rules while its narrative still recommends it, and the narrative is where the reasoning lives.
- **`blackgoat-research` design-integrity rules**: the `## Divergence & Supersession Register` design heading; a **Self-Consistency Pass** built on *the document must be true wherever a reader lands* — samples win over prose (fix the sample, not the invariant), frozen means literal and complete (zero elisions in anything designated normative), assertion sets are checked as sets rather than pairwise, a revision rewrites in place instead of layering an override banner, and *a decision that makes any FR/NFR sentence false is a supersession* — **NOT complete until** both a register row and an in-place `requirements.md` annotation exist; a closing **Brief-Conformance Diff** walking every FIXED brief section and Must-Have FR/NFR item-by-item; and a **Mode 1 Blueprint / Mode 2 Scoped Advisory** split so `bgpdd-build`'s blast-radius review runs steps 1–3 only instead of the full design workflow.
- **`shipping-and-launch` verdict integrity**: the checklist is now explicitly *a floor, not the whole checklist* — where a numbered requirements set exists, every Must-Have FR and NFR gets its own row cited by ID and carrying its evidence, enumerated **from the requirements document, never from the built feature list**, because requirements expressed as qualities (accessibility, contrast, performance, theming, responsiveness) are exactly what a feature-shaped review cannot see; a requirement with no row is an unperformed check, and the recommendation is `NO-GO` until it has one. The GO/NO-GO decision now certifies **one exact tree state** (commit SHA recorded, working tree confirmed clean; uncommitted changes at verdict time are a `NO-GO`, and any later change means reissuing rather than leaving a document certifying a tree no longer on disk), and must **reconcile against the ledger**: every open blocker entry in `orchestrator-state.json` copied verbatim, waivers recorded beside the entry they waive and never inferred from silence or an elapsed phase, and `blockers: None` treated as an assertion that the ledger was read and found empty — never a default, never a summary of the author's own view.
- **Three `blackgoat-idea-honing` checklist items**, each closing a class that reached design unasked: check-then-act gates on counted or summed state (for *every* "at most N" / "only while capacity remains" rule — quota, balance, rate, seat, credit — ask what happens when two requests arrive at once), externally-supplied amounts that move money (what is the number validated against internally — a signature proves origin, not correctness), and **MoSCoW tiers must discriminate** (ask the cut question on every Must candidate; a requirement the user would ship without is not a Must).
- **`code-review-and-quality`: undeclared substitution and undeclared addition are both Critical** — review the change against the requirement text as written, not only against the task that paraphrased it. Both defects hide from a task-level read because the code is competent and the task is silent.
- **`ui-design-patterns`: library-vs-token-layer property ownership** — when a component library and a token/utility layer coexist, the committed direction names which layer owns each visual property (surface color, radius, border, elevation, typography, density) *before* code. Reaching for `!important`, a selector into the library's internal class names, or a global element-level override to land a design decision is a **defect signal, not a technique**: the property has no owner, the override survives only until the library's internals change, and that surface is now silently detached from the design system.
- **`CLAUDE.md` convention #8 — a deliberate divergence must name the rule it refines.** This plugin is a layered ruleset, and an unlabelled tighter-or-looser bound is indistinguishable from a contract collision: an auditor reports a false contradiction, and a reader silently picks whichever bound they read first.
- **Eval: `evals/contract/mechanical-pipeline/`** — a zero-LLM, deterministic integration case walking the full mechanical milestone lifecycle in a disposable git repo (next_milestone derivation with a stale cursor → update_state cursor/blocker writes → check_commit_gate failure paths: Request Changes, standing blocker, undeclared tree, missing rendered evidence → evidence-gated blocker resolution → gated commit → run_quiet error extraction); 13 asserted steps, safe to run unconfirmed (no `claude -p`), exempt from the runs=5 doctrine since it has no LLM variance. Its first execution found the `--verify-tree` untracked-directory defect below.
- **`check_agent_report.py`** (`pipeline-tools`): closes the last face-value verdicts in the pipelines — Cipher and Vera could report "pass/secure" with no durable artifact behind it, and `bgpdd-shipping` Step 3 consumed their handoffs unverified. Both agents now carry an output contract (Cipher: `security-report.md`; Vera: `verification-report.md`, replacing her no-artifact-by-default override) in `.docs/{project-name}/implementation/`: one section per round, one terse line per check — exact command, exit code, finding counts (never scanner output or log dumps — evidence binding by exit code, deliberately cheaper than log capture), `NOT RUN`/`BLOCKED` for anything unexecuted, findings with severity + file:line — ending in a machine-read `**Verdict:** Pass|Fail` token. The gate script parses the report fail-closed (last verdict-bearing section wins, exact tokens, unevidenced lines fail, zero check lines fail, any Critical finding fails — the verdict is arithmetic over the lines, per `code-review-and-quality`'s Approve rule) and shipping Step 3's new Report Gate runs it over both reports before proceeding, with the standard no-Python manual fallback. Self-tested plus `fixtures/agent-report-happy/` and `fixtures/agent-report-sad/`; `bgpdd-build`'s `[SEC]` lane now routes Cipher's rounds to the same file.
- **Eval: `evals/contract/alex-domain-tags/`** — a persona contract case (authored per the runs=5 / 4-of-5 doctrine) testing whether Alex emits `[UI]`/`[API]` domain tags and domain-homogeneous milestones from the planning skill alone: the delegation brief deliberately never mentions tags, homogeneity, or milestone shape — the omission is the test. Graded mechanically (per-task tag exclusivity, per-milestone homogeneity, `next_milestone.py` exit 0, coverage gate exit 0). A first live run passed on all criteria and surfaced the two format-seam defects below.
- **Five more contract eval cases** (`evals/contract/`), each hand-proven against a good artifact and at least one cheap-path artifact: `luna-clean-approve` (the `luna-verdict-arithmetic` trap case's missing mirror — the same fixture genuinely fixed, correct verdict `Approve`, catching reflexive suspicion and severity inflation); `cipher-security-report` (a clean-looking notes service hiding a hardcoded `sk_live` secret and wildcard CORS, graded by deferring to `check_agent_report.py`); `nova-ui-contract` (first builder-tier case — a frozen Vue 3 API-client boundary with no `node_modules`, so rendering is impossible and evidence honesty is graded directly); `scout-brief-path` (a Tier-2 brief path against Scout's Tier-1 default, plus a richly-commented dead module as bait); and `iris-discovery-guard` (a pre-existing curated `context.md` against a routine discovery brief, testing the do-not-overwrite rule).
- **Eval fixtures' `.docs` inputs tracked in git** — they were never actually frozen; an untracked working-directory file can drift silently between runs, defeating the "frozen fixture" premise the whole suite is built on. Now committed alongside each case.
- **Failing-run artifact preservation** (`run-evals.ps1`): a failing run now copies its working copy plus the grader output to `evals/results/artifacts/<case>-run<n>-<suffix>/` before the temp dir is deleted, so a flake is diagnosable from the actual failing state instead of destroyed with the temp dir.

### Removed
- **Parallel Fan-Out within a milestone** (`bgpdd-build` Phase 1) and its planning-side contract (`planning-and-task-breakdown`: the "authoritative for conflict-free parallel execution groups" reading of `Dependencies:`/`Files likely touched:`, and the parallelism clause of Milestone economy). Observed failure: parallel Masons committing to the shared working branch moved HEAD under their siblings, and each verification round then re-verified the entire moving diff instead of one task's changes — multiplying token cost for a wall-clock gain the pipeline doesn't need. A milestone is now again the unit of delegation: one Mason builds its tasks in plan order, one Quinn/Luna round verifies the milestone's diff once. (Read-only parallel lanes are unaffected: discovery Scout fan-out, Luna+Cipher `[SEC]` reviews, shipping Stage 2.)
- **`Files likely touched:` task field** (`planning-and-task-breakdown` template, Verification checklist, and all cross-references). Its only structural consumer was the removed fan-out conflict computation, and it duplicated `Named identifiers:`, which already requires exact file paths to create/modify. `Dependencies:` remains as the ordering contract.
