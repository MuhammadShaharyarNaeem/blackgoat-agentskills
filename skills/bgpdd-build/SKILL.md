# End-to-End Multi-Agent PDD: Execution Phase (bgPDD-Build)

This Standard Operating Procedure (SOP) coordinates the execution squad (Mason, Nova, Quinn, Luna, Dep, Cipher; Aria as conditional blast-radius advisor; Alex as conditional re-planning agent) to take an existing `plan.md` through building, review, optimization, testing, and deployment prep.

Invoke with `/bgpdd-build` (add the `auto` argument for Autonomous Execution Mode — see §3).

Rationale, observed-failure narratives and examples for every rule below: `references/build-rationale.md`, read on demand. The spine wins on any apparent conflict.

**Four `references/` files are SUB-CONTRACTS, not rationale** — binding detail, each fronted below by a ≤120-word stub naming its HALTs, gate scripts and exit routes. A stub is an index, never a substitute: **read the named file in full before executing that phase or gate.** `build-phase0.md` (readiness), `build-gate-ladders.md` (commit + runtime-evidence gates), `build-phase5-gates.md` (epic ladder), `build-phase6.md` (game tape).

Committing is pipeline state management, not application-code writing — it does not violate your no-coding rule.

Exit 0 = passed and the commit exists; exit 1 = do not commit, back into the Phase 3 step 4 cycle; exit 2 = artifact/environment defect. A milestone commits only when no blocker scoped to it, and none scoped to nothing, stands. There is no "commit now, the finding is minor".

## 2. Global Safety Mechanisms

Error recovery is the skeleton's section, which points at the Orchestrator Contract §2. This pipeline's refinements, because it is the only pipeline where workers write code:

- **Incremental persistence includes committing.** The instruction you pass every agent must cover code as well as documents: partial work is committed to the working branch (see Git Workflow in §1) before the agent returns, which is what makes the contract's rule enforceable here rather than aspirational.
- **Resumption after interruption** must state exactly what already exists — files *and* commits — so the fresh agent resumes rather than restarting or overwriting finished work.
- **Log discipline.** Every builder/tester delegation is instructed to run builds and test suites through `{PLUGIN_ROOT}/pipeline-tools/scripts/run_quiet.py --log .docs/{project-name}/implementation/logs/<slug>.log -- <command>` when a Python 3 runtime is available. `run_quiet.py` defaults to a 240s timeout; pass `--timeout` explicitly for long suites (e.g. real-DB integration tests). Exit 124 with a `TIMEOUT:` header is a harness result to escalate, never recorded as a test FAIL. Stack skills (e.g. `dotnet-backend-patterns`) carry the no-Python flag fallbacks.
- **Auto Mode raises the stakes on all of the above (§3)**: an unattended run may proceed a long time with nobody watching to restart a lost phase.

## 3. Auto Mode (Optional Argument)

If invoked with the `auto` argument (`/bgpdd-build auto`), operate in **Autonomous Execution Mode**:
- **Macro-Loop Execution**: Seamlessly transition [Phase 1 (Build) → Phase 2 (Test) → Phase 3 (Review) → Phase 4 (Refactor)] in a loop for *each milestone* in `plan.md` without asking for "proceed" confirmation.
- **Phase 5 (Epic Shipping Prep)**: Dep writes the prep `ship-decision.md` (GO/NO-GO) — deploy is deferred to `/bgpdd-shipping`.
- **Phase 6 (Game Tape Checkpoint)**: the Orchestrator appends this run's evidence to `game-tape.md`; Forge runs once at epic end, in `bgpdd-shipping` Step 7.
- **HALT**: Once ALL milestones are complete, drop out of Auto Mode. You MUST ask for explicit human approval before invoking Phase 5 for the entire epic (Phase 6 is a free Orchestrator checkpoint — no approval needed).
- **Circuit Breakers**: If the builder loops 3 times, or Luna flags a blocker the builder cannot fix, immediately drop out of Auto Mode and halt for human intervention.

Non-auto phase-transition reporting: the few-shot example lives in `references/build-rationale.md` § Few-shot handoff example.

## 4. Folder Structure (Semantic Memory)

This is **Tier 2** — the per-enhancement work dir (`.docs/{project-name}/`): this pipeline's read-write workspace, scoped to the current enhancement. **Tier 1** (`.docs/summary/{feature}/`) is the global knowledge base produced by **`/bgpdd-discovery`** — read-only for this pipeline. NEVER write build artifacts to Tier 1.

```text
.docs/{project-name}/
└── implementation/        # Checklists, reviews, and release plans
    ├── plan.md            # Dependency-mapped task list (REQUIRED INPUT)
    ├── environment-manifest.md # Services, repointing map, forbidden hosts, capabilities (Phase 0, user-supplied)
    ├── test-report.md     # Test execution logs and coverage (Quinn)
    ├── review-report.md   # Quality review (Luna)
    ├── acceptance-results.md # Per-step walkthrough results (Quinn, Phase 5 step 2.5)
    ├── ship-decision.md   # Prep GO/NO-GO (Dep, Phase 5); shipping Stage 2 Dep refreshes for final launch
    └── game-tape.md       # Per-phase evidence checkpoints (Orchestrator, Phase 6)
```

The four evidence paths under `implementation/evidence/` — `preflight/`, `build/`, `runtime/`, `review/` — are written and gated by four different parties and **may never be merged**: see `references/build-rationale.md` § Four separate evidence paths.

## 5. Detailed Pipeline Phases

### Phase 0: Verification Readiness (Orchestrator + user, main session)
> **MANDATORY: read `references/build-phase0.md` in full before executing this phase** — a sub-contract, not rationale.
- Interactive, Orchestrator-owned, **once per session** before the first builder delegation. Resolve the environment manifest by precedence, then run the preflight: capture each readiness check with `run_quiet.py --capture` under `evidence/preflight/`, and exercise once every capability the plan's `[vs:]` surfaces demand.
- **The only immediate HALT is a gap that blocks the *building*** — an uninspectable schema, an unreachable feed, a compile-time credential. Every other gap is recorded via `update_state.py --add-blocker`, blocking at the evidence boundary; Phase 1 proceeds. `--resolve-blocker` clears by id.
- Persist via `update_state.py --set-artifact environment_manifest=…`; skip only when every milestone is `[vs:none]`.
### Phase 1: Building
- **Delegated Agent**: **Mason** (Builder, `[API]`/backend milestones) or **Nova** (UI Builder, `[UI]` milestones). Each reads their methodology dependencies (TDD, debugging, SDD) on-demand.
- **Workflow**:
  1. Pick the next milestone — not the stored `milestone_cursor`, and not the one after the milestone you just finished (see the Hydration Phase rule in §1). Do this every time you enter Phase 1, not once per run.
     - **Primary path**: run `python {PLUGIN_ROOT}/pipeline-tools/scripts/next_milestone.py --plan .docs/{project-name}/implementation/plan.md --state .docs/{project-name}/orchestrator-state.json --emit-gate-args --ledger .docs/{project-name}/implementation/gates.jsonl`. Result `NEXT` → proceed with its `milestone_text` and `domain` for the routing step below. Result `MIXED` (exit 1) — including when the script treats `UNTAGGED` as `MIXED` — → the routing rule's planning defect (step 2): **halt** and surface it, do not improvise a split. Result `DONE` → skip ahead to Phase 5's completion gate.
       - `--emit-gate-args` returns a `gate_args` object (`surface`, `expect_status`, `require_keys`, `forbid_hosts`) parsed from the milestone's `RUNTIME PROBE:` line. **Carry it forward to Phase 2 step 4 — convention #9 in force** (why: `references/build-rationale.md` § `--emit-gate-args`). If `gate_args` is null for a field, read that field off the `RUNTIME PROBE:` line yourself.
       - `--ledger` surfaces an advisory `unbacked_complete` list — milestones marked `[x]` with no PASS commit-gate entry behind them. Treat any entry as a state defect and surface it before building further.
  2. **Route by domain.** Read the domain off the milestone's tasks' domain tags (`[API]` or `[UI]`, assigned at planning). Route the whole milestone to the matching builder: `[API]` tasks go to Mason, `[UI]` tasks go to Nova. A milestone mixing `[UI]` and `[API]` tasks is a PLANNING DEFECT: **halt** and surface it to the user for re-planning (route back through Alex) — do NOT improvise a split yourself. An `UNTAGGED` milestone (no `[UI]`/`[API]` on heading or tasks) is the same class of planning defect as `MIXED` — halt and surface it; do not invent a route.
  3. Delegate the milestone to a **single builder agent (Mason or Nova per the routing rule)**, who builds its tasks in plan order. **The milestone is the unit of delegation — do NOT fan the milestone's tasks out to parallel builder agents**, even when their `Dependencies:` fields show no ordering constraint between them (why: `references/build-rationale.md` § Why one builder per milestone). **CRITICAL CONTEXT HANDOFF**: copy the exact text of the active milestone from `plan.md` into the delegation prompt so it knows exactly what to build.
     - **Point the builder at the probe it is already holding.** The pasted milestone text already carries the `[vs:<surface>]` tag and the `RUNTIME PROBE:` line inside its `### Checkpoint:` block. Quote both into the brief explicitly, exactly as Phase 2 step 1b does for Quinn, and instruct the builder to run the declared probe as a **self-check** written to `.docs/{project-name}/implementation/evidence/build/` — never `evidence/runtime/`, which is the verifier's gating path. This adds no gate: Phase 2's Runtime Evidence Gate still runs solely against Quinn's independent capture.
  4. **STRICT BLAST RADIUS RULE**: Instruct the builder that *before* modifying any shared DTO or library, it MUST trace dependencies by searching the codebase for all consumers of the DTO/library. If the radius extends beyond its active microservice, it must document it in its handoff and return for architectural review.
  5. If the blast radius exceeds the active microservice:
     a. Notify the User: "Blast radius exceeds the current microservice boundary. Architectural review required."
     b. Delegate to the **Aria** agent as a temporary advisor (**Mode 2 — Scoped Advisory** in her `blackgoat-research` methodology — she must NOT write or modify `detailed-design.md` in this mode), passing her the builder's blast-radius report; ask for a scoped architectural recommendation returned in her `<handoff>`.
     c. Present Aria's recommendation to the User for approval.
     d. After approval, delegate a **fresh builder** agent (same builder as this milestone's routing), passing it the prior handoff state and Aria's ruling.
  6. Read the builder's returned handoff and extract the strict `<changed_files>` XML list from it. **Accumulate, do not replace**: the milestone's changed-files set is the union of the builder's `<changed_files>` here, Quinn's `<changed_files>` from Phase 2 and every retest round, and any Phase 3/4 remediation `<changed_files>` — accumulated across the whole milestone, never replaced by the last handoff. This accumulated union is what feeds `--changed-files` at the commit gate (§1).
  7. **Record the delegation** (Orchestrator Contract §4 owns the rule; `{PLUGIN_ROOT}/pipeline-tools/SKILL.md` owns the CLI):
     `python {PLUGIN_ROOT}/pipeline-tools/scripts/record_run.py --log .docs/{project-name}/implementation/run-log.jsonl --pipeline bgpdd-build --phase "Phase 1" --event delegation --agent <mason|nova> --model <tier> --unit "<milestone title>"`
     `--model <tier>` is **mandatory** on a delegation record (exit 2 without it) — name the tier the delegation actually ran at, not the one the plan recommended. Plus `--duration-s`/`--tokens-in`/`--tokens-out` (or `--from-json <the completion payload>`) from the runtime's completion notification, and `--status` from the handoff. Phases 2, 3 and 5 repeat this on their own returns with their own `--phase`/`--agent`; only the first occurrence spells the invocation out.

### Phase 2: Testing
- **Delegated Agent**: **Quinn** (QA Tester). She reads her methodology dependencies (runtime-evidence always; TDD when authoring new test code; debugging and playwright as scoped) per her dependency table.
- **Workflow**:
  1. Delegate to the **Quinn** agent. **CRITICAL CONTEXT HANDOFF**: pass her the exact text of the active milestone and the `<changed_files>` list from the builder. **CRITICAL PATHING**: instruct her to append results to `.docs/{project-name}/implementation/test-report.md`. If the milestone contains `[UI]`-tagged tasks, inject the resolved path of `{PLUGIN_ROOT}/ui-design-patterns/references/component-mechanics.md` — Quinn derives her [UI] assertions from it (each citing the item's CM-id).
  1b. **Route the runtime probe into her brief.** The milestone's `### Checkpoint:` block is already inside the verbatim `milestone_text` you pasted in step 1 (level-3 headings never terminate a milestone block — why `planning-and-task-breakdown` forbids `## Checkpoint:`). Quote its **`RUNTIME PROBE:`** line into her brief explicitly and instruct her to: execute it **out-of-process**, save the capture under `.docs/{project-name}/implementation/evidence/runtime/` via `run_quiet.py --capture`, and cite it with a `**Runtime evidence:**` line in her `#Task [N]:` block. Inject the resolved path of `{PLUGIN_ROOT}/runtime-evidence/SKILL.md`.
     - **The capture must come out of `run_quiet.py --capture`, and the probe must be a real client.** The gate in step 4 reads the `<capture>.meta.json` sidecar that only `--capture` writes, so a hand-authored capture file fails structurally; it also refuses a non-zero probe exit code, and refuses a probe that is not a client invocation (curl, httpie, newman, …) unless the milestone's `RUNTIME PROBE:` line itself carries `[probe-exempt: <reason>]`. Say both in her brief — **she cannot add the exemption herself**: the probe line is the planner's artifact, not hers.
     - **If the milestone declares no `RUNTIME PROBE:` line, HALT.** That absence is a planning defect (`planning-and-task-breakdown`, Step 5) — surface it and route back through Alex. **Do NOT let Quinn invent the probe**: a probe authored by the agent it grades is not a criterion, and the milestone's `[vs:<surface>]` tag exists precisely so this cannot be silently skipped.
     - **If the milestone's surface is `[vs:none]`**, pass its written justification instead and skip the probe — the gate in step 4 is not run for that milestone.
  2. Instruct Quinn to design and directly execute the test strategy for the newly built code.
  3. **Rejection Loop** — **fix-verification precondition first (Orchestrator-side, mechanical).** A builder's rejection-round handoff MUST carry a `<fix_verification>` element naming the check it re-ran and the observed result (Mason §7 / Nova §3). If the element is absent, do **NOT** re-delegate to Quinn — return to the same builder for it, and **do not count that return against the 3-round bound**: the bound caps fix *attempts*, and spending one on a missing report field is not what it is for. A `NOT VERIFIED — <what blocked>` element is legitimate and proceeds to Quinn; a missing one does not. This is convention #9 in force: a field you must read, not prose the builder must remember.
     Then, the loop itself: if Quinn's returned handoff reports failing tests, extract her failing-test logs and send them to the milestone's builder **as a follow-up to the same spawned builder agent** (Mason or Nova, Bugfix mode) — per Orchestrator Contract §1, *Continuation vs fresh delegation*, fresh only on its mechanical triggers. Loop builder ↔ Quinn, with Quinn's retest likewise continuing the same spawned Quinn as a follow-up, until tests pass. **Bound this to 3 rounds per milestone** — a deliberate refinement vs Contract §2's 2-round autonomous-rejection bound, and **a distinct counter from it** (§2 bounds rejection of a defective *artifact*; this bounds builder-fix → Quinn-retest cycles on failing *tests*): track how many rounds the current milestone has been through. If tests still fail after round 3, **HALT** and surface to the user: the milestone, the builder's attempted fixes across rounds, and Quinn's exact failing-test logs. Do NOT delegate a 4th round. (Also deliberate: this replaces the fresh-delegation-each-round wording this pipeline previously carried.) Separately, follow-ups to a single spawned agent are capped per Orchestrator Contract §1's continuation cap, counted across Phases 2–4 and independent of the round count above.
  3b. **Record each Quinn return** as Phase 1 step 7 does, with `--phase "Phase 2" --event delegation --agent quinn --model <tier> --unit "<milestone title>"` and `--rounds <this milestone's round number>` — every retest round is its own record, which is what makes the round count countable rather than remembered.
  4. **Runtime Evidence Gate (mechanical) — MANDATORY: read `references/build-gate-ladders.md` § Phase 2 step 4 in full before running it** (a sub-contract, not rationale). Run it as soon as Quinn's handoff is in hand, before Phase 3: a `PASS` in her report is a claim, the capture is the evidence. `check_runtime_evidence.py`, with `--surface`/`--require-key`/`--expect-status` taken from `gate_args`, `--forbid-host` from the manifest, and `--require-openapi-reachable` on `[vs:api]`/`[vs:web+api]`. Skipped for `[vs:none]` and — a deliberate refinement (convention #8) — for `[vs:ui]`. Exit 0 = proceed to Phase 3; exit 1 = **BLOCK**, back into the rejection loop (counts as a round); exit 2 = a non-conforming capture, back to Quinn. **HALT** rather than loop if the application cannot be started out-of-process here.

### Phase 3: Code Review
- **Delegated Agent**: **Luna** (Reviewer). She reads her methodology dependencies on-demand.
- **Workflow**:
  1. **Generate the review package BEFORE delegating** — a reviewer handed only a path list reads the amended tree, where a fix is indistinguishable from the status quo and a deletion is invisible:
     `python {PLUGIN_ROOT}/pipeline-tools/scripts/review_package.py --repo . --base HEAD --head WORKTREE --changed-files <the accumulated Phase 1 step 6 list> --out .docs/{project-name}/implementation/review/review-package.md --ledger .docs/{project-name}/implementation/gates.jsonl --milestone "<milestone title>"`
     `--base HEAD --head WORKTREE` because the milestone is uncommitted until Phase 5. Exit 0 = the package exists; exit 2 = git failed or the diff is empty — fix the range, never delegate without the artifact. Then delegate to the **Luna** agent, passing her **both** the exact `<changed_files>` XML list (so her scope is surgical) **and the review-package path** (so she reviews the diff, not the tree). Full CLI contract: `{PLUGIN_ROOT}/pipeline-tools/SKILL.md`.
  1b. **[SEC] Parallel Security Review**: if the active milestone contains `[SEC]`-tagged tasks, delegate **Cipher** in parallel with Luna in the same batch, passing him the same `<changed_files>` list, scoped to the security surface of those tasks. **CRITICAL PATHING**: instruct Cipher to append his audit round to `.docs/{project-name}/implementation/security-report.md` per his persona's Security Report contract (his durable artifact — the shipping pipeline's Report Gate reads the same file). Treat any vulnerability finding in Cipher's handoff as a Critical blocker (step 4 routing).
     - **Report Gate (mechanical)** — run as soon as Cipher returns, before you act on his handoff: a "secure" in the handoff is a claim; the report file is the evidence.
       `python {PLUGIN_ROOT}/pipeline-tools/scripts/check_agent_report.py --report .docs/{project-name}/implementation/security-report.md --ledger .docs/{project-name}/implementation/gates.jsonl`
       Exit 0 = his `Pass` verdict is backed by evidenced check lines with zero standing Critical findings — proceed to step 2. Exit 1 = **BLOCK**: the JSON names the cause; route it into the step 4 remediation cycle exactly as a Critical finding. Exit 2 = the report is structurally non-conforming — an artifact defect; route back to Cipher for a conforming report. Same gate `bgpdd-shipping` Step 3 runs on the same file. Full CLI contract: `{PLUGIN_ROOT}/pipeline-tools/SKILL.md`.
