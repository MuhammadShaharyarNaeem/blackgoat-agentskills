# pipeline-tools

A family of pure-stdlib Python 3 CLIs under `scripts/` that convert the bgpdd pipelines' prose gates into commands with exit codes. The Orchestrator runs them directly via a shell action, and there is no manual open-and-read substitute for any of them.

**Who may run which — a labelled carve-out from this file's own "never delegated to an agent" rule (convention #8).** That rule was written absolutely and is false as written: `base-persona.md` § Timeouts instructs *every* agent to wrap its commands in `run_quiet.py --log`, `agents/cipher.md` and `agents/vera.md` instruct their agents to take each check through `run_quiet.py --capture`, and `api-contract-evolution/SKILL.md` § Verification has its loading agent run `check_openapi_diff.py`. The rule the divergence refines is the real one, which is about *authority*, not about scripts:

- **Orchestrator-only — the commit, ship and close gates.** `check_commit_gate.py`, `check_ship_decision.py`, `check_quick_close.py`, `check_batch_close.py`, `mark_milestone.py`, `update_state.py`, `next_milestone.py`. These decide whether work is done, land commits, and move pipeline state. A subagent running one is grading its own submission, and Orchestrator Contract §4 owns their invocation. The same holds for every other gate a pipeline step names as the Orchestrator's — `check_test_authenticity.py`, `check_runtime_recipe.py`, `check_coverage.py`, `check_agent_report.py`, `check_runtime_evidence.py`, `check_handoff.py`, `check_redelegation.py`, `check_ledger.py` and the rest: the reader of an agent's output is never that agent.
- **Permitted and expected — self-gating captures and lints the producing agent runs on its OWN output, before it hands anything back.** `run_quiet.py` (both `--log`, which is mandatory for every command an agent runs, and `--capture`, which is how Cipher and Vera evidence a check line) and `check_openapi_diff.py` on the contract document the agent just changed. An agent running these is doing its own work properly, not adjudicating it; the gate that reads the result still runs in the main session.

Anything not in the second list is Orchestrator-run. A persona that needs to run something else names it in its own file and says why.

This file is the **lean contract spine**: per script, what it is for, how it is invoked, its flags, its JSON keys, its exit codes, and its problem codes. Rationale, observed-failure narratives, parsing grammars, fixture inventories, scope-limit essays and self-test case lists live in `references/<script-name>.md` and are loaded on demand.

**Its size is a deliberate divergence from CLAUDE.md convention #1, which asks a `SKILL.md` to be a lean spine with depth in `references/`.** This file is not a methodology contract read by an agent adopting a role; it is the OPERATIONAL contract for thirty-odd CLIs, and a caller needs a flag's exact name, its exit code and its problem codes *at the moment of invocation* — a synopsis that sends the reader to a second file to learn whether `--require-gates` takes a comma list is a synopsis that gets guessed at instead. So the split is by KIND, not by length: every invocable term (synopsis, flags, JSON keys, exit codes, problem codes, migration notes and the one-sentence reason a term exists) stays here; every narrative (observed-failure stories, parsing grammars, fixture inventories, scope-limit essays, self-test case lists) lives in `references/<script-name>.md`. The bound that replaces "short" is that bound: prose here that does not change what a caller types belongs in `references/`.

## Single contract authority

The pipeline gates — `bgpdd-plan` Phase 3.5, `bgpdd-lite` Phase 2.5, `bgpdd-build` Phase 2 and Phase 5, `bgpdd-verify` Phase 3, `bgpdd-secure` Phase 1 and Phase 3, `bgpdd-shipping` Steps 0.3–3.5, and `bgpdd-bugfix`, `bgpdd-quick` — reference this file as the single source of truth for every CLI's contract (invocation, flags, JSON shape, exit codes, parsing rules). They do not restate the rules inline; update them here only. The file therefore stays at this path: fourteen files across the pipelines, the personas and the sibling skills cite it by name.

## Gate ledger

Every gate in this family accepts `--ledger <path>` and appends **exactly one JSON line per run, on every exit path** (creating parent directories):

```json
{"ts": "<ISO-8601 UTC>", "gate": "<script basename>", "argv": ["..."], "milestone": "<--milestone value or null>", "inputs": {"<path as given; a cited capture is keyed by its resolved path relative to the cwd>": "<sha256 hex or null>"}, "verdict": "PASS|FAIL|ERROR", "exit": 0, "prev": "<sha256 of the previous line, or \"genesis\">", "self": "<sha256 of this record without `self`>"}
```

`inputs` carries every file path argument the script read. `verdict` maps exit 0/1/2 to PASS/FAIL/ERROR. Writing the ledger is **best-effort**: a ledger that cannot be written never changes the gate's own verdict — it is an audit trail for LATER gates, not a term in this one. `update_state.py --resolve-blocker` additionally records `"action": "resolve-blocker"` and `"evidence": "<the raw --evidence value>"`, plus, once it resolves, `"evidence_resolved"` (the path, state-dir-relative) and `"evidence_sha256"`. `--evidence` must now resolve to an existing, non-empty file (state directory first, then the CWD) or the call exits 1 with nothing written — "trust me" is a syntactically valid but nonexistent path, refused like any other typo, not merely recorded as unverifiable prose. `record_run.py --allow-tier-inversion` adds `"tier_inversion_reason"` to the RUN LOG record (not the ledger — that script is not a gate).

**`run_quiet.py --capture --ledger` writes a record too, and it is not a gate verdict.** Its `verdict` is `CAPTURED` (never PASS/FAIL/ERROR), its `exit` is the CHILD command's exit code, its `inputs` are the capture and its `.meta.json` sidecar, and it carries two extra chained fields: `command_argv` (the child argv) and **`capture_sha256`** — the artifact's hash as it landed on disk. That last field is the lookup key three readers use (`--require-ledgered-captures`, below): it is what distinguishes a capture the tool RECORDED from a self-consistent pair somebody authored.

### The chain: `prev` and `self`

The ledger is the evidence four gates read a verdict out of, and until it was chained it was a text file anybody could retype. Every record therefore carries two hashes, written by the same byte-identical helper in all fourteen gates:

- **`prev`** — sha256 of the **previous line's bytes**, stripped of its terminator and surrounding whitespace (so a CRLF ledger written on Windows chains identically to the same file read on POSIX). `"genesis"` when the ledger is missing or holds no non-blank line yet.
- **`self`** — sha256 of this record **serialized canonically without its own `self`**: `json.dumps(record_without_self, sort_keys=True, separators=(",", ":"))`, UTF-8. Key order in the written line is therefore not content; the line's own bytes still feed the next record's `prev`.

Both are computed at write time, after any `extra` fields are merged, so every field in the record is covered.

**What this buys, and the limit that stays.** A single record edited, inserted or removed after the fact is now visible: the edited line fails its own `self`, and an inserted or removed one fails the following line's `prev`. What it does **not** buy — deliberately, and this limit is accepted rather than papered over — is protection against a forger who rewrites the **entire tail** consistently, recomputing every `prev` and `self` from the edit point onward. There is no external anchor (no signature, no notary), so the chain detects tampering that is *local*, not tampering that is *thorough*. Truncating trailing records is undetectable for the same reason. The change is that casual edits stop being free, not that the ledger becomes unforgeable.

**Migration.** A record written before this contract carries neither field. Such **legacy records are tolerated only before the first chained record** — a pre-chain ledger migrates forward by simply being appended to. Once a chained record exists, an unchained one after it is a refusal (`legacy-after-chained`): reverting to unchained is exactly what deleting the chain looks like. **Any gate that appends to a shared ledger must therefore chain**; a new gate that copies the old unchained `append_ledger` will break every chained ledger it touches.

### `check_ledger.py` — the chain verifier

Documented here rather than in its own section because it is not a pipeline gate: it verifies the artifact this section describes.

```bash
python check_ledger.py --ledger <path>
python check_ledger.py --self-test
```

- Walks the chain and reports the **first** broken link. `--ledger` is the **subject under test, not an append target** — unlike every other script in this family it writes nothing (convention #8, a deliberate divergence from "every gate carries `--ledger`"): appending its own record would extend the chain it is reporting on.
- **JSON keys** — `ledger`, `pass`, `records`, `chained_records`, `legacy_records`, `problem` (`{problem: "chain_broken", line, reason, detail}` or null), `error`.
- **Reasons** — `unparseable`, `legacy-after-chained`, `incomplete-chain-fields` (only one of `prev`/`self`), `self-mismatch` (the line was edited), `prev-mismatch` (a record was inserted, removed or edited before this line), `unreadable`.
- **Exit codes** — **0** intact (an empty ledger and an all-legacy ledger included); **1** `chain_broken`; **2** missing `--ledger` or a ledger file that does not exist.
- **Self-test** — **21** cases, including the five the contract names (intact, edited middle, inserted, legacy-then-chained, chained-then-legacy), one asserting the accepted tail-truncation limit so it cannot regress into a silent claim, and two **drift guards** over the sibling scripts: the helper block must be byte-identical in every file that carries it, and each of the fourteen chained gates must actually set `prev`/`self` before it writes. A gate that appends unchained is what turns a shared ledger into `legacy-after-chained`.
- **Who else checks it** — `check_commit_gate.py --require-ledger-gates`, `check_ship_decision.py --require-ledger-gates` and `mark_milestone.py --require-gates` verify the chain of the ledger they read *before* looking at any verdict, and fail with `ledger_chain_broken`. A PASS read out of a tampered ledger is not a weaker PASS; it is no PASS.

Carrying `--ledger` (and therefore chaining): `check_commit_gate.py`, `check_quick_close.py`, `check_batch_close.py`, `check_agent_report.py`, `check_acceptance_suite.py`, `check_ship_decision.py`, `check_coverage.py`, `check_blockers.py`, `check_runtime_evidence.py`, `check_bugfix_intake.py`, `check_red_green.py`, `next_bugfix_route.py`, `update_state.py`, `mark_milestone.py`, and — a **deliberate divergence from "every gate carries `--ledger`"** (convention #8), because it is a *writer*, not a gate — `run_quiet.py --capture`. `next_milestone.py` and `summarize_run.py` READ the ledger but never write it; `next_bugfix_route.py` both reads and writes it (it refuses to route without a recorded intake PASS). `record_run.py` carries no `--ledger` flag at all — it is not a gate; it writes the other durable record, the run log, described below. The pipelines pass `--ledger .docs/{project-name}/implementation/gates.jsonl` on every gate invocation (Orchestrator Contract §4), `check_openapi_diff.py`, `check_always_on.py`, `check_handoff.py`, `check_redelegation.py`, `check_tier1_provenance.py`, `check_runtime_recipe.py`.

## The capture sidecar, and why the body witnesses it

`run_quiet.py --capture <path>` writes two files: the capture artifact and `<path>.meta.json`, the machine-owned sidecar. Four gates read that sidecar — `check_runtime_evidence.py`, `check_red_green.py`, `check_quick_close.py`, `check_ship_decision.py` — and one more reads it per check line (`check_agent_report.py`).

**`capture_sha256` protects the capture FILE's bytes. Nothing protects the sidecar's own fields.** So the hash-checked body is the *witness* and the sidecar is the *claim under test*: editing the sidecar alone — `exit_code` 3 → 0, or `finished` pushed forward to defeat a freshness or ordering check — left every hash intact and every gate green. Every gate that reads a sidecar's `exit_code` or `finished` therefore compares them against the capture's own header lines:

- the body's `- Exit code: <N>` must equal the sidecar's `exit_code`;
- the body's `- Captured: <ts>` must equal the sidecar's `finished`, which is the instant `run_quiet.py` now stamps it **from**. The comparison allows a **one-sided 0–2 second window** (never earlier than `finished`), solely so a capture written by the pre-2.4 build path — which called `now()` again while rendering, landing 0–1s after `finished` — is not accused of forgery. A stamp moved to fake freshness or backdate a run moves it far outside the window.

Header lines are read from the region **before** `## Captured output`, with fences blanked: a probe or test runner that prints `- Exit code: 0` supplies nothing.

Problem codes, identical in every gate: **`sidecar_body_disagrees`** (they disagree) and **`capture_header_missing`** (the capture carries no readable header pair, so the sidecar is unwitnessed). `run_quiet.py` re-checks the agreement at write time, so this tool family can never be the source of a failing pair.

**Migration**: a capture written before this contract — no `- Exit code:` / `- Captured:` header pair, or a sidecar whose `finished` is more than 2s from the body — fails closed. Re-take the probe with `run_quiet.py --capture`. There is deliberately **no waiver flag** for this (convention #8, tighter than `--allow-missing-sidecar`, which waives sidecar *absence*): a present-but-disagreeing sidecar is the exact forgery this check exists for, and re-taking a capture is cheap.

### The unkeyed-sidecar limit: one forger, seven gates

The agreement check above raises the cost of editing a sidecar. It does not make a capture unforgeable, and the size of that gap is stated here rather than only in `references/check_red_green.md`, because it is a property of the FAMILY, not of one gate.

Every field `run_quiet.py` writes — `argv`, `cwd`, `host`, `pid`, `started`, `finished`, `exit_code` — is typeable, and both hashes are unkeyed SHA-256 over content anyone can produce. There is no nonce, no key and no monotonic anchor, so a ~40-line stdlib script writes a self-consistent capture + sidecar pair for a command that never ran: the body matches the header, the header matches the sidecar, the sidecar's `capture_sha256` matches the file. **The blast radius of that one script is seven gates** — `check_runtime_evidence.py`, `check_red_green.py`, `check_quick_close.py`, `check_agent_report.py`, `check_ship_decision.py`, and, through their ledger records, `check_commit_gate.py --require-ledger-gates` and `mark_milestone.py --require-gates`. A commit gate run with every hardening flag on has been shown to exit 0 and commit over a wholly fabricated evidence base built this way.

**This is accepted, not overlooked, and the honest framing is what the family buys**: a forgery is now a WRITTEN ACT rather than an omission — somebody has to author artifacts that hang together, and the ledger keeps them attributable. Closing it needs a secret the runtime does not have (a keyed MAC, or an external notary), so no flag here pretends to. Related, and equally accepted: `record_run.py`'s run log is authored too, so `check_commit_gate.py --require-agents` proves a delegation record exists, not that the delegation happened (`--require-ledger-gates` is the flag that re-hashes); and `check_ledger.py` detects a LOCAL edit, not a thoroughly rewritten tail.

### `--require-ledgered-captures`: the capture must also have been RECORDED

The gap above stayed exactly that size while no reader asked *where the pair came from*. `run_quiet.py --capture --ledger` now appends one chained record per capture, pinning that capture's `capture_sha256`, and three readers look the artifact up in it:

- **Who reads it** — `check_agent_report.py` (each cited check-line capture), `check_runtime_evidence.py` (each cited runtime capture), `check_ship_decision.py` (the rehearsal capture and every baseline reading). Each takes the flag `--require-ledgered-captures`, which **requires `--ledger`** (exit 2 otherwise).
- **The lookup** — the artifact's CURRENT sha256 must appear as the `capture_sha256` of some `gate: "run_quiet.py"` record in that ledger. Because it is the current hash, an edit after recording un-ledgers the artifact as surely as it breaks the sidecar.
- **Warn, then fail — a one-release grace, and a DELIBERATE divergence (convention #8) from this family's fail-closed default.** With `--ledger` and no `--require-ledgered-captures`, an artifact no record pins emits the warning line `unledgered_capture: <path>` and the exit code is **unchanged**. With the flag, it is problem code **`unledgered_capture`** and a failure. Without `--ledger` the lookup does not happen at all, so every existing invocation behaves exactly as before.
- **Not chain integrity** — a record inside a broken chain still counts here. `check_ledger.py` owns the chain, and `--require-ledger-gates` re-walks it at commit time; duplicating that check in five places would make one broken ledger report five different problems.
- **Migration** — captures taken before this release carry no ledger record, so every one of them warns. Re-take a check or probe with `run_quiet.py --capture <path> --ledger <the ledger> -- <command>` to earn one. The pipelines should pass `--require-ledgered-captures` once their captures are all taken with `--ledger`.
- **What it still does not buy** — the ledger is unkeyed too, so a forger who also appends a chained line still passes. It raises the cost from "write two files" to "write two files and extend a hash chain that `check_ledger.py` walks", which is a larger written act, not an impossible one.

## Fenced blocks and encoding

Every verdict/status parser blanks fenced regions (three backticks or three tildes) before parsing, preserving line count, and every file read uses `utf-8-sig`. A verdict or status token inside a fence is a TEMPLATE or a captured transcript, never an assertion — and because these parsers resolve latest-mention-wins, a pasted example silently overrode the real verdict. A BOM previously made a valid report exit 2. `check_coverage.py`'s plan and design modes are the labelled exception (convention #8) — see `references/check_coverage.md`.

## check_coverage.py

Verifies every Must-Have FR/NFR in `requirements.md` is covered: by `plan.md` tasks (plan mode), by evidenced passing tests in `test-report.md` (test mode), or by an in-place supersession annotation in `detailed-design.md` (design mode). Plan mode additionally runs five gating lints; design mode runs the supersession/citation lints only.

```bash
python check_coverage.py --requirements <path> --plan <path>          # plan mode
python check_coverage.py --requirements <path> --test-report <path>   # test mode
python check_coverage.py --requirements <path> --design <path>        # design mode
python check_coverage.py ... [--ledger <path>]
python check_coverage.py --self-test
```

- **Flags** — exactly one of `--plan` / `--test-report` / `--design` (more than one or none is exit 2); `--requirements` required in every mode; `--ledger` optional.
- **JSON keys** — `mode`, `requirements_file`, `target_file`, `must_have`, `should_have`, `covered`, `uncovered`, `uncovered_should`, `blocked`, `unevidenced`, `warnings`, `lint_failures`, `result`, `error`. `uncovered` and `lint_failures` are the two gating arrays. `lint_failures` entries are `{check, task, detail}`, where `check` is one of `literal-count`, `consumes-provides`, `path-hygiene`, `runtime-criterion`, `domain-tag` (plan mode) or `supersession-annotation`, `fr-citation`, `adr-citation` (design mode). **`adr-citation`** fires on a design-register row that names a superseded FR/NFR but cites no `ADR-NNNN` token and no `adr/NNNN-` path: a supersession with no filed decision is a change of mind nobody can read back. **Scope limit** — it matches the TOKEN, not the file, so `ADR-9999` satisfies it even when no such file exists under `.docs/{project-name}/design/adr/`. Resolving the citation to a file is a known gap, recorded here rather than left to be rediscovered.
- **Test-mode evidence rule** — a status is read only from a list item (`- FR-3: PASS — …`). A `PASS` whose evidence half cites nothing checkable (an exit code, a `file::test-name`, or a `**Runtime evidence:**` / `evidence/runtime/` citation) is recorded `UNEVIDENCED`: status-bearing, NOT covered, so the Must-Have lands in `uncovered`.
- **Exit codes** — **0** every Must-Have covered and no lint failed; **1** a Must-Have gap or any lint failure; **2** usage error, missing/unreadable file, or a structural contract failure (no Must-Have requirements, no task blocks).
- **Self-test** — `--self-test` runs **138** cases; `python scripts/test_check_coverage.py` runs the same suite directly. Depth (parsing grammars, the five lints, fixtures, the authoring smoke test): `references/check_coverage.md`.

## check_commit_gate.py

Makes the `bgpdd-build` milestone commit gate machine-run instead of a manual two-file read: it checks the milestone's latest review verdict, whether that review postdates the diff, and whether the blockers ledger is clean, then — on a pass — performs the commit itself, so a skipped gate is loud (no commit exists) rather than silent.

```bash
python check_commit_gate.py --review-report <path> --state <path> \
    --milestone "<title>" --changed-files <p1> [<p2> ...] \
    [--commit --message "<msg>"] [--repo <dir>] [--docs-root <dir>] [--ignore-unscoped] \
    [--require-rendered-evidence] [--require-files-reviewed] [--verify-tree] \
    [--max-changed-files <N> [--waiver <path>]] \
    [--ledger <path>] [--require-ledger-gates <name>[,<name>...]] \
    [--require-run-log <path> --require-agents <name>[,<name>...]] \
    [--require-runtime-evidence --runtime-report <path> \
     [--surface <key>] [--require-key <name>]... [--expect-status <N>] \
     [--forbid-host <pattern>]... [--require-build-marker <value>] \
     [--require-openapi-reachable] [--allow-missing-sidecar] \
     [--openapi-doc <path> --openapi-route <path> [--openapi-method <verb>]]]
python check_commit_gate.py --self-test
```

- **Flags** — `--repo` defaults to `.`. `--changed-files` entries may be absolute or relative; a relative one resolves against `--repo` and, failing that, against the process's cwd (accepted only if it then lies under `--repo`); an absolute one must lie under `--repo` outright. An entry that exists but lies outside `--repo` is exit 2, `changed_file_outside_repo` (the fix is to run the gate once per repo, not to combine paths from several); one that exists nowhere searched is exit 2, `changed_file_missing`, naming the repo searched. `--docs-root` defaults to the nearest ancestor of `--review-report` (or `--state`) named `.docs`, else `--repo/.docs`; set it explicitly only when neither derivation lands on the right directory. Every runtime-evidence assertion flag forwards to `check_runtime_evidence.py`; any of them passed *without* `--require-runtime-evidence` is exit 2, never a silent no-op. `--ledger` and `--allow-missing-sidecar` forward when the child script declares them. `--require-ledger-gates` requires `--ledger` (else exit 2) and demands that the ledger's hash chain be **intact** and that each named gate's latest ledger entry for this milestone record `PASS` **and** still hash the same inputs. The chain check short-circuits: naming which gate recorded a PASS is pointless when the file it was read from is not trustworthy.
- **`--max-changed-files <N>`** (the `bgpdd-bugfix` fix-size bound; lane default `5`) — counts the **declared** `--changed-files` paths, the same list the staleness check already validates exist; pairing it with `--verify-tree` is what makes that count equal the real diff. `N < 1` is exit 2. Unset, the bound is not applied (`size_ok: true`, `max_changed_files: null`) and behaviour is unchanged. **`--waiver <path>`** (exit 2 without `--max-changed-files`) waives an overrun when that file carries a `## Size waiver` heading (level 2–4, outside a fence) whose body is non-empty and not a placeholder — **in either shape**: every line individually a stand-in, or one `<...>` span wrapped across several lines (the shape the shipped `rca-template.md` writes, asserted to fail by `test_the_shipped_rca_template_waiver_fails`). **Deliberately hand-typed, unlike every other evidence path in this family (convention #8)**: exceeding the bound is the *user's* decision and no script can verify a judgement call, so the gate buys durability and attributability — the decision written into `rca.md` and hashed into the ledger record — not verification.
- **`--require-run-log <path> --require-agents <name>[,<name>...]`** — the two flags are inseparable (either alone is exit 2). Each named agent must carry at least one `record_run.py` **delegation** record in that run log scoped to this `--milestone`, with a non-null `model`. The gate already refuses to commit over an unapproved review; what it could not see is whether the review *happened* — a milestone whose Quinn or Luna round was skipped outright leaves a green report and an empty run log, and the gate passed on the report alone (convention #9: the Orchestrator Contract §4 "record the delegation" rule became a file the gate reads). `record_run.py` refuses to write a delegation without a model, so a record missing one was hand-written and is not evidence a delegation occurred. **Scoping is EXACT on the record's `unit` — deliberately tighter than `--require-ledger-gates`, which also accepts an unscoped entry (convention #8)**: a gate ledger line legitimately covers a whole epic, but a delegation with no unit does not say which milestone it built. Build's invocation names `quinn,luna` plus the milestone's builder.
- **Section boundaries** — ANY heading of level 2–6 closes a `## Review:` section. **Migration**: a `**Verdict:**` line must appear BEFORE any subheading inside its review section, or the section reads as no-verdict and fails closed.
- **Verdict/severity consistency (DEFAULT ON, no flag)** — converts `code-review-and-quality/SKILL.md` § The Review Report's prose rule ("`Approve` is unavailable while any Critical or Important finding stands in the same report") into a mechanical check. **Scans the WIDER range** — from the matched `## Review:` heading forward to the next level-2 `##` heading (shared with `--require-files-reviewed` below as `matched_section_range`, so the two cannot drift) — **not** the narrower body `find_latest_review`'s verdict comes from: the review template files real findings under `### Correctness` / `### Security` / etc, which sit outside that narrower verdict-only body by design (a `**Verdict:**` line must come before the first `###`; that body-closing rule is right for the verdict and wrong for findings). A **finding line** is a line whose first non-list-marker, non-whitespace content is `**Critical:**` or `**Important:**` (a `|`-prefixed table row, e.g. the severity legend, never counts); its **block** is that line plus every following line up to a blank line, a heading, or a sibling list item at the same or lesser indentation. A finding is resolved only when its block contains the literal uppercase word `RESOLVED` (`\bRESOLVED\b`, case-sensitive — lowercase `resolved` does not count). Verdict `Approve` with any unresolved Critical/Important finding standing anywhere in the matched section (its subsections included) → `findings_consistent: false` and the gate fails; `Request Changes` is unaffected by this term regardless of findings; only the LATEST matching `## Review:` section is read, so a finding under a LATER section for a different milestone is never counted. This is the grammar authority `code-review-and-quality/SKILL.md` cites for its `RESOLVED` marker.
- **Files-reviewed coverage — `--require-files-reviewed` (opt-in)** — converts the review template's `### Files reviewed` convention ("a file missing here has not been reviewed", `code-review-and-quality/SKILL.md` § The Review Report) into a mechanical check, over the SAME wider range the term above uses (`matched_section_range`): since `parse_review_sections` closes a `## Review:` section's own body at the first subheading, `### Files reviewed` sits OUTSIDE it. This flag finds a level 3–4 `Files reviewed` heading inside that wider range and collects the first backticked path on each of its list-item lines. Every resolved `--changed-files` path must appear there (forward-slash, case-sensitive; a declared path ending in `/` + a listed path also counts, since a listed path may be repo-relative to a shorter root than the declared one was resolved to) or the gate fails, naming the misses in `files_unreviewed`. No `### Files reviewed` subsection at all fails every declared file. **Not checked**: whether the line's disposition is honest (`review_package.py` records an excluded file as "not reviewed: excluded from package", and that line still counts — this flag checks presence of the path, not what it says about it).
- **JSON keys** — `milestone`, `review_report`, `state_file`, `docs_root`, `review_found`, `verdict`, `ambiguous_review_section`, `standing_findings` (`[{severity, line, text}]`), `findings_consistent`, `stale`, `blocking`, `unscoped_blockers`, `other_milestone_blockers`, `ignored_unscoped_ids`, `rendered_evidence`, `rendered_evidence_ok`, `undeclared_changes`, `tree_verified`, `require_files_reviewed`, `files_reviewed`, `files_unreviewed`, `files_reviewed_ok`, `max_changed_files`, `changed_file_count`, `size_waiver` (`{path, present, section_found, body_nonempty, satisfied}`), `size_ok`, `already_committed`, `runtime_evidence`, `runtime_evidence_ok`, `ledger`, `require_ledger_gates`, `ledger_gate_problems`, `ledger_gates_ok`, `run_log`, `require_agents`, `run_log_problems`, `run_log_ok`, `warnings`, `committed`, `result`, `error`. **Problem codes**: `ledger_gate_problems` entries carry `ledger_chain_broken`, `ledger_missing`, `ledger_failed` or `ledger_stale`; `run_log_problems` entries carry `run_log_missing`, `run_log_agent_missing` or `run_log_model_missing`; with `--require-rendered-evidence`, a cited `.png` additionally requires a `record_capture.py` provenance sidecar, failing per-citation into the `rendered_evidence` warnings as `sidecar_missing`, `sidecar_bad_origin` (a non-http(s) recorded `url`), `sidecar_sha_mismatch` (the PNG's current bytes no longer match the sidecar's recorded `sha256` — it was swapped after being recorded), or `sidecar_malformed` (unparseable JSON, not an object, wrong `schema`, or a missing `url`/`sha256`).
- **`already_committed`** — with `--commit`, if no declared `--changed-files` path differs from HEAD, the change was committed outside this gate (a builder committing its own fix, a hand commit). That is exit **1**, not a no-op: the commit must be the gate's. Reset the outside commit, keeping the tree, and re-run.
- **Blockers precondition** — same normalization and exact-equality scoping as `check_blockers.py` (helper duplicated). Scoped-to-this-milestone (`blocking`) or unscoped (`unscoped_blockers`) block; `--ignore-unscoped` skips unscoped and names them in `ignored_unscoped_ids`; `other_milestone_blockers` never block; `Info` never blocks (fixed floor, deliberately not caller-tunable at the last checkpoint).
- **Exit codes** — **0** gate passed (and committed, with `--commit`); **1** gate failed (`verdict` not `Approve`, `ambiguous_review_section`, `stale`, non-empty `blocking`, unignored `unscoped_blockers`, `findings_consistent: false`, `rendered_evidence_ok: false`, `runtime_evidence_ok: false`, `ledger_gates_ok: false`, `run_log_ok: false`, `size_ok: false`, `tree_verified: false`, `files_reviewed_ok: false`, or `already_committed: true`); **2** usage error (including `--waiver` without `--max-changed-files`, `--max-changed-files 0`, `--require-agents` without `--require-run-log`, or `--require-run-log` without `--require-agents`), a `--changed-files` path that does not exist under `--repo` nor the cwd (`changed_file_missing`, naming the repo searched) or one that resolves outside `--repo` (`changed_file_outside_repo`), unreadable artifact, invalid state JSON, git failure, or a structural failure from the delegated runtime gate.
- **Self-test** — **131** cases, including six for the `record_capture.py` sidecar (`sidecar_missing`, `sidecar_bad_origin`, `sidecar_sha_mismatch`, two `sidecar_malformed` shapes, and the conforming-sidecar pass) and `test_pipeline_value_never_changes_the_verdict`: the verdict JSON is **byte-identical** across every `pipeline` value and with the field absent, and the report never echoes it. `bgpdd-bugfix`'s feature route shares the epic's state file and never stamps its own `pipeline`, so it cites this test rather than asserting the property in prose (convention #9). Depth (delegation rationale, parsing rules, the ledger-gate essay, the two convention #9 conversions above): `references/check_commit_gate.md`.

## check_quick_close.py

The `bgpdd-quick` Phase 3 gate, and that lane's ONLY gate — it carries alone what the heavier lanes spread across five gates and a squad. Given the lane's two artifacts (`note.md`, one `run_quiet.py --capture`) and the declared file list, it verifies the change was declared before it was made, still matches the tree, was checked *after* the edit by a command that passed, edited no frozen test, and is still small enough for a lane with no plan behind it — then, with `--commit`, commits exactly the declared files.

```bash
python check_quick_close.py --note <path> --capture <path> \
    --changed-files <p1> [<p2> ...] [--repo <dir>] \
    [--max-changed-files <N>] [--frozen <path-or-glob>]... \
    [--milestone "<slug>"] [--ledger <path>] [--require-ledger-gates <name>[,<name>...]] \
    [--commit --message "<msg>"]
python check_quick_close.py --self-test
```

- **Flags** — `--note`, `--capture` and at least one `--changed-files` path are required; `--repo` defaults to `.` and a relative `--changed-files` entry resolves against it, not against the process's cwd; `--frozen` is repeatable. `--commit` requires `--message`, and `--message` without `--commit` is exit 2, never a silent no-op. **`--max-changed-files` DEFAULTS to `3`** and must be `>= 1` — **deliberate divergence (convention #8) from `check_commit_gate.py`, where the bound is opt-in**: there it is an extra assertion, here it is the lane's definition, so a forgotten flag would silently delete it. **There is deliberately no `--waiver`** — also tighter than `check_commit_gate.py` (convention #8): an overrun in this lane has named escalation destinations, which the failure message prints, so a waiver would let the one bound that defines the lane be self-certified by whoever exceeded it.
- **Note grammar** — three labelled lines, matched case-insensitively as list items or bare lines, outside fences: `- What:`, `- Where:`, `- How verified:`. A value that is `<...>`, `TODO`, `TBD`, `N/A`, `none`, `unknown`, `???` or `...` counts as absent (same vocabulary as `check_bugfix_intake.py`). The `Where` line's paths (comma- and/or whitespace-separated, backticks stripped) must **equal** the `--changed-files` set after repo-relative normalization.
- **`- How verified:` is ONE argv-runnable command** (backticks optional): no pipes, no redirects, no `&&` — `run_quiet.py` spawns argv with no shell, so a shell-only construct is not re-runnable as written. **`capture_command_mismatch`** compares that value with the capture sidecar's recorded child `argv` on **token lists, not strings**: the shell has already removed the quoting, so `-d '{}'` in the note is `['-d', '{}']` in argv and a string compare would reject exactly the carefully quoted commands. Three candidate tokenizations, ANY match passes, nothing fuzzier (no case-folding, no reordering, no dropped tokens) — `shlex.split(posix=True)`; the same with backslashes doubled first, so a Windows path survives posix mode; a raw whitespace split, which an unquoted command satisfies and a shlex parse error cannot defeat. **The matcher is byte-identical to `next_bugfix_route.py --red`'s `- Command:` check and `check_agent_report.py`'s per-line check**, guarded in all three by a self-test comparing the parsed functions: the three gates must not disagree about what "the same command" means. `capture_command_match` in the JSON names the strategy that matched. Without this term the gate checked that A capture existed, hashed, was fresh and exited 0 — never that it captured THE DECLARED CHECK: a real `run_quiet.py --capture ... -- cmd /c exit 0` closed a lane whose note said `npm test`, no forgery, one legitimate tool call.
- **Freshness — deliberate divergence (convention #8) from `check_red_green.py`'s strict `>`**: the sidecar's `finished` (whole seconds) is compared `>=` against each changed file's mtime **floored to the second**. There the two captures are a fix round apart; here an edit and its check routinely land inside one second, and a strict `>` would reject honest work.
- **Frozen check** — fires only on porcelain statuses meaning an **existing tracked file changed** (`M`/`D`/`R`/`C`/`U` in either column); `??` and `A`/`AM` are new files. Adding a test passes, editing one fails — a rule that forbade the lane's own use case would be routed around rather than obeyed. Staged and unstaged edits both count.
- **`--frozen` accepts globs.** A value carrying `*`, `?` or `[` is matched as a glob against the repo-relative forward-slash path; anything else stays a path or directory prefix, so `tests/` is unchanged. Segment semantics, hand-rolled rather than `fnmatch` (whose `*` crosses `/`, silently turning `tests/*.py` into `tests/**/*.py`): `**/` is zero or more leading segments, a trailing `**` is the rest of the path, `*`/`?` stop at `/`, `[...]`/`[!...]` are character classes. Backslashes are folded to `/` and the pattern is `normcase`d, so a Windows-typed `tests\**\test_*.py` matches. **`--frozen` has NO default and must not** — a freeze the gate guessed and got wrong is indistinguishable from a change with no test to protect, so the caller states what is frozen; `bgpdd-quick` Phase 3 passes `detect_stack.py`'s `test_path_globs`.
- **`check_test_authenticity.py` is IMPLIED, not just reminded.** The moment a declared `--changed-files` path matches `--frozen` or `check_test_authenticity.py`'s own default test-glob heuristic (copied in), it is added to the required-gates set even with no `--require-ledger-gates` given — `pipeline_driver.py`'s quick-lane step emission cannot see `--changed-files`, so it can only remind the caller to run the gate, never require it; this term is the actual enforcement (convention #9). The ledger must hold a **PASSING `check_test_authenticity.py` record exactly scoped to `--milestone`** whose `inputs` cover the declared test file at its CURRENT hash. **`--require-ledger-gates <name>[,<name>...]`** names any OTHER gate this close must also find a fresh PASS for, in `check_commit_gate.py`'s own comma-separated syntax — unlike the implied `check_test_authenticity.py` entry, these are milestone-scoped-**or**-unscoped like that sibling gate, with no input-coverage check, since they are not necessarily about a specific set of changed files.
- **JSON keys** — `note`, `capture`, `repo`, `milestone`, `note_fields`, `note_where_paths`, `changed_files`, `changed_file_count`, `max_changed_files`, `size_ok`, `capture_sidecar`, `capture_body_agrees`, `capture_argv`, `capture_command_match`, `capture_exit_code`, `capture_finished`, `newest_changed_file`, `fresh`, `undeclared_changes`, `frozen`, `frozen_modified`, `test_files`, `required_ledger_gates`, `ledger_gate_problems`, `problems`, `problem_codes`, `warnings`, `committed`, `result`, `error`.
- **Problem codes**, evaluated in this order — `note_missing`, `note_incomplete`, `note_where_mismatch`, `capture_missing`, `not_a_capture`, `sidecar_missing`, `sidecar_hash_mismatch`, `sidecar_body_disagrees`, `capture_header_missing`, `capture_command_mismatch`, `capture_exit_nonzero`, `capture_stale`, `changed_file_missing`, `undeclared_tree_changes`, `frozen_path_modified`, `test_authenticity_gate_missing` (the implied `check_test_authenticity.py` entry has no fresh scoped PASS), `required_ledger_gate_missing` (an explicitly named `--require-ledger-gates` entry has no fresh PASS — `ledger_missing` / `ledger_failed` / `ledger_stale` / `ledger_chain_broken`, reported under this one code), `size_bound_exceeded`; `problems` entries are formatted `"<code>: <prose>"`. Every code is reported rather than short-circuited, so one run names every term that failed. The two sidecar-agreement codes are the shared contract above, and they run **before** `capture_exit_nonzero` and `capture_stale` — both of which read fields the sidecar alone would otherwise be trusted for.
- **`--ledger` inputs** — the note, the capture, **its sidecar**, and every declared file, so a later re-hash catches an artifact edited after this gate passed.
- **Exit codes** — **0** every term held (and committed, with `--commit`); **1** any problem code; **2** usage error (a missing required flag, `--max-changed-files 0`, `--commit` without `--message`, `--message` without `--commit`), an unreadable artifact, or a git failure / missing git.
- **`frozen_path_modified`'s escape** — the message names it: **narrow the glob and record why in the note's `## Result` section**. A rename that legitimately touches the spec beside the code is not a defect, and routing it to `/bgpdd-bugfix` (which demands a RED capture proving the test was wrong) is the wrong destination; only a genuinely wrong test goes there.
- **Self-test** — **63** cases, each against a real temp git repo, including two end-to-end captures written by the real `run_quiet.py` (one matching the note, one deliberately not), the glob matcher's own unit table (Windows separators included), and the `check_test_authenticity.py` implied-requirement and `--require-ledger-gates` cases (missing, failed, stale, chain-broken, and a passing scoped record). Depth (the two divergences, the frozen status-letter rule, the copy-not-import decision, the case inventory): `references/check_quick_close.md`.

## check_agent_report.py

Verifies a durable agent report (Cipher's `security-report.md`, Vera's `verification-report.md`, Dep's `post-deploy-report.md`) backs its `Pass` verdict with evidenced check lines and zero Critical findings. Deliberately terse: the evidence contract is command + exit code + counts + **the capture that recorded the run**, per line — the gate never requires (and the report must never contain) full scanner output or log dumps.

```bash
python check_agent_report.py --report <path> [--milestone "<title>"] [--repo <dir>] \
    [--allow-uncaptured] [--ledger <path>] [--require-ledgered-captures]
python check_agent_report.py --self-test
```

- **Check-line grammar** — `- <name>: PASS|FAIL|BLOCKED|NOT RUN — `<command>` — exit <N> — <terse counts> — capture: evidence/<dir>/<file>.md`. An **executed** line (`PASS`/`FAIL`) carries both an exit code and the `capture:` citation; `BLOCKED` / `NOT RUN` carry their reason and cite nothing. The citation path may be backticked, must contain an `evidence/` segment and no `..`, and is resolved against the report's directory, then `--repo`, then the cwd.
- **The capture is the only unforgeable term.** Everything else on a check line is text an agent types: until this existed, a wholly invented report whose lines carried plausible exit codes passed. So the cited capture must exist, carry its `<capture>.meta.json` sidecar, still hash to it, satisfy the body/sidecar agreement above, and record an `exit_code` **equal to the one the line claims**.
- **`capture_command_mismatch` ties the capture to THIS line.** The exit-code equality above was described as that tie and is not one: it ties a capture only to lines claiming the same exit code, and every clean scan claims 0 or 1 — a three-line report whose secrets-scan, `npm audit` and `dotnet test` lines all cited one `exit 1` capture passed with verdict Pass. So each executed line's **backticked command**, read from the text **before** the `capture:` citation (a backticked path cannot stand in for it), must token-match the cited sidecar's `argv` under the same three tokenizations `check_quick_close.py` and `next_bugfix_route.py --red` use — byte-identical, and guarded by a self-test that compares the parsed functions. A line citing a capture but naming no command is the same code: the grammar above has always required one. **Never waived** (convention #8, tighter than `--allow-uncaptured`): a line citing a capture of a different run is the exact fabrication this term exists for, and re-running one check is cheap.
- **Flags** — `--milestone` scopes this run's ledger record so a later `check_commit_gate.py --require-ledger-gates check_agent_report.py` can find it; `--repo` defaults to `.`. **`--allow-uncaptured`** waives the **citation only** — a cited capture that disagrees is never waived (the same split as `check_runtime_evidence.py --allow-missing-sidecar`) — and exists for one named reason: grading a report authored before this contract. It warns loudly on stderr and sets `allow_uncaptured: true`.
- **`--ledger` inputs** — the report **plus every cited capture and its sidecar**, so a later re-hash catches one edited after this gate passed.
- **`--require-ledgered-captures`** (requires `--ledger`, else exit 2) — every cited capture's current sha256 must be pinned by a `run_quiet.py` ledger record in `--ledger`, per § `--require-ledgered-captures` above. Without the flag an unpinned capture is the warning `unledgered_capture: <path>` and the exit code is unchanged; without `--ledger` the lookup does not happen.
- **`--emit-fingerprints REPORT`** is a separate read-only mode, independent of `--report` and every other flag: prints `<fp>  <category>  <file>  <title>` for every finding line (`- **<Severity>** — <finding> — <file:line>`, `agents/cipher.md` § 4) in REPORT's gated section — the same last verdict-bearing section `--report` grades — and exits 0 (2 on the same missing/empty/no-verdict-section failures `--report` raises for). The fingerprint is a 12-hex-char sha256 of the normalized `(file, category, title)` key: the location's `:<line>` suffix is EXCLUDED (a fix landing above the finding must not turn it into a "new" one), `category` is the nearest PRECEDING check-line name in the same section (`uncategorized` if none precedes it — the finding grammar has no category field of its own), and `title` has every digit run collapsed to `#` and its whitespace collapsed to one space. Fingerprints are DERIVED here, never hand-authored (the `*.meta.json` reasoning again) — `diff_findings.py` (same directory) takes two such reports and classifies findings as RESOLVED/PERSISTENT/NEW.
- **JSON keys** — `report`, `section`, `verdict`, `checks`, `passed`, `failed`, `blocked`, `not_run`, `unevidenced`, `uncaptured`, `capture_disagrees`, `capture_command_mismatches`, `unledgered_captures`, `capture_problems` (`[{check, problem, detail}]`), `capture_inputs`, `allow_uncaptured`, `require_ledgered_captures`, `critical_findings`, `warnings`, `result`, `error`. **Problem codes** (in `capture_problems[].problem`): `check_uncaptured`, `check_capture_disagrees`, `capture_command_mismatch`, `unledgered_capture` — the last is the only one there that does not gate unless `--require-ledgered-captures` is passed.
- **Exit codes** — **0** verdict exactly `Pass`, at least one check line, every line `PASS`, evidenced and captured, zero Critical findings; **1** any other verdict (an unparseable latest verdict fail-safes to no-verdict), a non-empty `failed`/`blocked`/`not_run`/`unevidenced`/`uncaptured`(unwaived)/`capture_disagrees`/`capture_command_mismatches`/`unledgered_captures`(only under `--require-ledgered-captures`), a standing Critical, or zero check lines; **2** usage error (`--require-ledgered-captures` without `--ledger` included), missing/empty/unreadable report, or no `## ` section carrying a `**Verdict:**` line.
- **Migration** — a report authored under 2.3.0 or earlier fails with `check_uncaptured` on every executed line. The fix is to re-run each check through `run_quiet.py --capture` and cite the artifact. A report authored under **2.6.0 or earlier** whose executed lines cite a capture but omit the backticked command now fails `capture_command_mismatch`: add the command, or cite the capture that actually recorded that line's claim. Captures taken **before this release** carry no ledger record and warn `unledgered_capture` under `--ledger` for one release; re-take them with `run_quiet.py --capture --ledger`. Producer-side grammar lives in `agents/cipher.md`, `agents/vera.md` and `shipping-and-launch/SKILL.md`.
- **Self-test** — **62** cases, including one that runs the REAL `run_quiet.py --capture --ledger` and passes the resulting capture under the strict flag — the tie between the writer and this reader. Depth (check-line grammar, producer-side pointers, fixtures): `references/check_agent_report.md`.

## diff_findings.py

Classifies a security/verification report's findings across a rescan, using `check_agent_report.py`'s own finding fingerprint (see that section's `--emit-fingerprints` bullet — not restated here). Reads each report's GATED section only (Cipher appends one section per round and never edits an earlier one, so a fixed finding would look permanently "still there" if the whole file were read instead of just its latest round).

```bash
python diff_findings.py OLD_REPORT NEW_REPORT [--fail-on-new] [--fail-on-persistent]
python diff_findings.py --self-test
```

- **Classification** — RESOLVED: fingerprinted in OLD_REPORT's gated section, absent from NEW_REPORT's. PERSISTENT: fingerprinted in both. NEW: fingerprinted in NEW_REPORT's only. Matching is by fingerprint alone, never by position — a finding that only moved lines, or was reworded in whitespace/digits, is PERSISTENT, not NEW.
- **Output** — a markdown table (RESOLVED/PERSISTENT/NEW sections, each row `` `<fp>`  <category>  <file>  <title> ``) plus a one-line count summary, printed to stdout regardless of exit code.
- **Flags** — `--fail-on-new` exits 1 when NEW_REPORT carries a fingerprint absent from OLD_REPORT, naming each one and its title on stderr ("triage or fix these before the verdict"); `--fail-on-persistent` does the same for a finding standing in both. Neither is required — default exit is 0 whatever the classification.
- **Exit codes** — **0** by default; **1** under `--fail-on-new`/`--fail-on-persistent` when that classification is non-empty; **2** usage error (`OLD_REPORT`/`NEW_REPORT` missing) or a report that is missing, empty, or carries no `**Verdict:**`-bearing section.
- **Self-test** — **12** cases: identical reports, a moved finding (persistent, not new), a fixed finding (resolved), a fresh finding (new), both `--fail-on-*` flags, default exit 0 regardless of classification, missing/empty/no-verdict-section reports, missing positional args, and the rendered table's shape.

## check_runtime_evidence.py

It reads a durable report (`test-report.md` in build, `verification-report.md` in shipping), collects its `**Runtime evidence:**` citations, and verifies each cited capture: provenance sidecar, out-of-process transport, allowlisted client, freshness, and required response keys. `runtime-evidence/SKILL.md` owns the capture artifact and citation grammar; this section owns only the CLI contract.

```bash
python check_runtime_evidence.py --report <path> --milestone "<title>" \
    --changed-files <p1> [<p2> ...] [--repo <dir>] \

    [--forbid-host <pattern>]... [--require-build-marker <value>] \
    [--min-captures <N>] [--require-openapi-reachable] \
    [--allow-missing-sidecar] [--ledger <path>] [--require-ledgered-captures] \
    [--openapi-doc <path> --openapi-route <path> [--openapi-method <verb>]]
python check_runtime_evidence.py --self-test
```

- **Flags** — `--report` and `--milestone` required; `--repo` defaults to `.`, and a relative `--changed-files` entry resolves against it, not against the process's cwd; `--min-captures` defaults to `1` and **must be >= 1** (`0` is an argparse error, exit 2 — a gate that passes with zero accepted captures once reported `PASS` while its own JSON named an in-process transport); `--require-key` and `--forbid-host` are repeatable and are supplied by the **caller**, never declared by the producer. `--allow-missing-sidecar` waives sidecar **absence** only. - **JSON keys, top level** — `report`, `milestone`, `citations`, `captures`, `accepted`, `rejected`, `missing_keys`, `stale`, `in_process_transport`, `sidecar_missing`, `sidecar_hash_mismatch`, `sidecar_body_disagrees`, `capture_header_missing`, `probe_failed_exit`, `probe_not_client`, `probe_exempt`, `unledgered_captures`, `require_ledgered_captures`, `allow_missing_sidecar`, `min_captures`, `warnings`, `result`, `error`, plus the OpenAPI set `openapi_unreachable`, `require_openapi_reachable`, `openapi_doc`, `openapi_route`, `openapi_method`, `schema_resolved`, `schema_unresolvable_reason`, `declared_properties`, `declared_absent`, `observed_undeclared`. - **Problem codes** — `sidecar_missing`, `sidecar_hash_mismatch`, `sidecar_body_disagrees`, `capture_header_missing`, `probe_failed_exit`, `probe_not_client`, `in_process_transport`, `stale`, `changed_file_missing`, and `unledgered_capture` (raised only under `--require-ledgered-captures`; otherwise the same finding is a top-level warning and the capture is still accepted); `problems` entries are formatted `"<code>: <prose>"`. The two sidecar-agreement codes are the shared contract above; the top-level report carries a bucket for each.
- **Exit codes** — **0** at least `--min-captures` accepted captures for this milestone and `declared_absent` empty; **1** any evidence failure (no citation, missing file, cited outside `evidence/runtime/`, no capture naming this milestone, stale, in-process transport, build/test-runner/search probe, a non-allowlisted client, a missing/mismatched/non-zero-exit sidecar, forbidden host, missing required key, status or build-marker mismatch, unreachable OpenAPI under its flag, an unledgered capture under `--require-ledgered-captures`, or a declared-but-absent schema property); **2** structural/usage — missing `--report`/`--milestone`, `--require-ledgered-captures` without `--ledger`, unreadable report, a cited capture with no `## Captured output` section, a `--changed-files` path that does not exist (`changed_file_missing`), `--min-captures 0`, or an incomplete/invalid `--openapi-*` combination.
- **Migration** — captures taken before this release carry no ledger record and warn `unledgered_capture` under `--ledger` for one release; re-take the probe with `run_quiet.py --capture --ledger`.
- **Self-test** — **110** cases, including one that runs the REAL `run_quiet.py --capture --ledger` and asserts this gate's lookup finds the record it wrote. Depth (sidecar and client-allowlist essays, OpenAPI flags, parsing rules, scope limits, fixtures): `references/check_runtime_evidence.md`.

## review_package.py

Materializes the diff a reviewer is told to review, as ONE markdown file plus a provenance sidecar. `bgpdd-build` Phase 3 step 4 told a fresh Luna to re-review "the remediation diff itself"; she received a path list and read the amended tree, which shows the files' CURRENT state — a fix is indistinguishable from the status quo and a deletion is invisible. That prose instruction is converted here into an artifact the Orchestrator must generate and name in the brief (convention #9). It renders; it does not judge — there is no exit 1.

```bash
python review_package.py --repo <dir> --base <ref> [--head <ref>|WORKTREE] \
    [--changed-files <p1> [<p2> ...]] --out <dir>/review-package.md \
    [--context <N>] [--ledger <path>] [--milestone "<title>"] \
    [--exclude <pattern>]... [--no-default-excludes] \
    [--max-diff-lines <N> [--waiver <path>]]
python review_package.py --self-test
```

- **Flags** — `--base` and `--out` required; `--repo` defaults to `.`, `--head` to `HEAD`, `--context` to `10`. `--changed-files` is a git pathspec restricting `## Stat` and `## Diff` only (never `## Commits`). **`--head WORKTREE`** compares the base against the **uncommitted working tree** — that is the `bgpdd-build` Phase 3 case, where the milestone is not committed until the Phase 5 commit gate and a two-dot range would render an empty package for work that plainly exists.
- **Output** — `<out>` carries a header (repo, base, head with resolved shas, timestamp, generated-by, scope), `## Commits` (`git log --oneline base..head`), `## Stat` (`git diff --stat`) and `## Diff` (`git diff -U<context>`, fenced with a backtick run one longer than any inside the diff — these packages routinely contain diffs OF markdown).
- **Sidecar** — `<out>.meta.json` mirrors `run_quiet.py`'s shape: `argv` (the exact `git diff` argv), `cwd`, `started`, `finished`, `exit_code`, `capture_sha256` (over the finished package FILE's bytes), `tool`, `schema: 1`; plus `git_argv` (all three commands) and the resolved `base`/`head` shas.
- **Excludes** — `DEFAULT_EXCLUDES` is a short, fixed list of `**/`-prefixed git pathspec glob patterns for files a human should not read line-by-line (lockfiles, `**/*.min.*`, `**/*.map`, `**/*.snap`, generated/designer files, `**/node_modules/**`, `**/vendor/**`, `**/dist/**`, `**/build/**`, `**/bin/**`, `**/obj/**`, `**/__pycache__/**`) — the `**/` prefix reaches any depth, not just the repo root, so `frontend/package-lock.json` in a monorepo is excluded exactly like a root `package-lock.json`. `--exclude <pattern>` (repeatable) adds patterns **as given** — a user pattern follows plain git glob rules and needs its own `**/` to reach nested paths, DEFAULT_EXCLUDES does not extend it; `--no-default-excludes` drops the built-in list. Effective excludes are appended as `:(exclude,glob)<pattern>` pathspec magic **after** any `--changed-files` paths (or alone, still after `--`, when there are none) in the `## Stat` and `## Diff` pathspec — never in `## Commits`. Exclusion is never silent: the header carries `- Excluded from diff (N): ...` (or `none`), and both the stdout JSON and the sidecar carry `excluded_files` and `exclude_patterns`, so a reviewer's `### Files reviewed` line can say `not reviewed: excluded from package` for each one. If every changed path was excluded, that is still exit 2, with a distinct message naming `--no-default-excludes`/`--exclude` as the fix (not the plain empty-diff message).
- **The size ceiling** — `--max-diff-lines <N>` bounds `diff_lines`, the count of `+`/`-` lines in the filtered `## Diff` (`+++`/`---` file headers excluded, excludes already applied). Over the ceiling with no `--waiver` is exit 2 naming the two routes out: split the milestone (`/bgpdd-plan`) or record the decision under a `## Size waiver` heading. `--waiver <path>` is deliberately hand-typed — the same labeled exception (convention #8) `check_commit_gate.py --waiver` already makes — and satisfied only by a non-placeholder `## Size waiver` body, else still exit 2. A satisfied waiver renders `- Size waiver: <path> (N lines over --max-diff-lines M)` in the header and `size_waiver: {path, present, section_found, body_nonempty, satisfied}` in the JSON/sidecar, exactly `check_commit_gate.py`'s shape. This converts `code-review-and-quality/SKILL.md`'s prose escalation ("too large to review properly → request a split") into a mechanical gate (convention #9). It renders; it does not judge — the ceiling is a **structural refusal** (exit 2), not a verdict, so there is still no exit 1.
- **JSON keys** — `written`, `out`, `sidecar`, `repo`, `base`, `head`, `context`, `changed_files`, `commit_count`, `diff_bytes`, `excluded_files`, `exclude_patterns`, `diff_lines`, `max_diff_lines`, `size_waiver`, `capture_sha256`, `result`, `error`.
- **Exit codes** — **0** package written; **2** git failed or is absent, a ref is unresolvable, `--repo` is not a git repo, a required flag is missing, `--out` cannot be written, `--max-diff-lines` given `< 1`, `--waiver` given without `--max-diff-lines`, **the diff is empty**, **every changed path was excluded by pattern**, or **the reviewable diff exceeds `--max-diff-lines` with no satisfying `## Size waiver`** — an empty or fully-excluded diff is not a package, and a review of nothing looks exactly like a review of something (a deliberate divergence from `run_quiet.py`, where empty output is a legitimate observation, per convention #8).
- **Self-test** — **34** cases in a disposable `git init` repo. Depth (the observed failure, rendering rules, sidecar meaning, excludes, the size ceiling, scope limits): `references/review_package.md`.

## check_bugfix_intake.py

The `bgpdd-bugfix` Phase 0 intake gate. Converts the prose rule that a bugfix starts from a written report rather than chat scrollback into an artifact that has to exist on disk: it lints `{bugfix-root}/bug-report.md` (template and field rules: `bgpdd-bugfix/references/bug-report-template.md`) for present, non-placeholder sections, a re-runnable reproduction, and the two enums later phases read. No delegation in that lane happens before it exits 0.

```bash
python check_bugfix_intake.py --report <path> [--milestone "<slug>"] [--ledger <path>]
python check_bugfix_intake.py --self-test
```

- **Required sections** — Observed behaviour, Expected behaviour, Exact error text or log excerpt, Reproduction, Environment, Regression, Affected surface (headings matched case-insensitively, level 2–6, `behavior` spelling accepted).
- **Field rules** — Reproduction needs **either** a usable `- Command:` line **or** at least **two** numbered steps whose text is not a placeholder. A usable `- Command:` value is **backtick-wrapped**, non-placeholder, and command-shaped: >= 2 whitespace-separated tokens, or 1 token carrying `/`, `\`, `.` or `:`. `- Command: see chat` (unquoted) and `` `pytest` `` (one bare word) both fail; `` `./scripts/repro.sh` `` passes. **Documented residual**: `` `see chat` `` is backticked and two tokens, so it passes this text lint — `next_bugfix_route.py --red` closes it mechanically. An unusable Command line beside >= 2 usable steps is a **warning**, and the mode falls back to `steps`. `- Surface:` must be exactly `api` / `ui` / `both`; `- Runtime observable:` and `- Regression:` exactly `yes` / `no`; `- Regression: yes` additionally needs a real `- Last known good:`. A value that is `<...>`, `TODO`, `TBD`, `N/A`, `none`, `unknown`, `???` or `...` counts as absent.
- **Fenced blocks — deliberate divergence (convention #8)** from the family's blank-the-fence rule above: fenced content lines are **masked to a sentinel, not blanked**, so a pasted log excerpt still counts as section content while a heading or `- Key: value` line *inside* a fence satisfies nothing. Blanking would make an honest log paste read as an empty section.
- **JSON keys** — `report`, `sections_found`, `sections_missing`, `placeholder_sections`, `reproduction_mode` (`command` | `steps` | null), `reproduction_command` (the backticks-stripped string, or null), `surface`, `runtime_observable` (JSON boolean), `regression` (JSON boolean), `last_known_good`, `problems`, `problem_codes`, `warnings`, `result`, `error`.
- **Problem codes** — `section_missing`, `section_empty`, `section_placeholder`, `reproduction_missing`, `surface_invalid`, `runtime_observable_invalid`, `regression_invalid`, `last_known_good_missing`; `problems` entries are formatted `"<code>: <prose>"`.
- **Exit codes** — **0** every check passed; **1** any problem code; **2** missing `--report`, an unreadable file, or a file with no level-2..6 heading outside a fence (structurally not a bug report).
- **Self-test** — **33** cases, including that the **shipped template itself FAILS** the gate: a template that passes is a bypass.

## check_red_green.py

The `bgpdd-bugfix` Phase 4 gate. A post-fix green alone cannot show the check ever failed, and a RED and GREEN of *different* commands are two unrelated runs dressed as a proof. Given one RED capture and one or more GREEN captures — all written by `run_quiet.py --capture` — it verifies the pair actually constitutes a before/after.

```bash
python check_red_green.py --red <capture> --green <capture> [--green <capture>]... \
    [--green-runs <N>] [--no-flaky-pass] [--milestone "<slug>"] [--ledger <path>]
python check_red_green.py --self-test
```

- **Checks** — every capture exists and carries a `## Captured output` section; every capture has its `<capture>.meta.json` sidecar, a JSON object whose `capture_sha256` still matches the capture FILE's bytes and whose `exit_code` is an integer; **every sidecar agrees with its capture's own header lines** (the shared contract above); the sidecars record the **identical** child `argv`; RED's `exit_code` is **non-zero**; every GREEN's is **zero**; every GREEN `finished` **strictly later** than RED.
- **Sidecar validation is `check_runtime_evidence.py`'s, duplicated not imported** (family convention: stdlib-only, one file each). Not weakened — the only difference is that RED inverts the exit-code expectation, which is the point of a RED capture. The agreement check matters most here: both of this gate's own terms (a non-zero RED, a GREEN ordered after it) read sidecar fields that a one-line edit could set, and the capture body is the only thing that contradicts such an edit.
- **One-second resolution, fail-closed** — `finished` is stamped to the second and the ordering test is strictly `>`, so EQUAL stamps do not order two runs and are rejected (`green_not_newer`). A real RED and GREEN are a fix round apart; a pair inside one second is re-taken.
- **`--green-runs <N>`** (default `1`, `< 1` is exit 2) — for a flaky bug: at least `N` `--green` captures must be supplied, **all must pass**, and above `N = 1` they must be **`N` DISTINCT RUNS**. **4 of 5 green is not fixed — and 1 of 1 cited five times is not 5 of 5 either.** Supplying fewer than `N` is exit **1** (`green_runs_short`), not exit 2: short evidence is a failed gate, not a usage error.
- **Distinctness (`green_runs_not_distinct`)** — the key is the sidecar's **`(started, pid)`** pair, what identifies a PROCESS: two runs in the same second still differ by pid; one green cited under five `--green` flags is one identity, and so are five copies made by copying the capture and its sidecar together (copying preserves exactly what the hashes protect). The capture body's `capture_sha256` is **reported, not required** — five honest runs of a deterministic command inside one second are byte-identical, and a rule refusing that evidence is worse than none; the body count is the fallback identity only when a sidecar carries neither `started` nor `pid`. Forging N sidecars with N pids is the unkeyed-sidecar limit stated under *Limits*, not this term's job. `green_distinct_runs` and `green_distinct_bodies` report both counts. **A term about repetition only** (convention #8, narrower than `command_mismatch`, which applies to every green): it never applies to a single green, so the default invocation is unchanged.
- **`--no-flaky-pass`** — opt-in, GREEN-only: enforces TDD's "retries are instrumentation, not treatment" (`test-driven-development/SKILL.md` Workflow step 2). Scans each `--green` capture's own runner output — from `## Summary` onward when that heading exists (a `run_quiet.py` capture: its normalised `Summary: <line>` restatement of a recognised per-runner status line), else from `## Captured output` onward — for a pass-on-retry marker, never the capture's header lines above either heading. Markers, each cited rather than guessed: Playwright's `"<N> flaky"` summary line and `"(retry #N)"` attempt suffix (playwright.dev/docs/test-retries), and pytest-rerunfailures' `RERUN <nodeid>` line (its own quickstart docs). A line-anchored marker also tolerates `run_quiet.py`'s own `Summary: `/numbered-TAIL `N: ` prefixes — its output shape, not a runner's. Jest/Vitest are a **documented gap, not a guess**: both retry silently or without a citable default-reporter marker (Jest: jestjs/jest#11646/#16134; Vitest: no marker in its reporters/retry docs). Any match is exit 1, problem code `green_flaky_pass_marker`.
- **JSON keys** — `red`, `green`, `green_runs`, `red_result`, `green_results`, `command`, `problems`, `problem_codes`, `warnings`, `result`, `error`. Per capture: `path`, `role`, `exists`, `is_capture`, `sidecar`, `sidecar_present`, `sidecar_capture_sha256_ok`, `sidecar_body_agrees`, `exit_code`, `argv`, `finished`, `started`, `pid`, `capture_sha256`, `problems`, `problem_codes`. Top level also carries `green_distinct_runs` and `green_distinct_bodies`.
- **Problem codes** — `capture_missing`, `not_a_capture`, `sidecar_missing`, `sidecar_hash_mismatch`, `sidecar_body_disagrees`, `capture_header_missing`, `sidecar_no_exit_code`, `sidecar_no_argv`, `red_exit_zero`, `green_exit_nonzero`, `command_mismatch`, `green_not_newer`, `timestamp_unparseable`, `green_runs_short`, `green_runs_not_distinct`, `green_flaky_pass_marker`.
- **`--ledger` inputs** — each capture **and its sidecar**, so a later `check_commit_gate.py --require-ledger-gates check_red_green.py` re-hashes both and catches a sidecar edited after this gate passed.
- **Exit codes** — **0** every term holds; **1** any problem code; **2** missing `--red`/`--green`, or `--green-runs < 1`.
- **Self-test** — **44** cases, including an end-to-end pair produced by the real `run_quiet.py`, the four distinctness cases (one path cited N times, N byte-identical copies, distinct pids with one body, two runs inside one second), and the `--no-flaky-pass` set (each marker, unaffected default invocation, clean GREEN passes, RED is never scanned).

## next_bugfix_route.py

Makes the `bgpdd-bugfix` FAST / FULL / PLAN fork a mechanical derivation from `bug-report.md` + `rca.md` (grammar: `bgpdd-bugfix/references/rca-template.md`) instead of a judgement call made where the Orchestrator most wants to proceed (CLAUDE.md convention #9).

```bash
python next_bugfix_route.py --report <bug-report.md> --rca <rca.md> --ledger <path> \
    [--red <capture>] [--milestone "<slug>"] [--max-changed-files <N>]
python next_bugfix_route.py --self-test
```

- **`--ledger` is REQUIRED** and doubles as an input: the gate **refuses to route** (exit 2, `intake_unbacked`) unless the ledger's latest `check_bugfix_intake.py` entry is a `PASS` whose recorded input sha256 still matches the current `bug-report.md`. Matching is on the **hash**, not the path string, because the earlier invocation legitimately recorded a different (relative vs absolute) path.
- **The intake lookup is scoped by `--milestone` when one is given.** It used to take the globally latest intake record, so two bugs interleaved in one ledger produced a false `intake_unbacked` on the older one: bug A's route read bug B's later record and reported that A's report had been edited since it passed. Fallback is deliberately narrow — records carrying **no** milestone at all (an unscoped invocation), never another bug's — and a scoped `FAIL` for this bug still blocks. **Pass `--milestone <bug slug>` on both the intake gate and the route**, or the scoping has nothing to match.
- **The report's own fields come from delegating** to `check_bugfix_intake.py` and reading its JSON — the same subprocess-reuse pattern `check_commit_gate.py` uses for `check_runtime_evidence.py`. A child re-run that disagrees with the recorded PASS over the same bytes is exit 2, never a route.
- **`--red <capture>` ties the RED to the report** — **REQUIRED** when the report carries a `- Command:` line (omitting it is exit **2**, `red_required`). The RED capture's `<capture>.meta.json` sidecar `argv` must **equal a legitimate tokenization** of the report's command (backticks stripped). The comparison is on **token lists, not strings** — `shlex.split(posix=True)`, then the same with backslashes doubled (so a backslash-separated Windows path survives), then a raw whitespace split; any match passes, and `red_match_strategy` names which did. A string compare rejected every correctly quoted command (`-d '{}'`, `-H "Content-Type: application/json"`), because the shell strips quoting before the child sees argv. Nothing fuzzier is tried: reordered tokens, case differences and a different URL all still mismatch. The `- Command:` value must be a single **argv-runnable** command (no pipes, redirects or `&&`) — `run_quiet.py` runs argv with no shell. Mismatch is exit **1** `red_command_mismatch`; an absent/unreadable/argv-less sidecar or a missing capture is exit **1** `red_sidecar_missing`. A steps-only report has no command to compare, so `--red` is optional and unchecked there (passing it warns). This check runs **before** the RCA is read, so a RED that does not back the report blocks regardless of the RCA's state.
- **Route rules** — **PLAN** (outranks all) when the RCA declares a new capability, a schema or contract change, or `- Estimated changed files:` above `--max-changed-files` (default `5`). **FAST** when *all* hold: `reproduction_mode` is `command`; **the RED capture ran that exact command**; exactly one `- Root cause file:`; surface is `api` or `ui` (not `both`); `- Baseline suite: green`. **FULL** otherwise.
- **FAST and FULL differ ONLY in user check-ins** (FAST proceeds phase to phase; FULL pauses after the RCA and before the commit). **Neither ever skips RED, GREEN, Luna, or the commit gate** — the tool prints this in its `reasons`.
- **rca.md grammar** — `- Key: value` lines read file-wide, **last mention wins**; `- Root cause file:` is the one repeatable key. Fences are blanked (family rule), so a template block asserts nothing. A missing `- Baseline suite:`, `- New capability:`, `- Schema or contract change:` or any `- Root cause file:` is `INCOMPLETE`; a missing `- Estimated changed files:` only warns.
- **JSON keys** — `report`, `rca`, `ledger`, `max_changed_files`, `intake_backed`, `surface`, `runtime_observable`, `reproduction_mode`, `reproduction_command`, `red`, `red_argv`, `red_command`, `red_match_strategy`, `red_matches_report`, `problems`, `problem_codes`, `root_cause_files`, `baseline_suite`, `new_capability`, `schema_or_contract_change`, `estimated_changed_files`, `missing_fields`, `route`, `reasons`, `warnings`, `result`, `error`.
- **Exit codes and result values** — **0** `FAST` / `FULL` / `PLAN`; **1** `INCOMPLETE` (the RCA cannot be routed as written — fill the named fields; mirrors `next_milestone.py`'s `MIXED`) or `BLOCKED` (`red_command_mismatch` / `red_sidecar_missing` — the RED does not back the report); **2** missing `--report`/`--rca`/`--ledger`, `red_required`, `--max-changed-files < 1`, an unreadable `rca.md`, `intake_unbacked`, or an unavailable/disagreeing intake gate.
- **Self-test** — **52** cases, including two interleaved bugs in one ledger, an intake PASS whose hash no longer matches, a later FAIL superseding an earlier PASS, a fenced RCA that routes nothing, the full `--red` set (mismatch, missing sidecar, argv-less sidecar, `` `see chat` `` refused here, steps-only unchecked), and the quoting set (single-quoted JSON body, double-quoted header, Windows path, plus reordering/case/different-URL all still mismatching).

## pipeline_driver.py

Emits the **one next mandatory action** for a `bgpdd-bugfix`, `bgpdd-quick` or `bgpdd-bugfix-batch` lane. Every other tool here answers "is this artifact good enough?"; this one answers "where am I, and what is the single next step?" — a question phase order used to answer from prose the Orchestrator recalled (CLAUDE.md convention #9). It reads the lane root's artifacts and the gate ledger, derives the current phase, and prints the next action with its exact flags. **The Orchestrator executes; the driver decides.** Like `next_milestone.py` it is a READER: it grants no verdict, so it never writes the ledger.

```bash
python pipeline_driver.py --root <lane root> [--lane bugfix|quick|batch|auto] \
    [--json] [--ledger <path>] [--milestone "<slug>"]
python pipeline_driver.py --self-test
```

- **Flags** — `--root` required. `--lane` defaults to `auto`: `note.md` present → quick, else `bug-report.md` → bugfix, else exit 2 (both present → quick, with a warning). `--ledger` defaults to `<root>/gates.jsonl` and is **read only**. `--milestone` overrides slug derivation; it is **required only on the pre-2.6.1 unscoped feature route**, whose root basename (`implementation`) names the epic and never the bug — on 2.6.1's `implementation/bugs/{bug-slug}/` root the basename is the slug. `--json` emits the machine report; without it a compact human block is printed.
- **Phase derivation, bugfix** — **0** Intake until `bug-report.md` exists AND `check_bugfix_intake.py` has a `PASS` whose recorded hash still matches the report; **1** RED until a sidecar-backed capture under `evidence/red/` records a non-zero exit in *both* the sidecar and the capture body; **2** RCA/route until `rca.md` exists AND `next_bugfix_route.py` is `PASS`; **3** Fix until `run-log.jsonl` holds an `event: delegation` record for `mason` or `nova`; **4** GREEN until a sidecar-backed exit-0 capture exists AND `check_red_green.py` is `PASS` (plus `check_runtime_evidence.py` on `- Runtime observable: yes`); **5** Review/Close until `review-package.md` exists, `review-report.md` carries a `## Review:` section whose title holds the slug as a whole token with a `**Verdict:**` line, AND `check_commit_gate.py` is `PASS` **with `--commit` in its recorded argv**; then **6** Complete.
- **Phase derivation, quick** — **0** Scope until `note.md` carries three real `- What:` / `- Where:` / `- How verified:` lines; **1** Change-and-Prove until `evidence/check.md` + sidecar exist at exit 0 (Phases 1 and 2 are **fused deliberately**: an edit leaves no artifact, so the capture is the only observable either has); **3** Close until `check_quick_close.py` is `PASS` with `--commit`; then **4** Complete.
- **`--lane batch`** — choreography only, over `{batch-root}/orchestrator-state.json`'s `bugs` artifact and each bug's `bug:<slug>:status`/`bug:<slug>:root` (written only through `update_state.py --set-artifact`): **0** Batch list (main session) until `batch.md` and the state file exist and `artifacts.bugs` is set; **1** Waves — per-bug lane, naming the next `OPEN` bug (status not `MERGED`/`DROPPED-PLAN`) and its own `pipeline_driver.py --root <bug-root> --lane bugfix --milestone "<bug-slug>" --json` invocation, one bug at a time; **2** Close once every bug is terminal, naming `check_batch_close.py`'s exact invocation; then **3** Complete once that gate is `PASS`. It never re-derives a per-bug phase — that is the named `--lane bugfix` driver's job.
- **Stack defaults in the quick actions** — the driver shells out to its sibling `detect_stack.py` (never imports it: one self-contained file per script, and a copied stack table would be a second table to keep in step) for the repo the lane root sits in — the nearest `.git` ancestor, else the `.docs` parent. Phase 0's `next_action` then names the first `suggested_check_commands` entry as the `How verified` **proposal** the user confirms or replaces, and Phase 3's close command carries `test_path_globs` as one `--frozen` per glob (falling back to `--frozen tests/` when nothing is detected — a printed example, not a default inside the gate, which deliberately has none). Best-effort and cached per repo: a missing detector warns once, and any other failure simply drops the clause rather than blocking a lane on a suggestion.
- **Route detection (bugfix)** — by folder shape, not file presence, because Phase 0 has not created the standalone state yet: a root at `…/implementation/bugs/{bug-slug}/` is the **feature** route (2.6.1) and `{state-file}` is the epic's own `orchestrator-state.json` three levels up; a root whose basename is `implementation` is the pre-2.6.1 feature shape with the state one level up (kept for in-flight bugs); either absent → exit 2, mirroring the spine's Phase 0 HALT. Anything else is **standalone** with the state inside the root.
- **JSON keys** — `root`, `lane`, `route`, `state_file`, `milestone`, `milestone_source`, `ledger`, `phase`, `phase_name`, `next_action`, `required_gate`, `required_gates`, `gate_status`, `blocked_by`, `artifacts_present`, `artifacts_missing`, `warnings`, `error`, `exit`.
- **`required_gate` is set only when running that gate IS the next action** — when the next action is to author an artifact or delegate an agent it is `null`. `gate_status` is `PASS|FAIL|MISSING|null`; a `PASS` whose recorded input hashes no longer match disk is reported as `FAIL` (the enum stays four-valued; `blocked_by` names the edited file). Staleness is deliberately **not** applied to the closing gate — a commit that already happened cannot be un-happened by a later edit, so that case warns and still exits 3.
- **`blocked_by` codes** — `gate_not_run <gate>`, `gate_not_passed <gate>`, plus the capture codes copied minimally from `check_red_green.py`: `capture_missing`, `not_a_capture`, `sidecar_missing`, `sidecar_hash_mismatch`, `sidecar_no_exit_code`, `capture_header_missing`, `sidecar_body_disagrees`, `red_exit_zero`, `capture_exit_nonzero`.
- **Exit codes** — **0** a next action was emitted; **1** BLOCKED, and the invariant is `exit 1` **iff** `blocked_by` is non-empty (a required gate that has never run counts, deliberately: the lane cannot advance, so a caller wiring this into a hook gets a stop — the exact command is still printed); **2** root unreadable, no lane detected, or a feature root with no epic state; **3** lane complete (`bugfix` and `quick`: the closing gate `PASS`ed with `--commit`; `batch`: `check_batch_close.py` `PASS`ed), with the close steps in `next_action`.
- **Not derived** — whether a gate *would* pass (it reads verdicts, never re-runs a gate), `--changed-files` (no artifact records them, so the emitted commands carry `<the builder's paths>` verbatim; every other flag is exact), and the commit message. `next_bugfix_route.py` records no `route` in its ledger line, so the Phase 3 warning names the re-run command instead of guessing FAST vs FULL.
- **Self-test** — **73** cases across four suites: every phase boundary for both lanes, feature vs standalone roots (both feature-route shapes), FAIL and stale records blocking, a report edited after intake PASS, a RED that exited 0, runtime-observable requiring the runtime gate, the deliberate skip (a builder delegation recorded while the route gate never ran), both lanes complete at exit 3, the `detect_stack.py` defaults reaching the Phase 0 and Phase 3 actions (with both fallbacks), and `--lane batch`'s own phase boundaries (no bugs list, an open bug naming the next per-bug driver invocation, the close gate missing/FAIL/PASS, and complete at exit 3). Depth (phase tables, the exit-code design, what the other lanes would need): `references/pipeline_driver.md`.

## check_batch_close.py

The `bgpdd-bugfix-batch` Phase 4 close gate. Converts that lane's prose-only close (a final table, a `git worktree remove` per bug, and the promise nothing was skipped) into an artifact that has to be run (convention #9). It reads `{batch-root}/orchestrator-state.json` for the bugs list and each bug's recorded `status`/`worktree`/`root` (written only through `update_state.py --set-artifact`, `bgpdd-bugfix-batch/SKILL.md` §1) and verifies, for every bug: its status is terminal (`MERGED` or `DROPPED-PLAN` — an `OPEN` bug, including one a rebase HALT left `OPEN`, blocks the close); a `MERGED` bug's OWN ledger (`{bugfix-root}/gates.jsonl`) holds a `check_commit_gate.py` record whose latest verdict for that milestone is `PASS` with `--commit` in its `argv`; its recorded worktree path no longer exists on disk (an `OPEN` bug's worktree is expected to still be there and is not checked); and `--batch-md`'s `## Final` table carries a row for it, with a non-placeholder commit cell when it is `MERGED`. ```bash

## check_acceptance_suite.py

Gates the **feature-scoped** walkthrough, one scope up from every other gate here: per-milestone evidence proves each brick, nothing else proves the wall stands. Execution mode gates Alex's `acceptance-matrix.md` against Quinn's `acceptance-results.md`; structure mode (`--lint-only`) gates that the matrix is well-formed at plan time, before any code exists. Run at `bgpdd-build` Phase 5 before Dep writes the prep ship-decision, at `bgpdd-verify` Phase 3, and again at `bgpdd-shipping` Stage 1 as regression.

```bash
# Execution mode — gates that the matrix was RUN (build Phase 5, verify Phase 3, shipping Stage 1)
python check_acceptance_suite.py --matrix <path> --results <path> \
    [--repo <dir>] [--require-priority P0[,P1]] [--min-scenarios <N>] \
    [--changed-files <p1> [<p2> ...]] [--emit-gate-args] [--ledger <path>]
# Structure mode — gates that the matrix is WELL-FORMED (bgpdd-plan Phase 3.5)
python check_acceptance_suite.py --lint-only --matrix <path> \
    [--requirements <path>] [--min-scenarios <N>] [--emit-gate-args] [--ledger <path>]
python check_acceptance_suite.py --self-test
```

- **Flags** — `--repo` defaults to `.`, `--min-scenarios` to `1`. `--require-priority` is **"at or above"** (so `P1` gates {P0, P1}); omitting it gates every scenario. `--results` with `--lint-only`, `--requirements` without `--lint-only`, and `--changed-files` with `--lint-only` are each exit 2, never a silent ignore. `--changed-files` adds freshness: the results file's mtime must be `>=` the newest changed file. **Deliberate divergence (convention #8):** `bgpdd-build` Phase 5 step 2.5b and `bgpdd-verify` Phase 3 do NOT pass `--changed-files` — the results are produced by the Quinn delegation immediately before the gate, so freshness is by construction; `bgpdd-shipping`'s later re-execution is the one call site where staleness is possible, and it passes the flag.
- **Manual evidence must BE a capture** — cited under `evidence/runtime/`, existing, non-empty, and carrying a `## Captured output` section; whether it is honest stays `check_runtime_evidence.py`'s job.
- **`--emit-gate-args`** derives `check_runtime_evidence.py`'s `--surface` / `--expect-status` / `--require-key` / `--forbid-host` from the matrix's `## Environment` preamble into `gate_args`, so `bgpdd-verify` Phase 3 stops copying them by eye (convention #9; the counterpart of `next_milestone.py --emit-gate-args`, which reads a plan's `RUNTIME PROBE:` line). Works in **both** modes and is **advisory — it never changes an exit code**, and no lint requires the preamble to exist (the build and lite lanes' matrices legitimately have none).
  - **Preamble grammar it reads** — `- Key: value` lines under a level-2..4 `Environment` heading, up to the next heading of that level or higher, fences blanked: `- Surface:`, `- Expect status:` (or `Expected status`), `- Response keys:` (or `Require key(s)`, `Response envelope keys`, `Envelope keys`), `- Forbidden hosts:` (or `Forbidden host patterns`, `Forbid host(s)`). Values are comma- and/or whitespace-separated with backticks stripped; `none`/`n/a`/`TBD`/`-`/`unknown` count as absent. Other preamble lines (start commands, base URLs) are read by humans and Quinn, not by this flag.
  - **Conservative by design** — a **repeated** `Surface` or `Expect status` (a per-surface preamble) is AMBIGUOUS, not last-wins: it emits nothing for that field and names the conflict in `warnings`, because silently picking one is precisely the transcription error this exists to prevent. A non-identifier "key" is ignored with a warning. An absent preamble warns and emits nothing.
  - **`gate_args`** — `{surface, expect_status, require_keys, forbid_hosts, argv, source}`, where **`argv` is the paste-ready flag list** to hand to `check_runtime_evidence.py`. `null` when the flag is not passed.
- **JSON keys** — `matrix`, `results`, `requirements`, `lint_only`, `require_priority`, `min_scenarios`, `changed_files`, `stale_results`, `scenarios`, `gated_scenarios`, `steps`, `steps_gated`, `passed`, `failed`, `blocked`, `not_run`, `missing_results`, `unevidenced_manual`, `dangling_inverse`, `undeclared_inverse`, `extra_results`, `warnings`, `result`, `error`, plus the structure-mode set `linted_scenarios`, `exempt_steps`, `invalid_exemption`, `missing_priority`, `missing_step_table`, `missing_columns`, `unrecognized_mode`, `missing_stores`, `duplicate_keys`, `malformed_steps`, and — only with `--requirements` — `must_have`, `should_have`, `uncovered_should`, `lint_failures`; plus `gate_args` (only with `--emit-gate-args`, else `null`). Every key is present in both modes.
- **Exit codes** — **0** gated scenarios ≥ `--min-scenarios`, at least one gated step had a result, and the blocking arrays empty; **1** any gated step missing a result, any gated `FAIL`/`BLOCKED`/`NOT RUN`, an unevidenced gated manual step, any dangling `[inverse of N]`, an unparsed gated step table, `stale_results`, too few scenarios, zero gated steps, or (structure mode) any structural defect or uncited Must-Have; **2** mode-separation violations, missing/unreadable matrix or results, no parseable scenario or result line, `changed_file_missing`, a `--requirements` file with zero Must-Haves, or a bad `--require-priority` token.
- **Self-test** — **107** cases. Depth (structure-mode conditions, results grammar, parsing rules, mode divergences, fixtures): `references/check_acceptance_suite.md`.

## check_ship_decision.py

Makes Dep's `ship-decision.md` GO/NO-GO machine-verifiable: an unambiguous labeled `GO` or `NO-GO`, a Rollback heading, a post-deploy checklist section. Used shape-only at `bgpdd-build` Phase 5 step 6 and `bgpdd-shipping` Step 0.4 (a prep decision legitimately predates a rehearsal and a baseline), and with `--require-go --require-rehearsal --require-baseline` at `bgpdd-shipping` Step 3.


- **Flags** — `--require-go` fails on `NO-GO`. `--require-rehearsal` demands one grammar-conforming `Time to Rollback:` line whose cited capture resolves under `evidence/rollback/`, is non-empty, has `## Captured output`, and has a `run_quiet` `.meta.json` sidecar with matching `capture_sha256`, agreeing with the capture's own header lines (the shared contract above), and `exit_code` 0. `--require-baseline` demands a `## Baseline`/`### Baseline` section with ≥3 `- <metric>: <value>` lines each citing an existing path under `evidence/baseline/` **that carries the same `.meta.json` provenance sidecar, matching `capture_sha256`, that a rehearsal capture does**. - **Problem codes** — `rehearsal_missing`, `rehearsal_unevidenced`, `rehearsal_stale`, `rehearsal_failed_exit`, `sidecar_body_disagrees`, `capture_header_missing`, `baseline_missing`, `baseline_unevidenced`, `unledgered_capture` (only under `--require-ledgered-captures`; otherwise the same finding is a `warnings` entry), plus `ledger_chain_broken`, `ledger_missing`, `ledger_failed` and `ledger_stale` from `--require-ledger-gates`. The two rehearsal-capture codes are the shared sidecar contract above, named identically across the four gates that read a sidecar: a rehearsal that FAILED and had its `exit_code` flipped to 0 is otherwise indistinguishable from one that proved the rollback works.

## mark_milestone.py

The write side of the `[x]` completion convention `next_milestone.py` reads. Until it existed, a milestone could be marked done by typing three characters: no commit, no gate, no evidence. It appends the marker only when the completion is backed, and leaves a ledger record either way.

```bash
python mark_milestone.py --plan <path> --milestone "<title>" --ledger <path> \
    [--repo <dir>] [--require-commit] [--require-game-tape <path>] \
    [--require-gates <name>[,<name>...] | --require-gates none]
python mark_milestone.py --plan <path> --reopen "<milestone>" \
    --evidence <path> --reason "<text>" --ledger <path>
python mark_milestone.py --self-test
```

- **Gate backing is ON BY DEFAULT, and the default is real.** With no `--require-gates` flag the gate set is `check_commit_gate.py`, which requires `--ledger` — so a bare `--plan --milestone` invocation is **exit 2**, not a silent pass. It used to be opt-in while the help text called it the default: `mark_milestone.py --plan p --milestone M2` appended the `[x]` and exited 0 with nothing behind it, which is the exact hand-edit this script replaced.
- **The opt-out is explicit: `--require-gates none`** (also `off`/`no`/`-`). A docs-only milestone or a spike legitimately has no gate behind it; that decision is now one somebody makes and the ledger's `argv` records, never one a forgotten flag makes silently. `--require-gates ""` still means *the default set* — deliberately not the same as `none`.
- **Flags** — `--require-commit` (still opt-in, for the same pre-repo case) demands that HEAD's history carry a commit naming the milestone (`git log --fixed-strings --grep="<title>"`). `--require-gates <names>` demands that each named gate's LATEST ledger entry for this milestone record `PASS`. The title match is case-insensitive and **whole-token**: `Milestone 1` never marks `Milestone 10`. Line endings and BOM survive; the diff is one character.
- **`--require-game-tape <path>`** — the shared game-tape cadence gate (identical implementation in `update_state.py`); see **The game-tape gate** under `update_state.py` below for its five checks and codes. The heading names **its own lane** (`bgpdd-<lane>`), so bugfix's Phase 5 tape satisfies it exactly as build's Phase 6 tape does.
- **`--reopen "<milestone>" --evidence <path> --reason "<text>" --ledger <path>`** — completion used to be a one-way door: `already_complete` refused a second mark, nothing removed the marker, and a shipping finding against a closed milestone had nowhere to go (`next_milestone.py` reported DONE, this script refused, and the only way back in was the hand edit it exists to replace). `--reopen` **removes** that milestone's `[x]`, which is precisely what `next_milestone.py` reads, so the router returns it as NEXT again. It is the one write here that DESTROYS a recorded verdict, so all three of `--evidence` (a file that must exist), a non-empty `--reason` and `--ledger` are **mandatory — exit 2 without any of them**, and `--require-commit`/`--require-game-tape` are exit 2 beside it (they are backing terms for a CLOSE, and a reopen is the claim that withdraws one). The chained record carries `action: "reopen"`, the evidence path, its sha256 and the reason, and the ORIGINAL close record is left in place: a reopen adds a line to the history, it never edits one. Exit **1** when the milestone is unknown or carries no `[x]`. **The marker is removed, not replaced with `[ ]`** — this grammar has no `[ ]` token, and `next_milestone.py` builds a title by stripping the heading prefix and nothing else, so an appended `[ ]` would become part of the title every later gate is scoped by, silently splitting one milestone's ledger records into two names.
- **Problem codes** (exit **1**, in `problems`) — `milestone_not_found`, `ambiguous_milestone`, `already_complete`, `no_commit`, `ledger_chain_broken`, `ledger_missing`, `ledger_failed`, `not_complete` (`--reopen` on a milestone carrying no `[x]`), plus the five game-tape codes.
- **Exit codes** — **0** the marker was appended; **1** a refusal above; **2** missing `--plan`/`--milestone`, an unreadable plan, no milestone headings, a gate requirement (default or named) without `--ledger`, or a git failure.
- **Deliberate divergence (convention #8)** from `check_commit_gate.py --require-ledger-gates`, which re-hashes inputs: this checks the VERDICT only. The ledger's hash **chain** is checked here too, and that is not a divergence — an intact chain is a precondition for reading any verdict out of the file at all.
- **Self-test** — **50** cases, including the six-lane game-tape heading table and eleven `--reopen` cases (the round trip through the real `next_milestone.py`, each missing-flag refusal, CRLF preservation, and re-closing a reopened milestone). Depth: `references/mark_milestone.md`.

## update_state.py

**The sanctioned read-modify-write path for `orchestrator-state.json`**, replacing hand-edits that risk malformed JSON or silent blocker deletion. Every invocation validates the existing file (if any), applies the requested action(s), stamps `updated`, and writes atomically before printing the resulting full state as JSON.

```bash
python update_state.py --state <path> \
    [--init --project-name <name>] \
    [--set-cursor <title|null>] [--set-pipeline <name>] \
    [--set-feature <feature|null>] [--set-branch <name>] \
    [--set-artifact <name>=<path>] \
    [--add-blocker "<text>" [--blocker-milestone <title>] [--blocker-capability <name>] \
        [--blocker-severity Critical|Important|Info] [--blocker-source <name>] [--blocker-evidence <text>]] \
    [--resolve-blocker "<id-or-text-or-substring>" --evidence <path>] [--ledger <path>] \
    [--set-halt '{"unit":...,"agent":...,"code":...,"reason":...}'] \
    [--clear-halt <unit> --reason "<what changed>"] \
    [--set-status active|escalated|closed [--reason "<text>"]] \
    [--milestone "<title>" --require-game-tape <path>]
python update_state.py --self-test
```

- At least one action is required per invocation; any combination may be given in one call.
- **`--init --project-name <name>`**: creates the skeleton (`schema` `"1"`, `project_name`, `feature: null`, `pipeline: ""`, `branch: null`, `milestone_cursor: null`, `artifacts: {}`, `blockers: []`) if the file does not exist; a **no-op with a warning** if it does, while other actions in the same call still apply.
- **`--set-cursor` / `--set-pipeline` / `--set-branch` / `--set-feature`**: set those fields verbatim. The **literal string `null`** sets the JSON field to `null`.
- **`--set-artifact <name>=<path>`** (repeatable): merges into `artifacts`; the literal value `null` stores JSON `null`. A spec with no `=` is a usage error.
- **`--add-blocker "<text>"`** (repeatable): appends a structured entry (schema in `check_blockers.py` above) with auto id `B-<n>`, one past the highest currently present — a documented limitation: a resolved top id can be reused. The `--blocker-*` companions apply to **every** `--add-blocker` in the invocation; any of them given without `--add-blocker` is a usage error. Legacy entries are never rewritten.
- **`--resolve-blocker "<target>" --evidence <path>`**: matches an exact id, then exact text (removing all entries sharing it), then a unique substring (ambiguous → exit 2 with `candidates`). **`--evidence` must resolve to an existing, non-empty file** — tried relative to the state file's own directory first, then the CWD (an absolute path is tried once, as given). Omitting it or passing a blank value is a usage error (exit 2, caught before any resolution is attempted); a non-blank value that does not resolve is a **FAILED gate, not a usage error** — exit 1, `evidence_not_found` / `evidence_empty` / `evidence_is_directory`, nothing written. A prose string like "trust me" is a syntactically valid, simply nonexistent path, so it fails the same way as any other typo. A target matching nothing warns and changes nothing. Every removal appends `<ts>\t<id>\t<full entry>\t<evidence>` to `blockers-resolved.log` beside the state file, and the ledger record gains `resolved_ids`, `resolved_entries`, and — once the evidence resolves — `evidence_resolved` (the resolved path, state-dir-relative) and `evidence_sha256`. Pipelines pass `--ledger` on this action.
- **`--set-status {active,escalated,closed} [--reason "<text>"]`**: merges `state["status"] = STATUS` plus a `status_updated` timestamp. `--reason` is optional here (unlike `--clear-halt`, where it is required) and, when given, is recorded on the ledger line alongside the `previous_status` this call overwrote. Written by `bgpdd-bugfix` Phase 2 step 5 / Phase 5 step 4 (standalone route) so `guard_action.py`'s lane-closed detection can treat an escalated or closed lane as closed without waiting on the 12-hour freshness window.
- **`--set-halt`/`--clear-halt` (`check_redelegation.py`'s write path)**: `state["halt"]` is a single standing entry, so a fresh `--set-halt` replaces whatever was there rather than accumulating a list. `--set-halt` takes a JSON object with non-empty string `unit`/`agent`/`code`/`reason` keys (any missing or blank → exit 2, nothing written) and stamps `added`. `--clear-halt <unit>` removes `state["halt"]` **only when it is currently set for that exact unit** — a mismatched unit or an absent halt is a no-op warning, never an error, since there is nothing wrong to fail on. **`--reason "<what changed>"` is required with `--clear-halt`** (blank or omitted → exit 2) — `check_redelegation.py` itself never clears a halt on any result, so lifting one is deliberately a human act with a recorded reason, not a field a passing re-run could flip. The ledger record for a successful clear carries `action: "clear-halt"`, the unit, the halt's `code`, and the reason.
- **The game-tape gate — `--milestone "<title>" --require-game-tape <path>`** (shared byte-for-byte with `mark_milestone.py`). A lane's game-tape phase fires **each time a milestone closes**, and the closing write is the moment the Orchestrator most wants to move on — so the cadence is enforced by the two scripts that perform that write, not by prose (convention #9). **The heading names its own lane**: `bgpdd-<lane>` for ANY lane name (`bgpdd-build`, `bgpdd-bugfix`, `bgpdd-quick`, …). It was hard-coded to `bgpdd-build`, which made the flag unusable everywhere else — `bgpdd-bugfix`'s Phase 5 tape is written under a `## bgpdd-bugfix — ` heading and could never satisfy a gate that looked for one word, so that lane's tape was unenforceable. Build is unchanged, and the SHAPE requirements are identical for every lane. With fences blanked (a checkpoint inside a fence is a template), the gate demands: a `## bgpdd-<lane> — <milestone> — <date>` heading matching the milestone by whole token — full title or its leading identifier, the same two tokens the commit gate matches a review heading on, and the **epic-summary heading does not count**; last matching section wins; **3–6 bullets**; **at least one fenced block** ("no pasted output, no claim"); and either a `summarize_run` mention or a table row (the pasted telemetry block). **Codes**: `game-tape-missing`, `no-section`, `bullet-count`, `no-pasted-output`, `no-telemetry`. In `update_state.py` it is **active only on a `--set-cursor`/`--set-pipeline` write with `--milestone`** — the write that closes a milestone; any other action (a blocker add, an artifact set) warns on stderr and proceeds, because a gate that fires when nothing closed teaches nothing. `--require-game-tape` without `--milestone` is exit 2. `--milestone` also becomes this run's ledger `milestone` value, overriding the `--set-cursor` fallback.
- **Exit codes** — **0** the action(s) applied and the file was written; **1** the game-tape gate refused, or `--resolve-blocker`'s `--evidence` did not resolve to an existing, non-empty file (`evidence_not_found` / `evidence_empty` / `evidence_is_directory`) — **nothing was written** in either case; **2** usage/structural failure (missing `--state`, no action, `--init` without `--project-name`, `--resolve-blocker` without non-empty `--evidence`, an ambiguous resolve target, a `--blocker-*` companion without `--add-blocker`, a bad `--set-artifact` spec, a state file that is not a JSON object, a missing state file without `--init`, `--require-game-tape` without `--milestone`, a malformed/non-object/missing-key `--set-halt`, or `--clear-halt` without a non-empty `--reason`).
- **Self-test** — **69** cases, including the six-lane game-tape heading table, the four near-miss headings that name no lane, the `--set-halt`/`--clear-halt` round trips, the `--evidence` file-resolution cases (not-found, empty, directory, and the successful `evidence_resolved`/`evidence_sha256` ledger fields), and the `--set-status` round trips (`status_updated`, `previous_status`). Depth (atomicity, the blocker-ledger rule this mechanizes, the schema migration): `references/update_state.md`.

## run_quiet.py

Runs a build or test command, writes its **full** merged stdout+stderr to a
log on disk, and prints a short report to stdout: a recognised runner's
**summary line(s) first**, then the header, an error excerpt with context,
and a tail. With `--capture` it also writes a conforming runtime-evidence
capture artifact plus the provenance sidecar the runtime gate requires. It
exists so a transcript carries only what it needs to diagnose a failure
while nothing is actually lost.

```bash
python run_quiet.py --log <path> [--context N] [--tail N] [--timeout SECONDS] -- <command and args...>
python run_quiet.py --capture <path> [--capture-field Name=value]... [--log <path>] [--full-body] [--ledger <path>] [--milestone "<title>"] -- <command and args...>
python run_quiet.py --self-test
```

- **Flags** — one of `--log` or `--capture` is required, plus a command after `--`. Defaults: `--context 5`, `--tail 15`, `--timeout 240` (seconds). Everything after `--` is passed to the child verbatim (no shell). `--capture-field`, `--full-body`, `--ledger` and `--milestone` without `--capture` are usage errors.
- **`--ledger <path>`** — after the capture and its sidecar are on disk, append ONE chained record (§ Gate ledger) with `gate: "run_quiet.py"`, `verdict: "CAPTURED"`, `exit` = the CHILD's exit code, `inputs` = the capture and sidecar hashed as they landed, plus `command_argv` and **`capture_sha256`**. That record is what `check_agent_report.py`, `check_runtime_evidence.py` and `check_ship_decision.py` look a capture up in under `--require-ledgered-captures`: without it, a capture+sidecar pair proves only that the two files agree with each other, which a forty-line script writes for a command that never ran. **`--milestone`** scopes the record the way every gate's does. Writing is best-effort (a ledger that cannot be written never changes this tool's exit code), and **without `--ledger` behavior is unchanged** — every existing invocation is unaffected.
- **`--capture` body is an EXCERPT by default** — the same error-profile lines with context, plus a tail, that `--log` prints to the terminal, capped at ~200 lines, not the full child output (the 130KB-Vite-chunk-list-in-a-quick-lane-capture failure mode). The FULL merged output always lands on disk: `--log <path>` if given, else a sibling `<capture path>.log`. Pass **`--full-body`** to embed the full output in the capture instead, for a probe whose entire output IS the evidence (a small JSON response, a short `curl -i`) — recorded as `full_body: true` in the sidecar.
- **`## Summary`** — a section above `## Captured output` (and the first line(s) of stdout, ahead of the header, in both `--log` and `--capture` runs) carrying the per-runner summary line(s) this tool recognises: dotnet test (`Passed!`/`Failed!`, `Total tests:`), MSBuild (`N Warning(s)`, `N Error(s)`, `Build succeeded.`/`Build FAILED.`), vitest/jest (`Tests:`, `Test Files`, `Test Suites:`), pytest (`=== N passed, M failed ... ===`), Playwright (`N passed`/`N failed`/`N flaky`) — or `Summary: none recognised (exit <code>)` when nothing matches.
- **`--capture` field ownership** — `--capture-field Name=value` supplies only the descriptive header (`Title`, `Milestone`, `Requirement IDs`, `Surface`, `Transport`, `Base URL`, `Environment`, `Config repointed`, `Build marker`, `OpenAPI`). A field name the tool owns — `Probe command`, `Captured`, `Exit code`, `Duration`, `Log`, `Log sha256` — is **rejected, not overwritten**: exit **2**, no capture written. That refusal is the integrity property of this mode.
- **The sidecar** — `--capture <path>` also writes `<path>.meta.json` recording `argv`, `cwd`, `host`, `pid`, `started`/`finished` (ISO-8601 UTC), `exit_code` (124 on timeout), `body_sha256` (over the captured text as embedded — the excerpt by default, the full output under `--full-body`), `capture_sha256` (over the finished capture FILE's bytes), `log_sha256`/`log_path` (over/naming the FULL log on disk), `full_body` (bool), `tool: "run_quiet.py"` and `schema: 2`. Its path is printed on the `sidecar:` line of the stdout summary. `check_runtime_evidence.py` requires it.
- **The body's header is stamped FROM the sidecar's values, and the tool asserts they agree.** `- Exit code:` is the exit code recorded in `exit_code`; `- Captured:` is the `finished` instant **exactly** (it used to call `now()` again while rendering, leaving the two honestly but unpredictably a second apart). `assert_capture_agrees()` re-checks the pair before the sidecar is written, so this tool can never emit a pair that fails the shared agreement contract above; a disagreement here is exit 2 with an `internal:` message, not a capture on disk.
- **Exit codes** — passthrough of the child's own exit code; **124** the child was killed for exceeding `--timeout` (best-effort process-tree kill); **2** structural/usage failure (no `--log`/`--capture`, no command after `--`, a log or capture path that cannot be created or written, an owned `--capture-field`, `--capture-field`/`--full-body` given without `--capture`, or a command that could not be launched). **Windows caveat**: the child is launched without a shell, so Python cannot exec a `.cmd`/`.bat` shim — invoke `npx.cmd`/`npm.cmd`, or bypass the shim (`node node_modules/@playwright/test/cli.js`).
- **Self-test** — **48** cases. Depth (sidecar rationale and the `.gitattributes` caveat, report shape, error profile, the no-information-lost guarantee, the excerpt-body/full-body split, summary extraction): `references/run_quiet.md`.

## record_run.py

Appends one run-telemetry record per delegation completion and per state persistence to `.docs/{project-name}/implementation/run-log.jsonl`. The gate ledger records which gates fired; this records what the run cost — agent, model, duration, tokens, rounds. Orchestrator Contract §4 owns the obligation; this section owns the CLI.

```bash
python record_run.py --log <path> --pipeline <name> --phase <name> --event <delegation|gate|phase|note> \
    [--unit "<title>"] [--agent <name>] [--model <id>] [--tier <haiku|sonnet|opus|fable>] \
    [--duration-s <float>] [--tokens-in <int>] [--tokens-out <int>] [--tokens-total <int>] \
    [--tokens-unavailable "<runtime>: <reason>"] [--rounds <int>] \
    [--status <STATUS>] [--note "<text>"] [--runtime <name>] [--from-json <file>] \
    [--allow-tier-inversion "<reason>"]
python record_run.py --self-test
```

- **Flags** — `--log`, `--pipeline`, `--phase`, `--event` required. **`--model` is additionally required for `--event delegation`, and so is a token measurement** (see below). `--status` ∈ `COMPLETE|PARTIAL|BLOCKED|PASS|FAIL|ERROR`. `--from-json <file>` maps a runtime completion payload; explicit flags override the payload. `--runtime <name>` (e.g. `claude-code`, `antigravity`, `cursor`) is recorded verbatim on any event and is never required.
- **Record** — `{"ts", "pipeline", "phase", "unit", "agent", "model", "tier", "event", "duration_s", "tokens_in", "tokens_out", "tokens_total", "tokens_unavailable", "rounds", "status", "note", "runtime"}`.
- **`--model` is mandatory on a delegation record.** Measured finding: model choice left to prose decays — 17 dispatches in one audited wave silently inherited the most expensive tier, and the run log could not tell that apart from a deliberate choice because the field was simply null. A null there is **not** "not measured": the tier is always known at dispatch, so its absence records a decision nobody made (convention #9 — a restraint rule skipped at the moment the Orchestrator wants to proceed becomes a gate, not louder prose). Checked **after** `--from-json` merges, so a payload carrying `model` satisfies it. `gate`/`phase`/`note` events are unchanged — demanding a tier there would invite a fabrication. **`--model inherit` is refused outright (`model_inherit`, exit 2), case-insensitively** — `inherit` names a runtime setting the Orchestrator configured, not a measurement of the tier the delegation actually ran at.
- **An unresolvable `--model` is exit 2 (`model_unknown`), not a null tier — UNLESS `--tier` supplies it.** `gpt-4o`, a name mentioning two tiers (`sonnet-or-opus`), a typo, or an honest non-Claude runtime id such as `gemini-3.8-flash` — each used to record cleanly with `tier: null` and silently DELETE the inversion check for that delegation, or forced a non-Claude runtime to lie about running on a Claude tier just to get recorded. Resolvable means `--model` contains exactly one of `haiku`/`sonnet`/`opus`/`fable`, case-insensitively, so `opus`, `Opus`, `opus-4.1`, `claude-opus-5` and `claude-fable-5-1` all resolve. **When `--model` resolves, `--tier` is optional and must agree if given (`tier_mismatch`, exit 2, otherwise). When it does not resolve, `--tier <haiku|sonnet|opus|fable>` is REQUIRED**; the record stores `model` verbatim and `tier` from the flag — this is how a run that actually executed on Google Antigravity with Gemini is now recorded honestly instead of as `model: "sonnet"`. Delegation records only; the inversion check reads the record's `tier` field (falling back to deriving it from `model` for older log lines that predate this field).
- **Tokens are mandatory on a delegation record (`tokens_missing`, exit 2).** One of: `--tokens-total`, both `--tokens-in` and `--tokens-out`, a `--from-json` payload carrying any of those, or `--tokens-unavailable "<runtime>: <reason>"` naming why none could be measured. Field audit of 25 real runs: only 20 of 138 delegation records carried any token figure at all before this gate — an absence must now be a stated refusal, not a silent null nobody explains.
- **`fable` is the top tier: `haiku < sonnet < opus < fable`.** Claude Fable 5.1 is the current top model and its ids look like `claude-fable-5-1`; left out of the tier map, every fable delegation was `model_unknown` and therefore unrecordable. With it ordered correctly the two real pairings resolve: a **fable** verifier over an **opus** producer is not an inversion, and an **opus** verifier over a **fable** producer is `verifier_below_producer`.
- **One delegation, one record (`duplicate_delegation`, exit 1).** Orchestrator Contract §4: "A second completion notification for an agent that has already returned is a re-wake — a background task it started finishing after its handoff — not a new delegation … the first completion is the measurement." That restraint is asked for while a notification with a bigger, more recent-looking number sits in the transcript, so convention #9 makes it a refusal: an `--event delegation` record whose (`--pipeline`, `--unit`, `--agent`, `--rounds`) tuple is already in the log is refused and **nothing is written**, keeping the first completion as the cost. **`--rounds N` is what distinguishes a real second delegation from a re-wake** — a fix round 2 of the same agent on the same unit records `--rounds 2` and is a different tuple; the error message says so. There is deliberately **no `--rewake` flag**: the lesson is that a re-wake is not recorded at all, so a flag that recorded one would be the thing being prevented. **`--phase` is outside the tuple** on purpose — a re-wake often lands after the Orchestrator has moved on, and letting a re-labelled phase mint a fresh record would leave exactly the double-count this refuses. Skipped when `--agent` is absent (nothing identifies the delegation to be a duplicate *of*) and for every non-delegation event. Checked **before** the inversion check: the tuple decides whether the record should exist, the tier only judges one that should.
- **Unknown is `null`, never `0`** (Evidence Integrity). An explicit `0` is preserved. `tokens_total` is derived only when both halves are known.
- **A verifier never runs below the producer it judges.** On `--event delegation` with `--agent` ∈ `quinn|luna|vera|cipher`, the script reads back the log's most recent **producer** delegation (`mason|nova|max|dep`) in the **same `--unit`** and refuses (**exit 1**, `verifier_below_producer`, nothing written) when this verifier's tier is lower. Tier order `haiku < sonnet < opus`, matched on the tier name appearing anywhere in the model string (`claude-opus-4-1` resolves to `opus`); a value naming no tier or two is refused outright at the flag (`model_unknown`, above), so an unresolved tier can no longer reach this comparison at all. **`dep` is a producer**: it produces the deployment artifacts Vera and Cipher judge at shipping, and its absence from that tuple made the one pairing unmeasurable. Nothing to compare against is not a refusal either: a verifier that runs before any producer in its unit (the bugfix lane's pre-fix RED capture) passes. **`--allow-tier-inversion "<reason>"`** overrides it and writes `"tier_inversion_reason": "<reason>"` onto the record; an empty reason is exit 2 — an inversion nobody justified in writing is the one this check exists to stop. This is the agent-audit's model-assignment-fit heuristic converted from a finding into a refusal (convention #9).
- **Exit codes** — **0** appended; **1** `duplicate_delegation` or `verifier_below_producer`; **2** usage error (including a delegation with no model, an unresolved `--model` with no `--tier` to fall back on (`model_unknown`), a `--tier` that disagrees with a resolvable `--model` (`tier_mismatch`), an invalid `--tier` value, `--model inherit` (`model_inherit`), a delegation with no token measurement (`tokens_missing`), or `--allow-tier-inversion` with a blank reason), a bad/unreadable `--from-json`, or an unwritable log. Unlike the best-effort ledger, a failed write is exit 2 — the record IS the artifact.
- **Self-test** — **70** cases, including the five `model_unknown` strings, the `dep`-as-producer pairing, the end-to-end case proving a typo can no longer disable the inversion check, five `fable` cases (both tier pairings and the current model ids), eight `duplicate_delegation` cases, `--tier`/non-Claude-model cases (required-when-unresolvable, optional-and-must-agree, `tier_mismatch`, an invalid tier value, and the inversion check reading a non-Claude producer's stored tier), `model_inherit` cases, the token-requirement cases (each of the four accepted forms, `tokens_missing`, and a blank `--tokens-unavailable`), and `--runtime` cases. Depth (`--from-json` mapping table, the deliberately unmapped fields): `references/record_run.md`.

## record_capture.py

Writes `<png>.meta.json`, the provenance sidecar `check_commit_gate.py --require-rendered-evidence` now requires for a cited PNG. The incident this closes: a UI builder that could not reach the running application rendered a static `file://` mockup, screenshotted it, and the existing magic-byte/mtime checks passed the file cleanly — nothing recorded WHERE the pixels came from. This is the write side: it records the URL the browser had open at capture time, so a mockup render and a real capture stop looking identical.

```bash
python record_capture.py <png> --url <url> --tool <name> [--force]
python record_capture.py --self-test
```

- **Flags** — `<png>`, `--url` and `--tool` are all required (exit 2, `missing_argument`, otherwise). `--url` must start with `http://` or `https://`; anything else — `file://`, `about:`, `data:`, empty — is refused (`bad_origin`, exit 1): a rendered capture proves the RUNNING application, and a non-http(s) origin proves a static document was open instead. `--force` overwrites an existing sidecar instead of refusing (`sidecar_exists`, exit 1, without it) — a capture is recorded once per PNG unless the PNG was re-taken.
- **Sidecar** — `<png>.meta.json` (appended to the full filename: `m2.png` → `m2.png.meta.json`), `{"schema": 1, "url", "tool", "captured_at" (ISO-8601 UTC, `Z` suffix), "sha256"}` (hex sha256 of the PNG's bytes at record time). This is the exact shape `check_commit_gate.py`'s rendered-evidence check reads back.
- **Exit codes** — **0** recorded; **1** `bad_origin`, `bad_magic` (the PNG's leading bytes are not the PNG magic), or `sidecar_exists`; **2** `missing_argument`, `png_not_found` (the file does not exist or cannot be read), or `write_failed` (the sidecar could not be written).
- **Self-test** — 11 cases: the happy path (http and https), a `file://`/`about:`/`data:`/empty refusal, a missing PNG, bad magic bytes (including a zero-byte file), the existing-sidecar refusal and its `--force` override, missing required arguments, and a check that the recorded sha256 matches the PNG's actual bytes.

## summarize_run.py

The reader half of `record_run.py` and the mechanical form of the fired-versus-rubber-stamped metric. `--markdown` emits a paste-ready game-tape block.

```bash
python summarize_run.py --run-log <path> [--ledger <path>] [--unit "<title>"] [--markdown]
python summarize_run.py --self-test
```

- **Flags** — `--run-log` required. `--ledger` adds the gates section (omitted or unreadable → `null` + a warning, exit unchanged). `--unit` scopes records and ledger entries to one milestone/bug slug; null-milestone ledger entries fall out of a unit view by design.
- **JSON keys** — `run_log`, `ledger`, `unit_filter`, `records`, `malformed_lines`, `pipelines`, `units`, `agents`, `gates`, `warnings`, `error`. Each bucket carries `records`, `delegations`, `duration_s_total`, `duration_known_count`, `duration_unknown_count`, `tokens_total`, `tokens_unknown_count`, `rounds_max`, `rounds_recorded` (plus `duration_mean_s` for agents). `gates = {per_gate: {<name>: {runs, pass, fail, error, units}}, fired, rubber_stamped, inconclusive}`.

```bash
guard_action.py [--format claude|cursor] [--window-hours N] < hook.json
guard_action.py --explain [--cwd DIR]

```

- **Rules** — `commit_through_the_gate` (Bash running a history-writing `git commit|merge|cherry-pick|revert|rebase|am|notes|tag|stash [pop|apply]`, or `gh pr merge`, while any active OPEN lane that HAS a commit gate is detected → names that lane's gate; gates commit from their own subprocess, so a gate is never blocked); `frozen_tests_during_a_fix` (a write to an **existing** test path while a bugfix lane has no commit-gate PASS yet; a new path is allowed); `no_delegation_before_intake` (`Task`/`Agent` while a fresh `bug-report.md` lacks a `check_bugfix_intake.py` PASS); `gate_artifacts_are_written_by_tools` (a write to `gates.jsonl`, `orchestrator-state.json`, `run-log.jsonl` or a `*.meta.json` sidecar — always, lane or no lane); `build_and_test_through_the_wrapper` (Bash whose command's LEADING tokens — after stripping a leading `NAME=value` shell-variable-assignment/`env` prefix, and recursing into an interpreter wrapper's inline command string when one opens the segment: `cmd /c`, `powershell -c`/`-Command`, `pwsh -c`/`-Command`, `bash -c`, `sh -c` — are a raw `dotnet build`/`dotnet test`/`npm test`/`npm run build`/`npm run test`/`pnpm test`/`yarn test`/`pytest`/`npx playwright test`/`npx vitest`/`npx jest`, while any lane is active, and `run_quiet.py` is not on the line → denies naming the exact `run_quiet.py --log <path> -- <command>` wrapper form. Matched on leading tokens per shell segment, not a substring search, so a runner name quoted inside a commit message or an `echo` never matches, and `DOTNET_CLI_TELEMETRY_OPTOUT=1 dotnet test` / `env VAR=1 dotnet test` / `bash -c "dotnet test"` can't bypass it by hiding the real executable behind an env-var prefix or a wrapping shell. `npm run build:prod` and other unrecognized npm SCRIPT NAMES stay allowed on purpose — tuple matching is exact, not a prefix on the script name); `delegation_halted_for_the_user` (Task/Agent while any active lane's own `orchestrator-state.json` carries a non-empty `state["halt"]` → denies naming the halted unit, its code, its reason, and the exact `update_state.py --clear-halt` command — with the lane's real state-file and ledger paths substituted in — that lifts it. `halt` is written by `check_redelegation.py` via `update_state.py --set-halt` on `halt_environment`/`halt_dependency`/`halt_repeated_blocker`/`halt_round_bound`; there is no auto-clear-on-PASS path (removed this round) — only a human runs `update_state.py --clear-halt "<unit>" --reason "<what changed>" --ledger <path>` themselves, which removes `state["halt"]`. Read from the SAME lane-detection result rule 1 already computed for the call, not a separate pass; a halt in a lane outside the 12h freshness window is not armed, because the lane itself is not detected); `blackgoat_persona_is_hand_edited_only` (`Write`/`Edit`/`MultiEdit`, or a `Bash` mutation, whose target resolves to `agents/blackgoat.md` → DENY, always, lane or no lane — mirrors rule 4's scope, no lane detection needed. CLAUDE.md convention #7's file; no agent, not even Forge, may edit it. The single carve-out is the sanctioned append to `## Part VIII: Problem & Solution Ledger`: the environment variable `BLACKGOAT_ALLOW_PART_VIII_APPEND=1` set in the hook's own environment, AND — checkable only for `Write`/`Edit`/`MultiEdit`, whose payload carries the before/after text — the edit is a pure append landing after the Part VIII heading (old content unchanged, new content is old content plus a suffix). `Bash` gets no carve-out, env var or not: a shell command's target is a path string, not a diff, so there is nothing cheap to check that `>>` was the only thing done to the file); `pipeline_tools_are_help_not_source` (`Read`, or a `Bash` command that dumps a file — `cat`/`type`/`Get-Content`/`sed -n`/`head`/`tail`/`less` — targeting a `skills/pipeline-tools/scripts/*.py` file, while any lane is active → DENY naming the `--help` invocation to run instead. `base-persona.md` § Command Timeout Discipline: a pipeline-tools script is invoked, never read — its `--help` is the complete contract at a fraction of the source's token cost. **Carve-out**: when the cwd's own repository root IS this plugin repository (`skills/pipeline-tools/scripts/guard_action.py` exists under it), the call is always allowed, lane or no lane — editing the tools requires reading them, which is authoring, not the execution this rule restrains).
- **Rules 2 and 4 see `Bash`, not only the write tools.** Until 2.6.1 both tested `tool_name in WRITE_TOOLS`, so "always, lane or no lane" was false for the one guarded tool that can write anything: `echo '{}' >> gates.jsonl`, `| tee -a`, `Set-Content`, `python -c "open(...,'a')"`, `sed -i tests/x.test.js`, `mv test.js test.js.old`, `rm gates.jsonl` and `git checkout -- tests/` were ALLOW while `Edit` on the same path was DENY. The extractor now reads every path a shell command plausibly WRITES: `>`/`>>` redirection (any leading fd digit, per `;`/`&`/`|`/newline segment); the verbs `tee`, `mv`/`move`, `cp`/`copy`, `rm`/`del`/`erase`, `ren`/`rename`, `truncate` and the cmdlets `Set-Content`/`Add-Content`/`Out-File`/`Clear-Content`/`New-Item`/`Move-Item`/`Copy-Item`/`Remove-Item`/`Rename-Item`; `sed`/`perl` **only** with an in-place flag; `python -c` opening a path in a writing mode; and `git checkout -- <paths>` / `git restore <paths>`. It deliberately OVER-collects candidates and lets the two narrow predicates decide — matching is case-insensitive and separator-agnostic. For rule 2 a **test directory** counts as well as a test file, so `git checkout -- tests/` is caught (convention #8, wider than the write-tool branch, which targets one file).
- **Active lane** — read from the tree, never from prose: (a) a state file with a non-empty `pipeline`; (b) `.docs/bugfix/*/bug-report.md`; (c) **the feature route** `.docs/*/implementation/bug-report.md` and `.docs/*/implementation/bugs/*/bug-report.md` — the paths `bgpdd-bugfix` mandates for a bug inside an in-flight epic, whose ledger is the one beside the report or, for a slug-scoped folder without its own, the epic's `implementation/gates.jsonl`; (d) an unclosed quick note. Each inside a 12-hour freshness window. Until detector (c) existed, a bug fixed on the feature route armed rule 1 only — the builder could edit the RED and the Orchestrator could delegate before intake. `--explain` prints the rules, what is detected, each lane's milestone, and which rule is armed for what.
- **Closed lanes — rule 1's carve-out.** Rule 1 routes the commit through the gate; it must not forbid the close the pipelines mandate AFTER it (`bgpdd-bugfix` Phase 5 and `bgpdd-lite` Phase 3 both end in a local `git merge`, which the guard denied). A lane stops arming rule 1 once its own ledger holds a `check_commit_gate.py` **PASS carrying `--commit` for the lane's CURRENT milestone** — the bug slug for bugfix, `milestone_cursor` for feature/lite. The milestone scope is what keeps this from being a blanket disarm: an epic that committed M1 still arms rule 1 while the cursor points at M2. A milestone that cannot be read (a null cursor, or the unscoped feature-route report whose directory is `implementation` rather than a slug) is treated as NOT closed — fail-closed, and `--explain` says so. Quick keeps its older predicate: a `check_quick_close.py --commit` PASS removes the lane from detection entirely.
- **Status-aware lane close — rule 2's own closing predicate, independent of rule 1's ledger check.** A lane is also closed, for rule 1 (`Lane.closed`) and separately for rule 2 (`unfixed_bugfix_lanes()`), when its own `orchestrator-state.json` carries a terminal `status` of `escalated` or `closed`, written by `update_state.py --set-status` (`bgpdd-bugfix` Phase 2 step 5 / Phase 5 step 4, standalone route). This is **STANDALONE bugfix only** — the state file sits at the lane's own root there. The **feature route's bugfix sub-lane has no state file of its own** (its state file is the epic's, one level up, and `bgpdd-bugfix` §1 forbids this lane writing anything to it but a scoped blocker), so an escalated feature-route bug still arms rule 2 for the freshness window — reading the epic's own `status` would misattribute the whole epic's status to one bug among possibly several open on that route, and no per-bug-scoped status exists there to read. This is a **documented gap**, tracked rather than silently worked around.
- **A `bgpdd-verify` lane does not arm rule 1.** It is still detected (so `--explain` shows it) and rules 2–4 still apply — rule 4 in particular still guards its ledger — but verify has no commit gate: its only durable output is Quinn's specs, committed by hand outside the lane, so arming rule 1 there named a gate that does not exist and left the lane with no commit path at all.
- **Output** — a deny is `hookSpecificOutput.permissionDecision` on stdout with exit 0 (not exit 2: the Windows launcher swallows exit codes). An allow prints nothing; an explicit `"allow"` would short-circuit the user's own permission prompt.
- **Fails open** — any internal error, missing interpreter or unparseable payload allows and notes it on stderr. Every deny is a positive identification, never an inability to decide. Fail-open is a property of the ERROR handling, not a licence for a rule to be unarmed: the 2.6.0 state of rules 2 and 4 was not a fail-open, it was a rule that did not exist for the one tool that mattered. **Known limits**, each fail-open: a quoted mention such as `echo "git commit"` is over-blocked, while a commit through an alias (`git cm`), a script file, `Start-Process git -ArgumentList commit` or `subprocess.run(['git','commit'])` is not caught; `git tag` and `git stash` are denied even in their read-only forms (an over-block costs one `--explain`, an under-block costs a rewritten history); `git push` and `git replace` are deliberately outside the list; and the Bash write extractor reads a command STRING, not a shell, so a path built by variable expansion, reached through a script, or produced by a here-document is invisible, as is a directory-level `Remove-Item .docs -Recurse` that names no protected basename.
- **Self-test** — **119** cases, including BOM-prefixed stdin from PowerShell (a real fail-open this caught), every Bash mutating construct against both protected classes, both bugfix routes, the closed-lane and verify carve-outs, the widened git surface, rule 5's eleven raw-runner denials plus its wrapped/outside-a-lane/quoted-argument allows, rule 5's env-assignment/`env`-prefix and `bash -c`-wrapper fix round (4 cases), rule 6's halted/cleared/no-lane/stale-lane cases (4 cases), the `--set-status` closed/escalated round trips for rules 1 and 2, rule 7's `agents/blackgoat.md` denials across `Write`/`Edit`/`MultiEdit`/`Bash`, the Part VIII append carve-out (with and without the env var, and rejecting a non-pure-append edit), and rule 8's `Read`/`cat`/`type`/`Get-Content`/`head`/`tail`/`less`/`sed -n` denials during an active lane, its allow with no lane, its allow under the plugin-repo carve-out (an active lane there included), and `sed -i`/a non-script read staying outside the rule (6 cases).

## check_handoff.py

Parses the `<handoff>` block an agent returns and asserts it against that persona's contract — `base-persona.md` § Output Format plus the persona's inline "Base Persona Override". Nothing parsed this interface before: a handoff missing `<changed_files>`, naming a path never written, or claiming `PASS` beside a `NOT VERIFIED` marker read exactly like a good one. Required elements per persona: mason/max → `<changed_files>`; dep/quinn/nova → `<changed_files>` + `<artifact>`; forge → `<changed_skills>`; everyone else → `<artifact>`. `<status>` and `<blockers>` always. `agents/blackgoat.md` is not a persona here (convention #7) and is a usage error. **On a `PARTIAL`/`BLOCKED` `<status>`, `<blockers>` must also carry a `blocked_on: <category> — <reason>` line** (category one of environment/credentials/dependency/spec/defect) — the grammar `check_redelegation.py` reads to decide whether a re-delegation should halt; see that section below.

```bash
python check_handoff.py --handoff <file> --persona <name> --repo <dir> [--repo <dir> ...] \
    [--docs-root <dir> ...] \
    [--since <ref>] [--advisory] [--fix-round] [--require consumers] \
    [--allow-scaffolding "<reason>"] \
    [--milestone "<t>"] [--ledger <path>]
cat handoff.txt | python check_handoff.py --persona mason --repo .
python check_handoff.py --self-test
```

- **Flags** — `--persona` required; `--handoff` defaults to stdin; `--repo` defaults to `.` and is repeatable (a `<changed_files>` path is accepted under any listed repo, and `--since` diffs it against the one it resolved to); `--docs-root` is repeatable and optional, letting `<artifact>`/`<changed_skills>` (never `<changed_files>`) additionally resolve under a shared reports tree, and defaults to the nearest ancestor of `--handoff` named `.docs`. A *relative* `<artifact>`/`<changed_skills>` path also falls back to each `--docs-root`'s own parent directory and the cwd — the real-world shape is a handoff written relative to the workspace root ABOVE `.docs` (`.docs/bugfix/x/report.md`), not relative to `.docs` itself. `--fix-round` additionally requires `<fix_verification>` (base-persona: "already complete" exempts nothing). `--require consumers` promotes the standing-optional `<consumers>` element (mason/nova) to required.
- **`--since <ref>` is optional to the CLI and REQUIRED by the pipelines.** It is the only term here git can contradict: without it `<changed_files>` need merely exist; with it, a file the agent never touched is rejected. Every pipeline handoff step passes `--since` **and** `--ledger`; a call without them checks shape only and says nothing about what was written.
- **`--advisory`** — the two sanctioned steps that ask for a RECOMMENDATION and no artifact (Forge's propose handoff in `bgpdd-learn`, Aria's Mode 2 blast-radius advisory in `bgpdd-build`) failed exit 1 in every tag form, so the Orchestrator's mandatory validation was contradicted by the pipelines twice per epic. With the flag, `<artifact>` and `<changed_skills>` become optional for that one call and the ledger record carries **`advisory: true`** (inside the chain), so waiving the artifact is a written act rather than a skipped gate. **Nothing else relaxes**: `<status>`, `<blockers>`, the path checks on whatever IS declared, the status enum and the honesty rules all still apply, and `<changed_files>` stays required for the personas that carry it — an agent that wrote code has an artifact whether or not the brief asked for one. It is the **caller's** declaration about the brief it wrote, so it belongs in the pipeline step, never in the agent's output: an agent that could set it could waive its own artifact.
- **`<status>` is the DELIVERY state, not the verdict.** `COMPLETE`/`PARTIAL`/`BLOCKED` says whether the agent finished the work it was briefed for. A verification verdict (`PASS`/`FAIL`/`BLOCKED`) is a different claim and belongs in the body, beside the durable report it is a verdict about; the `status_invalid` message now says exactly that. `BLOCKED` is the one token both vocabularies share, and it means the same thing in each.
- **Checks** — a well-formed `<handoff>…</handoff>` outside fenced code (fenced templates are blanked first); every required element present and non-empty; every `<changed_files>`/`<artifact>`/`<changed_skills>` path exists under `--repo` and does not escape it; `<changed_files>` ⊆ `git diff --name-only <ref>` + untracked, when `--since` is given; `<status>` in `COMPLETE`/`PARTIAL`/`BLOCKED`; `<consumers>` lines in `path::symbol` grammar; two honesty rules — an upper-case `PASS`/`GREEN` token beside a `NOT VERIFIED`/`BLOCKED` marker in the same element, and `<status>BLOCKED</status>` with `<blockers>None</blockers>`; and, on `PARTIAL`/`BLOCKED` only, at least one `<blockers>` line matching `blocked_on: <category> — <reason>` with `<category>` one of environment/credentials/dependency/spec/defect (`COMPLETE` is exempt; an entirely absent `<blockers>` is `element_missing` instead, never both).
- **A COMPLETE artifact carries no scaffolding (`artifact_scaffolding_left`).** `base-persona.md` § Incremental Persistence: "Sweep the scaffolding before you return COMPLETE — the skeleton, its markers, and any note explaining that the markers exist are working apparatus for you, not content for the reader." That restraint is asked for once the substance is written and the sweep is bookkeeping, so convention #9 makes it a refusal. On `<status>COMPLETE</status>` every existing **text** file cited in `<artifact>` or `<changed_skills>` is READ and swept for the skeleton's vocabulary: base-persona's placeholder marker (an underscore joined to `TODO`, as in the template's `_ TODO : pending _`, spaced here so this page is not itself a hit), a `TODO`-colon-`pending` phrase, an `<!--`-`TODO` or `<!--`-`skeleton` comment, and any line that EXPLAINS the markers to the reader ("Note: the placeholder sections are filled in later"). One finding per hit line, naming `file:line` and which marker matched. Four deliberate bounds: **`PARTIAL`/`BLOCKED` are exempt** (§ Incremental Persistence hands unfinished work back *with* its markers — the rule is about the word COMPLETE); **`<changed_files>` is not swept** (source legitimately carries a `TODO`); **a marker inside an inline code span is not a hit** (backticks are how the convention is documented and cited — `base-persona.md` and this page — never how a skeleton leaves a placeholder, which is written bare); and **a marker inside a fenced block IS a hit** — the opposite of how the handoff text is read, deliberately, because a fenced `<handoff>` is an *illustration* that must not satisfy the gate while a fence inside a delivered artifact is still ink the reader scrolls past. A binary or unreadable artifact is skipped with a warning: "the gate could not look" is not "the agent left a marker".
- **`--allow-scaffolding "<reason>"`** is the escape for a page that must legitimately quote the marker (this gate's own reference doc, a lesson that names it). It waives `artifact_scaffolding_left` and **nothing else**, requires a non-empty reason (blank is exit 2), and writes `allow_scaffolding_reason` plus the waived `{path, line, marker}` entries into the chained ledger record — matching `--allow-drift` and `--allow-tier-inversion` elsewhere in this family. A clean run records neither key.
- **Codes** — `handoff_missing`, `element_missing`, `path_missing`, `changed_files_not_in_diff`, `status_invalid`, `consumers_grammar`, `honesty_contradiction`, `artifact_scaffolding_left`, `blockers_uncategorised`. Under `--advisory`, `element_missing` simply never fires for `<artifact>`/`<changed_skills>`; no new code is introduced there.
- **JSON keys** — `result`, `persona`, `since`, `fix_round`, `advisory`, `advisory_waived_elements`, `required_elements`, `present_elements`, `status`, `changed_files`, `artifacts`, `changed_skills`, `scaffolding_scanned`, `allow_scaffolding`, `scaffolding_waived`, `findings` (`{code, detail, …}`; a scaffolding finding adds `path`, `line`, `marker`, `text`), `warnings`, `error`.
- **Exit codes** — **0** PASS; **1** at least one finding; **2** usage, an unreadable handoff, an unknown persona, a bad `--repo` or `--docs-root` (any one not a directory), a `--since` ref git cannot resolve in the repo a changed file resolved to (an unperformable check is never a pass), or an `--allow-scaffolding` with a blank reason.
- **Self-test** — **67** cases: the adversarial four (a fenced fake handoff, a path that does not exist, `<changed_files>` naming an untouched file, an empty element), ten `--advisory` cases — Forge's and Aria's real shapes, everything the flag does NOT waive, and the ledger record's `advisory: true` inside the chain — thirteen sweep cases: every marker shape, a fenced marker, the `PARTIAL`/`BLOCKED` exemption, an unswept `<changed_files>`, a binary artifact, and the `--allow-scaffolding` round trip through the ledger — multi-`--repo`/`--docs-root` cases: a path resolving under the second `--repo`, `--since` diffed against the repo it resolved to, the `.docs`-ancestor default, and the relative-path parent/cwd fallback for `<artifact>`/`<changed_skills>` only — and ten `blocked_on:` grammar cases: every known category, an unknown one, a missing line, the `COMPLETE` exemption, a bulleted/backtick-wrapped line, and the absent-`<blockers>`-is-only-`element_missing` non-duplication case. Depth: `references/check_handoff.md`.

## check_redelegation.py

Run by the Orchestrator BEFORE re-delegating an agent that has already returned on a unit (round ≥ 2). Measured on epic slide-s5: Quinn was delegated four times on Milestone 1 and returned PARTIAL every time with the same blocker — no admin shell, no installed Gorelo.Agent service, no dev token — an environment wall only the human could clear; about 1.2M tokens re-discovered that one fact. `orchestrator-contract.md` §2 already says to halt after 3 consecutive attempts; this is that rule's mechanical form (convention #9). Depends on `check_handoff.py`'s `blocked_on:` grammar (above).

```bash
python check_redelegation.py --run-log <path> --unit "<title>" --agent <name> \
    --handoff <the agent's LAST handoff file> \
    [--previous-handoff <file>] [--state <orchestrator-state.json>] \
    [--allow-redelegation "<reason>"] [--ledger <path>]
python check_redelegation.py --self-test
```

- **Rule 0 — standing halt (checked FIRST, only with `--state`).** If `state["halt"]` already names `--unit`: exit 1 immediately with THAT halt's own `code`/`reason`, whatever the new handoff says — rules 1-2 are not evaluated. **This gate never clears a halt, for any agent, on any result.** A blocker in `environment`/`credentials`/`dependency` is about the unit's world, not about which agent's handoff happened to look clean; clearing is a human act — `update_state.py --clear-halt <unit> --reason "<what changed in the world>" --ledger <path>` (`--reason` required there, exit 2 without it).
- **Rule 1 — category halts.** If the last handoff's `<status>` is `PARTIAL`/`BLOCKED` and any `blocked_on:` line names `environment` or `credentials`: exit 1, `halt_environment` — outside the agent's power, halt for the user. A `dependency` category is exit 1 `halt_dependency` unless `--allow-redelegation "<what changed since>"` waives it (recorded in the ledger line). `spec`/`defect` never halt on their own.
- **Rule 2 — repetition, two INDEPENDENT checks that may BOTH fire.** Counts prior `delegation` records in `--run-log` for this exact (`--unit`, `--agent`) pair whose `status` is `PARTIAL`/`BLOCKED`. **Round bound (always applied):** ≥ 3 such priors is exit 1 `halt_round_bound` — the mechanical form of `orchestrator-contract.md` §2's "3 consecutive attempts" bound, deliberately tighter than *nothing* (convention #8), and unconditional: giving `--previous-handoff` never suppresses it, only this round's wording differing must never let a 4th round through. **Similarity (layered on top, only with `--previous-handoff`):** with `--previous-handoff` and ≥ 2 such priors, a normalised token-set (Jaccard) similarity ≥ 0.8 between this and the previous PARTIAL/BLOCKED handoff's `<blockers>` is *additionally* exit 1 `halt_repeated_blocker`, and can trip as early as round 3 (2 priors), before the round bound would.
- **`--state`** merges a FRESH `state["halt"] = {unit, agent, code, reason, ts}` via `update_state.py --set-halt` when rule 1/2 fires for the first time — never on rule 0's short-circuit (nothing changed) and never on PASS. A write failure is a warning on this gate's own report, never a change to its verdict.
- **Codes** — `halt_environment`, `halt_dependency`, `halt_repeated_blocker`, `halt_round_bound` (rule 0 reuses whichever of these the standing halt was already recorded under).
- **JSON keys** — `result`, `unit`, `agent`, `handoff`, `previous_handoff`, `status`, `round`, `prior_statuses`, `similarity`, `allow_redelegation`, `standing_halt`, `findings`, `warnings`, `state`, `error`.
- **Exit codes** — **0** PASS (delegate); **1** a halt finding (fresh or standing); **2** usage, an unreadable handoff, or a blank `--allow-redelegation` reason.
- **Self-test** — **39** cases: every category (including precedence when more than one `blocked_on:` line is present), the round-bound boundary at 2/3 priors (unconditional even with `--previous-handoff`) and its unit/agent scoping, the similarity path above/below 0.8 and requiring 2 priors, both round-bound and similarity firing together, `--allow-redelegation` waiving only `halt_dependency`, a standing halt surviving a passing run by a DIFFERENT agent and being reported verbatim on re-run, a passing run touching state not at all, and the ledger chain.

## check_tier1_provenance.py

Enforces the Tier-1 provenance stamp `bgpdd-discovery/SKILL.md` § 1 promises downstream — the gate that section explicitly says does not exist yet. Every Tier-1 root artifact (`context.md`, `{feature}/overview.md`) must carry, in its header, a date and a 40-hex commit sha per in-scope repo, and each sha must resolve in that repo. Drift against current HEAD is reported and **never** fails, per the same section.

```bash
python check_tier1_provenance.py --summary-root .docs/summary [--feature <id>] \
    --repo [<name>=]<path> [--repo ...] [--warn-on-drift] \
    [--verify-current [--allow-drift "<reason>"]] [--previous <path>] \
    [--milestone "<title>"] [--ledger <path>]
python check_tier1_provenance.py --self-test
```

- **Flags** — `--repo` repeats once per repo on a multi-repo Target Scope; `name=path` keys the sha, a bare path keys on the directory name. `--feature` scopes to one `overview.md` (the Phase 4 invocation); without it every feature directory under the root is checked, plus `context.md` always. `--warn-on-drift` adds stderr warnings only — it can never change the exit code. `--milestone "<title>"` scopes this run's ledger record and changes no verdict.
- **`--verify-current` — drift as a gate, on demand.** Drift stays a warning in the default run, exactly as `bgpdd-discovery` §1 says. This flag is the opt-in inversion for the CONSUMER end — the plan/build/lite/verify/shipping Pre-Flight about to brief agents from this map: with it, a stamped sha that is not the repo's current HEAD is **`tier1_drift`, exit 1**, naming the repo, the stamped sha and HEAD. The producer (discovery) writes the stamp and never passes it. **`--allow-drift "<reason>"`** accepts the staleness in writing and records the reason plus the waived entries in the ledger record; an empty or whitespace-only reason is exit 2 (matching `--allow-breaking` and `--allow-tier-inversion`), and `--allow-drift` without `--verify-current` is exit 2 — waiving a check that never ran records a decision nobody had to make. It waives `tier1_drift` and nothing else.
- **A future date is not a date.** The date was checked for SHAPE only, so `2031-01-01` passed; it now fails `stamp_date_future`. A stamp says "this map was derived from the tree on this day", and a date that has not happened records nothing that happened — in the direction that keeps a stale map reading as fresh. Only the LATEST date in the header is judged (a header may mention an earlier date in prose), against today plus one day of slack for a machine running ahead of UTC.
- **Stamp grammar** — the header is everything above the first `## ` heading; it must hold a `YYYY-MM-DD` date and, per in-scope repo, a line with a 40-hex sha. With two or more repos in scope that line must also carry the repo's name; with one, a bare sha line suffices.
- **`--previous <path>` — a cumulative file is not a rewrite (`tier1_repo_dropped`).** `bgpdd-discovery` §1: Tier-1 `context.md` is cumulative and project-wide, a run's Target Scope is a subset view recorded *inside* it, and sessions in one workspace are each scoped to their own repos — so a whole-file rewrite deletes every repo the previous run recorded, with no diff, no conflict marker and no version history in `.docs/` to recover from. The SKILL tells the Orchestrator to back the file up before re-running Phase 1 and to confirm afterwards that every previously recorded repo still appears; this flag is that confirmation, asked for at the moment the phase most wants to close because *this* run's own repos all check out. Every repo stamped in the previous copy that appears in neither the repo keys nor the shas of the current artifact is **`tier1_repo_dropped`, exit 1**, naming the repo and **both** files. What it does **not** fail: a repo present in both with a different sha (that is this run's refresh, the whole point of re-running Phase 1) or a repo the current artifact adds (that is this run's scope). Removal fails **whether or not this run was ever scoped to the vanished repo** — "yes, update it" authorizes adding this run's scope, never removing another's. A repo counts as still stamped when its **key or its sha** reappears, so a bare single-repo stamp that gained a repo name, and a reworded line, are refreshes. `--previous` may be a **file** (compared against `context.md`, the one cumulative artifact) or a **directory** mirroring `--summary-root` (compared per artifact; a missing counterpart is a warning, since there is nothing to compare). A `--previous` path that does not exist at all is **exit 2** — an unperformable check is never a PASS.
- **Codes** — `artifact_missing`, `stamp_missing`, `date_missing`, `stamp_date_future`, `sha_missing`, `sha_unknown`, `tier1_drift` (`--verify-current` only), `tier1_repo_dropped` (`--previous` only). A sha that resolves to nothing is a fabricated stamp, not an old one, and fails.
- **JSON keys** — `result`, `summary_root`, `feature`, `features_checked`, `artifacts_checked`, `previous`, `repos`, `verify_current`, `allow_drift`, `drift_waived`, `findings`, `drift`, `warnings`, `error`. A `tier1_repo_dropped` finding carries `artifact`, `previous`, `repo` and `stamped`.
- **Exit codes** — **0** PASS (drift included, unless `--verify-current`); **1** at least one finding; **2** a bad `--summary-root`, no or malformed `--repo`, git unusable, a `--previous` path that does not exist, or an `--allow-drift` that is empty or lacks `--verify-current`.
- **Self-test** — **39** cases against real temp git repos (skipped, never faked, when git is absent), including the five date cases, the six `--verify-current` / `--allow-drift` cases and twelve `--previous` cases — the dropped repo, the refreshed sha, the added repo, the bare stamp that gained a name, the directory mirror, and the missing backup path. Depth: `references/check_tier1_provenance.md`.

## tier1_staleness.py

Answers the question `check_tier1_provenance.py` cannot: not just THAT a repo
drifted past its stamp, but WHICH Tier-1 docs under `.docs/summary/{feature}/`
are affected, so a refresh re-runs only the stale ones. Reads the same
provenance stamp (imports `check_tier1_provenance.py`'s `header_of` /
`stamped_repos` rather than re-deriving the grammar), diffs each stamped repo
from its stamped sha to HEAD, and matches each doc's cited source paths
against what changed.

```bash
python tier1_staleness.py --summary-root .docs/summary --feature <id> \
    --repo <name>=<path> [--repo ...] [--json|--markdown] \
    [--fail-on-stale] [--ledger <path>]
python tier1_staleness.py --self-test
```

- **Flags** — `--repo` repeats once per stamped repo (`name=path`, matched
  against the doc's stamp case- and separator-insensitively, so `gorelo_backend`
  matches a stamp key mangled to `gorelobackend` by markdown-decoration
  stripping). `--markdown` prints a compact table in place of the default
  `--json`; the two are mutually exclusive (exit 2 together). `--fail-on-stale`
  is the only thing that can turn a finding into exit 1 — without it the
  report is advisory and always exits 0, matching `check_tier1_provenance.py`'s
  own "drift is a warning" stance.
- **Scope** — every `.md` under `.docs/summary/{feature}/` (recursively) plus
  `.docs/summary/context.md`.
- **Inherited stamps** — the discovery contract (`bgpdd-discovery/SKILL.md`
  §1, Phase 4) stamps only `context.md` and `{feature}/overview.md`; every
  per-API `{api}.md` and `QA/*.md` doc is never stamped by design. A doc
  under `{feature}/` with no stamp of its own now **inherits**
  `{feature}/overview.md`'s stamp and its verdict computes normally from it
  (`stamp_source: "inherited:overview.md"`; a doc with its own stamp reports
  `stamp_source: "own"`). `context.md` never inherits. `unstamped` now means
  only that `{feature}/overview.md` itself carries no stamp (or does not
  exist) — in which case every stampless sibling is `unstamped` too, and
  `warnings` names the cause once instead of once per doc.
- **Citation extraction, two classes**:
  - **Path-shaped** — multi-segment path tokens ending in a source extension
    (`.cs .ts .tsx .vue .js .py .ps1 .sql .json .yaml .yml .csproj .razor
    .cshtml`), slash or backslash, matched against the changed-file list by
    trailing path segments in either direction (handles both a citation
    shorter than the diff path and one carrying a leading repo-folder prefix
    the diff output lacks). Hits land in `changed` / `deleted_or_renamed`.
  - **Bare filename** — a single-segment token with a source extension and no
    path separator (`AlertHelper.cs`, the shape of most of Echo's
    `overview.md` citations). Matched against the ADDED/MODIFIED file list
    (not renames or deletes — a bare name has no directory to disambiguate a
    move by) by BASENAME ONLY, across every repo the doc's stamp scopes,
    combined: exactly one match is `changed_by_basename` and counts toward
    stale; two or more matching files is an unresolvable collision, listed
    in `ambiguous_basenames` with its count and does **not** count toward
    stale. A bare name whose basename a path-shaped citation in the same doc
    already covers is skipped — path-shaped citations take precedence.
- **Verdicts** — `fresh` (stamped — own or inherited —, resolvable, nothing
  cited changed), `stale` (something in `changed`, `deleted_or_renamed`, or
  `changed_by_basename`), `unstamped` (no own stamp and nothing to inherit —
  only possible when `overview.md` itself has no stamp), `unresolvable` (a
  stamped sha this run cannot resolve, or a stamped repo none of the
  `--repo` args matched — code `stamp_unresolvable` or `repo_not_provided`
  respectively, in that doc's `findings`).
- **JSON keys** — `result`, `summary_root`, `feature`, `repos`, `docs` (each:
  `path`, `stamp_source` [`"own"` / `"inherited:overview.md"` / `null`],
  `stamped`, `commits_behind`, `cited_paths`, `cited_basenames`, `changed`,
  `deleted_or_renamed`, `changed_by_basename`, `ambiguous_basenames` [list of
  `{name, count}`], `verdict`, `findings`), `summary` (`counts` per verdict,
  `stale_docs` sorted by `len(changed) + len(deleted_or_renamed) +
  len(changed_by_basename)`), `warnings`, `error`.
- **Exit codes** — **0** always, unless `--fail-on-stale` is given and
  `result` is `FAIL`, in which case **1**; **2** bad `--summary-root`, no
  `--repo`, missing `--feature`, a `--feature` whose directory does not
  exist under `--summary-root`, a `--repo` path that is not a directory or
  not a git repository (each named in `error`), or git unusable. Every one
  of these means the check could not be performed at all — none is folded
  into an exit-0 report, since an unperformable check that exits 0 reads as
  "fresh" to a caller that only checks the exit code.
- **A `--repo` NAME no stamp references, as opposed to a bad PATH, is not an
  error** — the path is still validated up front (it must exist and be a
  git repo), but a valid repo nobody's stamp happens to mention is harmless
  scope, not a usage problem.
- **Never writes.** No doc, no re-stamp — the stamp rule stays Echo's, read at
  write time, exactly as `bgpdd-discovery/SKILL.md` §1 says.
- **Self-test** — **19** cases against real temp git repos (skipped when git
  is absent): stale via a changed citation, stale via a rename, fresh despite
  `commits_behind` > 0, a bogus sha (`stamp_unresolvable`), a stamped repo
  none of `--repo` names (`repo_not_provided`), an inherited stamp computing
  fresh and computing stale, an unstamped `overview.md` cascading to its
  siblings (with the one-line `warnings` explanation), a uniquely-matched
  bare-filename citation counting toward stale, an ambiguous bare-filename
  citation NOT counting toward stale, `--fail-on-stale` exit codes,
  `--markdown` output, ledger chaining, a missing `--feature` directory and
  an unusable `--repo` path (both exit 2, naming the path — nonexistent AND
  exists-but-not-a-git-repo), two other usage-error cases, and two
  citation-extraction/matching unit tests (backslash paths, a leading
  repo-folder prefix).

## check_openapi_diff.py

Diffs two OpenAPI documents and exits non-zero when the head document breaks a published contract. `api-contract-evolution/SKILL.md` states the rule (additive-only within a major version) and names the breaking classes; this is the artifact that has to be run for the claim to stand (convention #9). It diffs **documents**, not implementations — that the document is actually served by a started application is `check_runtime_evidence.py --require-openapi-reachable`, and neither substitutes for the other.

```bash
python check_openapi_diff.py --base <openapi.json|yaml> --head <openapi.json|yaml>     [--allow-breaking "<reason>"] [--milestone "<title>"] [--ledger <path>]
python check_openapi_diff.py --self-test
```

- **Breaking `kind`s** — `path_removed`, `operation_removed`, `response_status_removed`, `response_field_removed` (a rename shows as this plus an additive `response_field_added`; the gate never guesses the pairing), `type_changed`, `required_request_field_added` (a new required request property, an existing one added to `required`, a new required parameter, an existing parameter turned required, or `requestBody.required` flipped true), `enum_narrowed` (a value lost, **or** an enum introduced where the base accepted any value), `nullable_removed` (`nullable: true → false` on a **response** schema). Additive `kind`s, recorded and never gating: `path_added`, `operation_added`, `response_status_added`, `response_field_added`, `optional_request_field_added`, `parameter_added`, `enum_widened`, `nullable_widened`.
- **`unanalyzable_schema` — a PASS over an unanalyzed schema is worse than a refusal.** The walk descends `properties`, `items` and `allOf`; it does **not** descend `oneOf`, `anyOf` or `not`, and until 2.6.1 it said nothing about that — a response schema wrapped in `oneOf: [...]` with a field removed inside returned exit 0 PASS, `breaking: []`, no warning. Any schema node carrying one of those keywords (after one level of `$ref` resolution, and including a parameter schema) is now exit **2**, naming the operation, the JSON path and the keyword, **never a PASS and never masked by `--allow-breaking`**: a waiver waives a diff somebody read, and there is no diff here to read. Deciding whether a variant was dropped from a union needs a subtype relation this tool does not implement; `check_runtime_evidence.py` refuses the same class the same way (`schema_skipped_reason`). The fix is to compare those branches by hand and waive on a document the gate CAN read, or to restructure the schema.
- **Nullability** — `nullable: true → false` on a response schema is breaking (`nullable_removed`): the same component is nearly always the one accepted in requests (one level of `$ref` reaches it from both), so the flip breaks every caller that sends or round-trips null, and it is the same narrowing the gate already refuses under `type_changed`. Deliberately conservative and deliberately **waivable** — exit 1 with a named kind and a one-flag waiver, rather than the silent PASS this was. The widening is `nullable_widened`, additive, and also listed in `warnings` because a caller that never handled null now must.
- **JSON keys** — `base`, `head`, `result` (`PASS` | `ALLOWED` | `FAIL` | `ERROR`), `breaking`, `additive` (both arrays of `{kind, path, detail}`), **`unanalyzable`** (array of `{where, path, keyword}`), **`warnings`** (array of strings: an unresolvable `$ref`, a walk stopped at the depth cap, a nullability widening), `allowed_by`, `error`. `breaking` stays fully populated under a waiver — `result: "ALLOWED"` is what says it was waived.
- **`$ref`** — resolved **one level** over any local `#/...` pointer (`#/components/schemas/X` primarily). A resolved schema's own `$ref`s are left alone, which is what makes a self-referential component terminate; a two-deep chain compares symmetrically and reports nothing. A pointer that does not resolve is now a `warnings` entry rather than a silent skip. `allOf` members are merged; `oneOf`/`anyOf`/`not` are refused (above).
- **Document formats** — JSON always. YAML **only** as the JSON-compatible block subset a minimal stdlib loader can read (nested mappings, `- ` sequences including the compact `- key: value` item, plain/quoted scalars, `[]`/`{}`, comments, one leading `---`). Anchors, aliases, tags, merge keys, block scalars, other flow collections and multi-document streams are **exit 2 with the construct named** — no YAML library is vendored, and a loader that guesses at an anchor could manufacture a phantom green.
- **`--allow-breaking "<reason>"`** — exits 0 over a breaking diff and records `allow_breaking_reason` plus `breaking_kinds` in the ledger record. **Deliberately hand-typed, like `check_commit_gate.py --waiver` (convention #8)**: no script can judge the reason, so the flag buys durability and attributability, not verification. An **empty or whitespace-only reason is exit 2** — an unreasoned waiver is indistinguishable from an omission.
- **Exit codes** — **0** every difference is additive, or a breaking diff carried a non-empty `--allow-breaking`; **1** a breaking diff; **2** a missing `--base`/`--head`, a document that is missing, unreadable, not valid JSON, YAML outside the supported subset, or not a mapping at the top level, an empty `--allow-breaking`, **or any `unanalyzable` node** (which no waiver clears).
- **Self-test** — **53** cases. Depth (the per-class detection rules, the `$ref` and YAML scope limits, what the waiver does and does not buy): `references/check_openapi_diff.md`.

## check_test_authenticity.py

Reads the test files in a changed set and exits non-zero when one of them tests **itself** rather than the product. Every other test gate in this family verifies a *transition* — a command red before the fix and green after (`check_red_green.py`), a capture that hashes to the run that produced it (`check_runtime_evidence.py`) — and a fake test satisfies all of it perfectly: a spec that defines `getBackupItemStatus` at the top of the file goes red before the definition is written and green the moment it is. The transition is real; the coupling to the shipped function of the same name is zero. Running it harder cannot detect that, so this gate reads the file's STRUCTURE instead: what it imports, what it navigates to, and whether the symbol under assertion is defined in the test or in the product (convention #9).

```bash
python check_test_authenticity.py --repo <dir> --changed-files <test file>...     [--files <test file>...] [--src-roots <dir>...] [--test-globs <glob>...]     [--allow <test file> --reason "<text>"]... [--milestone "<unit>"] [--ledger <path>] [--json]
python check_test_authenticity.py --self-test
```

- **`--files` and `--changed-files` are the same flag** (both repeatable, both accumulate) — the pipelines pass `--changed-files`; the shorter spelling exists for a hand invocation. Paths may be repo-relative or absolute, with either slash.
- **Problem codes** — `test_no_production_import` (the file touches NEITHER production code nor a running surface: no import resolves under a src root **and** there is no `page.goto` / `browser_navigate` / `request.<verb>(` / `HttpClient` / `WebApplicationFactory` / `TestServer` / `fetch` to an http URL. Doing **either** one passes this check — a unit test imports, an end-to-end spec navigates); `test_inline_reimplementation` (the file defines a function/class/arrow whose body is ≥ **3** statements, references no driving surface, and whose NAME is also defined under a src root — the test asserts against its own transcription; **also** fires on ≥ **2 distinct** such definitions in a file that touches neither production code nor a running surface, name match or not); `test_source_eval` (a `readFileSync`/`fs.readFile`/`File.ReadAllText`/Python `open` **plus** a string literal naming a path under a src root **plus** `new Function` / `eval` / `vm.runIn` / `transpileModule` / `ts.transpile` — Python: `eval`/`exec`/`compile`); `test_synthetic_dom` (`page.setContent(` or `document.body.innerHTML =` with **no** navigation anywhere in the file, **or** the fallback shape: a `try` block containing `page.goto` whose `catch` block injects DOM).
- **Every problem cites `file:line` and a one-line excerpt.** One finding per NAME, not per occurrence: a spec that redefines the same transcribed helper once per `test()` block is one problem, and a gate that prints it four times trains its reader to skim.
- **Non-test files in the set are IGNORED, and reported.** They land in `ignored` with a reason and never contribute a verdict, so the pipelines can pass a whole changed-file list without filtering it first.
- **`--test-globs`** replaces the defaults entirely. Defaults: `**/*.spec.*`, `**/*.test.*`, `**/tests/**`, `**/__tests__/**`, `**/*Tests.cs`, `**/*Test.cs`, `**/test_*.py`, `**/*_test.py`. Matched case-insensitively against the repo-relative POSIX path; a pattern with no `/` is also matched against the basename.
- **`--src-roots`** replaces the discovered roots entirely. Discovery, when it is omitted: (1) `src`, `app`, `lib`, `Source` under the repo root, when they exist; (2) for every project manifest (`package.json`, `pyproject.toml`, `*.csproj`) at depth ≤ 3, that manifest's own `src`/`app`/`lib`/`Source` subdirectory when one exists, else — for a `.csproj` only — the manifest's own directory, because the C# convention is code beside the project file. Noise directories (`node_modules`, `bin`, `obj`, `dist`, `.venv`, …) are never roots and never walked; a root nested inside another is dropped as redundant.
- **A repo with no discoverable src root is exit 2, never a PASS.** The whole discrimination rests on a symbol index built from those roots; an empty index matches nothing and would report every test file in the tree as authentic — a PASS over a tree the gate never read, the same class of lie `check_openapi_diff.py` refuses under `unanalyzable_schema`. Pass `--src-roots` explicitly instead.
- **`--allow <file> --reason "<text>"`** — repeatable, and each `--allow` needs exactly one paired `--reason` (a count mismatch is exit 2). Clears one file's problems (`verdict: "ALLOWED"`, findings still listed) and records the text in the ledger record as `allow_reasons`. **Deliberately hand-typed, like `check_openapi_diff.py --allow-breaking` (convention #8)**: some tests legitimately do this (a snapshot of a template renderer, a spec pinning a build artifact's shape), no script can judge which, so the flag buys durability, not verification. An **empty or whitespace-only reason is exit 2**. A waiver naming a file that was not judged is a `warnings` entry, not an error.
- **JSON keys** (`--json`; the default is a text report) — `repo`, `src_roots`, `test_globs`, `src_symbols` (the index size), `result` (`PASS` | `ALLOWED` | `FAIL` | `ERROR`), `files` (array of `{file, verdict, problems, waived_by}`, each problem `{code, file, line, excerpt, detail}`), `ignored` (array of `{file, reason}`), `problem_codes`, `waivers`, `warnings`, `error`.
- **Ledger extras** — `problem_codes`, `judged`, `ignored` on every verdict; `failing_files` on a FAIL; `allow_reasons` on an ALLOWED. `inputs` keys are the judged files resolved against `--repo`, so the hashes are real rather than `null` (a gate is not run from the repo).
- **Exit codes** — **0** no problems, or every problem was in a waived file; **1** a problem in a non-waived file; **2** a missing `--repo` or empty file set, an input that is not on disk or cannot be read, no discoverable src root, or a waiver with a blank or unpaired reason.
- **Self-test** — **83** cases. Depth (the four tiers of fake test, why RED/GREEN cannot catch any of them, and each heuristic's honest false-positive and false-negative limits): `references/check_test_authenticity.md`. End-to-end: `evals/contract/test-authenticity-adversarial/`.
