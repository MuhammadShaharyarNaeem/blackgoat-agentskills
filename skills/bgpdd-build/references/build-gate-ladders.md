# bgpdd-build — Sub-Contract: The Per-Milestone Gate Ladders

**This file is a SUB-CONTRACT, not rationale.** `bgpdd-build/SKILL.md` carries a stub for each ladder below naming its HALTs, gate script names and exit routes; the executable detail lives here and is binding. Read the relevant § in full before running that gate. Where it and the spine appear to conflict, the spine wins — but nothing here is optional.

The two ladders are deliberately held in one file: the commit gate **re-runs** the runtime-evidence gate, forwarding every assertion flag the Phase 2 gate passed, so reading one half without the other is how a weaker commit-time re-run happens.

## § The commit gate (§1, Git Workflow)

  - **The commit gate is mechanical — and machine-RUN, not just machine-checkable.** Build the invocation in this order; every step is mandatory unless its condition says otherwise. Rationale: `build-rationale.md` § Commit gate.
    1. **Base invocation** (always):
       `python {PLUGIN_ROOT}/pipeline-tools/scripts/check_commit_gate.py --review-report .docs/{project-name}/implementation/review-report.md --state .docs/{project-name}/orchestrator-state.json --milestone "<milestone title>" --changed-files <the milestone's accumulated changed-files union — see Phase 1 step 6> --commit --message "<milestone name + FR/NFR IDs covered>" --verify-tree --ledger .docs/{project-name}/implementation/gates.jsonl`
    1b. **`--require-run-log` / `--require-agents` are always on too** — append `--require-run-log .docs/{project-name}/implementation/run-log.jsonl --require-agents quinn,luna,<mason|nova per this milestone's routing>`. Each named agent must carry a `record_run.py` delegation record scoped to **this milestone's exact title** with a model on it. The review report says Luna approved; this says the delegation happened. A milestone whose Quinn or Luna round was skipped outright leaves a green report and an empty run log, and the gate used to pass on the report alone. Codes: `run_log_missing`, `run_log_agent_missing`, `run_log_model_missing` — each routes back to the phase whose delegation is missing, not into the review cycle. On a `[SEC]` milestone add `cipher`.
    2. **`--verify-tree` is always on** — it fails the gate if the working tree holds changes beyond the declared `<changed_files>` plus `.docs/`.
    3. **Add `--require-rendered-evidence`** when the milestone carries `[UI]` tasks, or its surface is `[vs:ui]`/`[vs:web+api]`, AND browser tooling is available on the runtime.
    4. **If the milestone carries `[UI]` tasks and NO browser tooling exists on the runtime, do NOT run this gate for the milestone at all** — **HALT** and surface to the user: the milestone, the fact that the review was necessarily source-only, and the missing-evidence blocker. A `[UI]` milestone is never committed on source-only evidence and never looped against a gate it cannot pass.
    5. **Add the runtime-evidence group** on every milestone whose surface is not `[vs:none]` or `[vs:ui]`: `--require-runtime-evidence --runtime-report .docs/{project-name}/implementation/test-report.md`, **plus every assertion flag you passed at the Phase 2 step 4 gate — `--require-key`, `--expect-status`, `--forbid-host`, `--surface`, `--require-openapi-reachable`, and the `--openapi-doc` trio if you used it. Repeat them all**; the commit gate forwards them to `check_runtime_evidence.py` and folds its verdict into the pass.
    6. **Add `--require-ledger-gates check_runtime_evidence.py`** alongside them — on a `[SEC]` milestone, `--require-ledger-gates check_runtime_evidence.py,check_agent_report.py`. This is what makes a weaker commit-time re-run *detectable* rather than silently the more permissive of the two. The flag also verifies the ledger's **hash chain** before it reads any verdict: `ledger_chain_broken` means a record in `gates.jsonl` was edited, inserted or removed, and the route is to `check_ledger.py --ledger .docs/{project-name}/implementation/gates.jsonl` and the user — never around it. Note the epic-level counterpart: `check_coverage.py` and `check_acceptance_suite.py` are epic-scoped and bind at `bgpdd-shipping` Step 3's ship decision, **not** here (naming them at a per-milestone gate is the deadlock the audit found).
    6b. **Add the API-contract diff on an `[API]` milestone whose repo keeps an OpenAPI document under version control** — **an addition to this ladder, not a divergence from any rule in it**. Find the document from the milestone's `RUNTIME PROBE:` line `openapi:` field if it carries one, else the `--openapi-doc` path you already pass at step 5; if neither names one, the project keeps no saved contract and this step does not apply. Write the published baseline to a temp path — **redirect it; the command only prints to stdout**: `git show <the milestone's base commit>:<doc> > <that temp path>` — and run `python {PLUGIN_ROOT}/pipeline-tools/scripts/check_openapi_diff.py --base <that temp path> --head <the working doc> --milestone "<milestone title>" --ledger .docs/{project-name}/implementation/gates.jsonl`, then add `check_openapi_diff.py` to step 6's `--require-ledger-gates` list. Exit 1 = the head document breaks the published contract: route it as a **planning** defect per `{PLUGIN_ROOT}/api-contract-evolution/SKILL.md` § A Breaking Change Is Plan-Level, not into the review cycle — unless the plan task authorizes it, in which case re-run with `--allow-breaking "<the task id and reason>"`. Exit 2 = the document is unreadable or is YAML outside the gate's supported subset; fix the artifact.
    7. **`[vs:ui]` exemption — the same exemption as Phase 2 step 4 (convention #8)**: a `[vs:ui]` milestone forwards `--require-rendered-evidence` only, never `--require-runtime-evidence`, because the gate the latter feeds cannot accept rendered evidence. `[vs:web+api]` milestones still forward **both** — they carry API captures alongside their UI surface.
    8. **Exit routes.** Exit 0 = gate passed and the commit exists — the script performs the commit, so a skipped gate is loud (no commit) rather than silent. Exit 1 = do not commit; the JSON on stdout names the failing check; route back into the Phase 3 step 4 cycle. Exit 2 = artifact/environment defect — fix the artifact or environment, never hand-wave past it. Full CLI contract (JSON shape, exit codes, parsing rules): `{PLUGIN_ROOT}/pipeline-tools/SKILL.md` — single authority; do not restate parsing rules here.
    - **Blockers precondition — nothing scoped here, and nothing unscoped, may stand.** A milestone commits only when `orchestrator-state.json` holds no blocker scoped to this milestone and no blocker scoped to nothing. An entry scoped to a *different* milestone does not block this one — deliberately looser than this rule's prior "the array must be empty" form (convention #8). `check_commit_gate.py` enforces this split, and `--ignore-unscoped` is its sanctioned override for exceptional cases (contract: `{PLUGIN_ROOT}/pipeline-tools/SKILL.md`).
    - **There is no "commit now, the remaining finding is minor"** — that judgement is exactly what this gate exists to remove.

## § Phase 2 step 4 — the Runtime Evidence Gate

  4. **Runtime Evidence Gate (mechanical)** — run this as soon as Quinn's handoff is in hand, before Phase 3: a `PASS` in her report is a claim, the capture is the evidence. Skip when the milestone's surface is `[vs:none]`, and skip `[vs:ui]` too — **a deliberate refinement of the every-surface-except-none rule (convention #8):** `check_runtime_evidence.py` structurally requires a `## Captured output` JSON capture, which a `[vs:ui]` milestone's rendered evidence cannot produce; its evidence obligation is the commit gate's `--require-rendered-evidence` path instead (detail: `build-rationale.md` § `[vs:ui]`). `[vs:web+api]` keeps both obligations — it has API captures alongside its UI surface.
     `python {PLUGIN_ROOT}/pipeline-tools/scripts/check_runtime_evidence.py --report .docs/{project-name}/implementation/test-report.md --milestone "<milestone title>" --changed-files <the milestone's accumulated changed-files union> --repo . --ledger .docs/{project-name}/implementation/gates.jsonl [--surface <the milestone's [vs:] key>] [--require-key <k> ...] [--expect-status <N>] [--forbid-host <pattern> ...]`
     Take `--surface` / `--require-key` / `--expect-status` from the `gate_args` object `next_milestone.py --emit-gate-args` returned at Phase 1 step 1, falling back to the milestone's `RUNTIME PROBE:` line for any field it returned as null — never invent them, and never let the producer declare them (a producer-declared assertion grades itself). Pass `--forbid-host` for every shared dev/staging hostname this project must never be probed against; in a multi-service estate this is the check that catches one service left pointing at dev.
     **Add `--require-openapi-reachable` whenever the surface is `[vs:api]` or `[vs:web+api]`** — it is the check that forces the probe at a real application rather than at anything that answers on a port. It proves the surface is up and its schema is served; whether the response *body* is what was wanted is `--require-key`'s job. If the project keeps a saved OpenAPI document under version control, also pass `--openapi-doc/--openapi-route/--openapi-method` to diff declared against observed top-level property names — an unresolvable schema warns rather than passing or failing, so adding it can never manufacture a green.
     Exit 0 = an out-of-process capture exists, is fresh, and carries the asserted keys — proceed to Phase 3. Exit 1 = **BLOCK**: route back into the Phase 2 rejection loop with the JSON's per-capture `problems` (this counts as one of the 3 rounds). Exit 2 = the capture is structurally non-conforming — an artifact defect; route back to Quinn to produce a conforming capture. Full CLI contract: `{PLUGIN_ROOT}/pipeline-tools/SKILL.md` — single authority, do not restate parsing rules here.
     - **If the application genuinely cannot be started out-of-process in this environment**, do NOT loop against a gate it cannot pass: **HALT** and surface the milestone, the fact that its verification was necessarily in-process only, and the missing-evidence blocker; record it via `update_state.py --add-blocker`. This mirrors the `[UI]`-without-browser-tooling rule in §1 exactly — a milestone is never committed on in-process-only evidence.
